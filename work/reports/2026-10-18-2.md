### Why no tag: #1857, and what the run found out about it

The batch was amended while the run was going, to say that this build gets no `dev-*` tag **even if
everything passes**, because of
[#1857](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1857): the main map's
legend stays empty with Visitor Parking and Construction Zones on. Nothing was tagged.

The run went ahead to find out whether the suite catches it. **It does not**, and that is the finding:

> The suite ran all 552 tests against a build with a known empty-legend fault on the main map and
> reported **0 failed**. Three legend tests passed, and none of them asks whether the legend has anything
> in it.

**This is a gap, not a broken check.** `legend.spec.ts:110`, which passed, is one of #1866's four and
checks that a layer switched off and on is followed by both the Layers list and the legend — a different
question from a legend that comes up empty. The check written for #1857 is not on `development` yet, so
the miss is real and expected rather than a mistake, which is what the batch asked to have said plainly.

Until #1857's check lands, an empty legend reaches production with a green suite behind it.

An earlier comment on #1849 gave the reason for the held tag as a decision taken as the run finished;
that has been corrected on the issue, since the batch had already settled it.
