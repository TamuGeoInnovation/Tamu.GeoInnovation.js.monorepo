## How it was verified, including a failure worth recording

**The first run of this batch produced eight `exit=0` lines and zero bytes of output, and I nearly believed
it.** Two faults, both mine:

1. I mounted the host's `~/.docker/config.json` into the Trivy container. It specifies
   `credsStore: desktop`, whose helper binary is on the host and not in the container, so every scan failed
   with `error getting credentials`. Fixed by passing `TRIVY_USERNAME`/`TRIVY_PASSWORD` through an
   `--env-file`, so no credential helper is involved.
2. I wrote `docker run ... | tail -3` and then read `$?`, which in a pipeline is **`tail`'s** status, not
   the scan's. The log said `exit=0` eight times beside eight failed scans. This is the exact mistake
   `CLAUDE.md` warns about for `nx` output.

The rerun captures each scan's own exit code and prints the output file's size beside it, so "it passed" and
"it produced something" are separate visible facts. All eight wrote 0.3 to 1.5 MB of JSON.

**The registry credential was also stale**: every `docker manifest inspect` returned `denied` until a
`docker login ghcr.io` with the existing `gh` token (`read:packages`). It fails looking like a missing image
rather than a missing login, which is worth knowing for the next person.
