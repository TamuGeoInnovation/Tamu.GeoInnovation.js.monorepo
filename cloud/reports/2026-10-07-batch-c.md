## 4. #1476: tsconfigs off the options TypeScript 6 deprecates

**Branch: `cloud/1476-tsconfig-ts6`, ready, but it doesn't finish the goal. The rest is filed as #1550.**

With `ignoreDeprecations` removed, `tsc` names exactly three deprecated options, all set in
`tsconfig.base.json`'s `compilerOptions`:

| Option | Result |
| --- | --- |
| `moduleResolution: node` (node10) | Now `bundler`. The Angular projects already set it; the Nest projects, which build with webpack, now get it from the base and build fine |
| `esModuleInterop: false` | Now `true` |
| `baseUrl` | **Kept.** Without it, TypeScript 6 rejects every `paths` entry (TS5090) unless it starts with `./`, and `paths` was off-limits in this batch |

- **`ignoreDeprecations`:** removed from the 130 non-CPA project tsconfigs that set it. It remains in
  `tsconfig.base.json` (for `baseUrl`) and in one library (below).
- **One source file outside the tsconfigs changed:** `libs/mailroom/data-api`'s helper controller did
  `import * as FormData` and then `new FormData()`, which no longer compiles with interop on. It's now a
  default import. That's deployed mailroom code, so I checked that `mailroom-helper-nest` starts and maps
  `POST /mail`.
- **`ui-kits-ngx-charts` keeps `esModuleInterop: false`, with `ignoreDeprecations`, in its own
  tsconfig.** Its chart container calls a namespace import of `deepmerge`, and its test failed with
  "deepMerge is not a function" (it passes on `development`). The fix is a one-line default import in a
  `.ts` file under `libs/ui-kits`, which this batch reserved. No deployed app uses the library.
- **Mistake caught in testing:** I first explained `baseUrl` with a comment in `tsconfig.base.json`, and
  that broke every test, because `jest.preset.js` `require`s the file as strict JSON. The comment is gone
  and the reason is in the commit message; #1550 notes the trap.
