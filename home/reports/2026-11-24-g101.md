## What this changes

<!-- What a reader needs to know. Why, not only what. -->

**Stacked on PR 3359: merge that first.** This branch starts from PR 3359's branch, `fix/3345-presenter-hidden-sessions`, and moves its filter into a shared helper, so until 3359 merges this diff shows its commit too.

Every public route in `event.controller.ts` that returns sessions returned the hidden ones (`active` false) as well, to anyone who asked: name, time, place and the rest (#3354, found in #3345). The admin pages read the same routes, and must see hidden sessions to put them back on the schedule (#2092), so a plain filter would have hidden them from admins too.

**What changed**
- **`_base/hidden-sessions.ts`:**
  - `onSchedule(session)`: a session the public sees.
  - `seesHiddenSessions(account)`: an account that may put a session back on the schedule, `update:events`.
  - `sessionsShownTo(sessions, account)` and `sessionShownTo(session, account)`; a hidden session by its id is not found, as one that does not exist.
- **The six routes:** `GET /events`, `/events/by-day`, `/events/season/active`, `/events/season/:guid`, `/events/:guid/event` and `/events/:guid`.
  - Each reads the account, if any, from the sign-in (`JwtGuard` with `@AllowAny`, as `/events/:guid` already did).
  - Each shows hidden sessions only to an admin. Anyone else gets none, or 404 by id.
  - The site sends its token with every API call, signed-in or not, so the admin pages need no change.
- **The presenter route (#3345)** uses `onSchedule`, the same test. It is the public page's own route, so it hides them even from an admin.
- **Why `update:events`:** `read:events` is not given to anyone today; only a spec names it. `update:events` is what the admin Events pages already need to put a session back.

**What changes for whom**
- **Anyone, signed in or not, without `update:events`:**
  - the session lists and by-day leave hidden sessions out;
  - a hidden session's own page, and its check-in page, answer not found.
- **An admin:** nothing changes. One side effect: the private-fields interceptor now knows who an admin is on these routes too, so an admin sees speakers' private fields there, as on the admin routes.
- **Not changed:** the public schedule reads `/season-days/:guid/events`, which already left hidden sessions out (`filter((e) => e.active)`).
