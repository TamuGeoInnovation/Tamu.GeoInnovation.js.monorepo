## Cause (confirmed, as you suggested)
`_buildLegendWhereClause` quoted every value. A multi-field row's value arrives as one string (`'1,1'`), so a numeric field's
parts were quoted too. The transportation server rejects an integer field compared with text, the query failed, and
`catchError` returned `null`, so **every** row was dropped: Freshman Selectable Parking's legend showed names with no symbols.
Business Parking hit the same path, but its lots also failed to draw for a separate reason (#1981).

## Fix
- A part is unquoted when **the layer declares that field numeric** (`layer.fields` type: small-integer, integer, big-integer,
  single, double, long, oid), not by how it looks, so `'09400'` stays quoted. A field the layer does not list stays quoted.
- A row whose query fails is **kept** (as one that throws already was), with a warning, rather than removed.
