## #3732: a live check called orphaned

- **The cause, measured on home:** with a63's `check-in-volume.sh` running, **`ps -ef` saw 0** processes running the
  script, and **Windows saw 8** (`Get-CimInstance Win32_Process`). Git Bash's `ps` shows no command-line arguments on
  Windows, so a live check's wrapper was invisible, and its container read as an orphan.
- **The fix:**
  - `process_command_lines` reads full command lines from Windows, or `ps -eo args` where there is no PowerShell.
  - `count_wrappers` counts the processes running `check-in-volume.sh` as an argument, not a `grep` or other search
    for it.
  - `orphans` is unchanged.
- **Run live on home** with a check running, the new count was **4**, where `ps -ef` gave 0. That is enough for the
  check's container not to be an orphan.
- **Not a per-container match.** A count above zero clears every check container on the machine, as before. A label
  carrying the wrapper's PID, which the issue suggests, would let one live check not clear a dead one beside it.
  That needs a change to `check-in-volume.sh` on `development`, so I left it. Q-g125-1.
