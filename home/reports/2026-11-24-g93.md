## What this changes

<!-- What a reader needs to know. Why, not only what. -->

`formToFormData`, which the organization, place location, speaker and sponsor admin forms save through, kept a value only if it was truthy, so a checkbox turned off was never sent (#3327).

It went unnoticed because each form that has a checkbox got by another way:
- **Speakers:** the API reads `isOrganizer` and `isActive` as `=== 'true'`, so one left out is read as false.
- **Sponsors:** a workaround, `_formData()`, set `active` by hand (#1962), because the API's `withActiveFlag` leaves a sponsor's `active` as it was when it is not sent.

A form added next would not have been so lucky.

**What changed**
- **`formToFormData` sends `false`,** as `"false"`, at the top level and inside a group. An empty or missing value is still left out, and so is a control named with a leading `_`, as before.
- **The API already reads `"false"` as false.** The speaker's flags compare with `"true"`; `withActiveFlag` takes `"true"` or `"false"`. Nothing changes there.
- **The sponsor form's workaround goes:** it now sends `formToFormData(this.form)` like the others. A new test, that saving a sponsor switched off sends `active` as `false`, passed with the workaround and passes without it.
- **Not in this pull request:** the admin forms' shared save, delete and toasts, which #3327 also described. That is now [#3340](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/3340).
