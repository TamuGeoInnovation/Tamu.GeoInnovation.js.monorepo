## The map already existed

`sustainable-transportation.definitions.ts` has been in the repository since May (#777): the same six layers, on by
default, with its own popups. It was registered in `EventDefinitions`. But it had `parkingCategory` and no `mapType`,
so it was listed nowhere (the same fault #2738 fixed for Micromobility). It was also **open on production to anyone
with its link**.

So the change is small:
- `mapType: 'transportation'`, which lists it in the section beside Micromobility;
- `developmentOnly: '#2742: ...'`, which keeps it off production as Micromobility is.

**Route preset or definition (the issue asks which, and why):** I kept the existing definition.
- It is the Micromobility shape the batch pointed at.
- Replacing it with a route that presets the main map's layers would be new machinery. It would also delete a
  working map while the bike layers' future is still being decided.
- The duplication the issue warns of is real: the six layers are declared here, on the main map, and in part on the
  EV Chargers map. But it predates this issue, and no new helper was written. If the bike layers stay, folding this
  map into a route preset is worth its own issue (question 2).

**Development-only: the guard, not build-time exclusion.**
- Event maps have no build-time exclusion. #2753's rule itself says "`DevelopmentOnlyMapGuard` is how a route does
  it", and Micromobility and NCAA Volleyball are gated that way.
- Build-time exclusion (`DEVELOPMENT_ONLY_LAYER_SOURCES`) is for layer and search sources. This map adds none: its
  service is the main map's, and on production stays the main map's.

## What the gate's proof needed

`development-only-maps.spec.ts` required every development-only map's services to be on `DEVELOPMENT_ONLY_SERVICES`,
the list of what production must never request. **TS/BikeMap cannot be on that list**: production's main map
requests it for its Sustainable Transportation group. So:

1. **The unit rule now exempts services that a map on production also reads.** That means the main map's production
   layer sources, plus every map that is not development-only. The exemption is computed from the definitions, not
   kept as a list.
2. **A new smoke check proves the gate itself, for every development-only map.** It runs in `development-only.spec.ts`:
   - on production, `/parking/<id>` must land under `/map`;
   - elsewhere, it must open the map.

   It reads which maps are development-only from `declared-layers.generated.json`, which now carries
   `developmentOnly: true` and is written by `declared-layers.spec.ts` as before. It covers Micromobility and NCAA
   Volleyball too. Until now they were proven only by their services.
