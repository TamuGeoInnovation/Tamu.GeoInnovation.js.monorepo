## What changed

- **`ManagementService.getUsers(filters?, search?)`** (`common-nest-auth`) **stops paging at 1,000 users** and so never asks for the
  page Auth0 refuses. It doesn't catch an error. It returns `{ users, truncated }`, and logs
  `Listed the first 1000 of N users: the Management API pages through no more.` when it is cut off.
  - The old 100-page guard is gone, since the 1,000 limit already bounds the loop.
  - `truncated` is `page.response.total > users.length`. I checked that auth0 7.6.0's `users.list` sends `include_totals: true` by
    default (`include_totals: includeTotals = true` in its client), so `total` is there.
- **The "incomplete" signal is in the body, `{ users, truncated }`, not a header.** The page is the only caller, and a header would
  need `observe: 'response'` in the data service plus an `Access-Control-Expose-Headers` entry. The new type is `Auth0UserList`.
- **The search, `GET users?q=<text>`**, goes through the provider and controller. Each word becomes `(name:*w* OR email:*w*)`, and
  the words are joined with AND.
  - Lucene's special characters are escaped.
  - It is sent with `search_engine: 'v3'` and sorted by name.
  - It stops at the same 1,000 and uses `_composeMetadata`.
  - A blank search counts as no search.
  - The guards are unchanged (`JwtGuard`, `PermissionsGuard`, `read:users`), and the new controller spec checks them.
- **The page:**
  - `UserService.getUsers(search?)` in `gisday-platform-ngx-data-access`.
  - The user list gets a shared `tamu-gisc-textbox` on a `FormControl`, debounced 400 ms. When the list is cut off it says
    "Showing the first 1,000 users. Search to find anyone else.", and a search with no results says "No users match that search."
  - No new styles: it uses the existing `form-collection`, `floating-table` and `loader` classes.
