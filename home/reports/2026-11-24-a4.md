## The sentence worth keeping

**The batch's premise was right and its conclusion was wrong.** It's true that nothing in the application sends a router page view: angulartics2's gtag provider sends page views only to its configured ids, and AggieMap configures none. It does not follow that one should be added. An in-app route change already sends exactly one page view, from the GA4 properties' own history tracking (enhanced measurement), so a page view from the application would be a second one. Anyone reading #3338's wording should check the network before acting on it.
