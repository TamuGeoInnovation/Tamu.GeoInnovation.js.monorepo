## What this changes

<!-- What a reader needs to know. Why, not only what. -->

A name, title or answer someone typed starting with `=`, `+`, `-` or `@` became a formula when an admin opened a GIS Day CSV export in Excel (CSV injection, #3332). None of the seven CSV writers escaped one.

**What changed**
- **`toCsv(columns, rows)`** in `@tamu-gisc/common/utils/ui`, beside `downloadFile`.
  - It writes CSV with Papa, as every export already did, with Papa's `escapeFormulae` on: a cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets a `'` in front, and is quoted.
  - Numbers are left alone, so a negative count stays a number.
  - A row is an array in the columns' order, or an object keyed by them.
- **Every export uses it:**
  - Class attendance (`class-edit`);
  - the dashboards' people lists (`dashboard-people`);
  - Speaker badges;
  - both judging-results files;
  - the competitions submission export (`export.processor.ts`, in the API);
  - the impact report, which wrote its own CSV. Its file still ends with a line break.
- **Nothing else in the files changes:** column order, headers and line endings are as before. A Speaker badges test holds one export byte for byte, and passed on the code before this change.

**Three edge cases change**, none of them a file anyone has asked for:
- An empty class roster downloads an empty file. Its `'No data'` fallback made Papa throw.
- The people lists with no one in them end their header line with a line break.
- The impact report quotes a name that starts or ends with a space, as Papa does.
