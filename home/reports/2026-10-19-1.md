## Not caused by the release: Transportation Services' map server is failing about half its queries

`directions.spec.ts:72` (the event map feature popup on `/parking/avp-parking/map?feature=AVP-parking-lots:26135`) fails
with "did not open its popup". The page selects the lot with one query to the `TS_Events/AnyValidPermitParking`
service (`objectIds=26135`). On failing loads that service answers HTTP 200 with
`{"error":{"code":400,"message":"Failed to execute query."}}`; `EventService.drawEvent` catches it, nothing is selected,
and the popup never opens. The map's own drawing queries on that layer fail the same way on those loads.

| Evidence | Result |
| --- | --- |
| The lot query, outside the app, 20 times | 7 failed |
| The same query as JSON, 20 times | 10 failed |
| A count of all records, 20 times | 8 failed ("Unable to complete operation.") |
| Dev (Release-484), about 25 loads | about half failed, every one with this server error; when the query succeeds the popup with "Directions To Here" opens in 2-7 s |
| **Production** (older code, none of this release) | **failed on 3 of 4 loads**, same error |

So zoneless (#1948), `@defer` (#1940), OnPush (#1908) and the trip planner (#1924) are ruled out. It passed in earlier
tiers because the server was healthy then; failing all three attempts fits a failure rate of about half.

**Noticed alongside:** `drawEvent` runs the URL selection, the chosen view and the focus flash in one `try`, so when the
lot query fails the map also skips opening on the chosen view and the flash.
