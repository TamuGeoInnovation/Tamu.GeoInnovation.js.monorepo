## The cause

**#2088 made the token list the page's own `/api`, and an unconfigured build then asked Auth0 for a token before
every API call.**
- `main.ts`'s Auth0 interceptor sends a call through `getAccessTokenSilently` when its URL starts with an entry of
  `auth0.urls`. It is `allowAnonymous`, so it waits for the answer before sending the call.
- Before #2088, both the API address and the list were unfilled placeholders that never matched each other, so in the
  E2E's build no API call took that path. On production, the list already matched every API call.
- The E2E suite runs `nx serve gisday-angular`, whose Auth0 settings are never filled in. With the list now
  `${origin}/api`, every API call asked `https://___angular_auth0_domain___/authorize` for a token in a hidden frame,
  and waited on it.
- **What the routes saw:** a request log on `/presenters` with the spec's routes showed no API request at all in 25
  seconds, only that `authorize` request. So `**/seasons/active` never fired, the page never asked for presenters, and
  the spec found 0 cards. The routes, the dev server's proxy and the base URL were all fine.

## The fix

`common.config.ts`: `accessTokenUrls(domain, api)` gives `[api]` once the Auth0 domain is filled in, and `[]` while it
is still the placeholder. The placeholder is matched by its shape (`/^_{3}\w+_{3}$/`), not written out, so the
container's substitution never fills that literal. `auth0.urls` uses it.
- **Deployed builds are unchanged:** their domain is filled in, and their API calls went through the token path
  before #2088 too.
- **Not the test:** the test was right. A build with no Auth0 shouldn't hold every API call on a sign-in host that
  doesn't exist.
