## What this changes

`discover.visible: false` meant "not in production's listings". So development still listed the undated Move Out beside its three dated periods, which is what #1691 set out to stop, and the smoke suite needed an allowance for it on the dev hosts. **It now means "not in the listings", on every environment**, the decision taken in the issue (its third option):

- **One meaning on both environments.** Dev exists to show what production will show; a listing that differs is dev misreporting the thing it is for.
- **It holds for the next map.** An undated parent kept alive for its old links is a pattern, not a one-off.
- **The alternatives each cost more.** A redirect throws away the parent's own page; an inverted `DevelopmentOnly` registration adds a second concept meaning almost the same as the first.

How:

- **`developmentOnly` is now its own field** on a listed map (`InternalDiscoverApplication.developmentOnly`). A development-only map used to arrive as `visible: false`, which is why the two meanings were tied. The one listing rule, `isListed`, is now `visible !== false && (isTesting || !developmentOnly)`. Development-only maps are listed on development alone, exactly as before, and the registry behaviour (`developmentOnly` maps absent from a production build) is unchanged.
- **The All Maps search** applies that rule on both environments instead of returning every map on development (`_filterApplications`).
- **Dev's All Events list** applies it too. It still keeps retired maps, labelled, but a map with `visible: false` is in no listing. This one matters for the smoke suite, which discovers maps by crawling the listings: with the search fixed, the crawl still found the undated Move Out in All Events.
- **`allowedUndatedEventMaps` loses `/events/move-out`** on both dev-host environments: the map is no longer discovered.
- **`LISTINGS_HIDDEN_FROM_PRODUCTION` is deleted**, with its escape hatch in `development-only-gates.spec.ts`. Its only entry was Move Out, and a map can now be listed on development and not on production only by being development-only, which the gates spec's other lists already check. The spec's "hidden listings" are now the listing rule asked both ways (`isListed(app, true) && !isListed(app, false)`), not `visible === false`.
- **CLAUDE.md's gate rule** said a listing is gated at run time by `visible: false`; it now says `developmentOnly`, and that `visible: false` is not a gate.
- Specs that stood in for a development-only map with `visible: false` (campus, event-maps, parking-maps) now use `developmentOnly: true`. The campus definitions test counts a campus marked either way.

The only map with `discover.visible: false` today is the undated Move Out; nothing else's listing changes.
