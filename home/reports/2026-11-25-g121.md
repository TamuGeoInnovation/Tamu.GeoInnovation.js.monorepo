## The short answer

Zoneless holds. **#3616 cannot have made anything worse.**
- GIS Day's own components were already `OnPush`; #3616 only removed the explicit lines.
- The shared components it marked `Eager` are now refreshed in every tick `OnPush` would refresh them in, and more.

So the only question was whether a shared component changes its own state from an async callback with nothing telling
Angular. **One did: the file picker's `reset()`.** It is fixed behind its interface, with a red-first spec.
- No GIS Day caller hits it today.
- Nothing in the component guaranteed that.

## 3. The fix

In `libs/ui-kits/ngx/forms/src/lib/components/file/file.component.ts`, `reset()` now calls `markForCheck()`, through
`inject(ChangeDetectorRef)`.
- **The interface is unchanged.** I did not turn the fields into signals, because Geoservices' upload input extends
  this component and its template reads `fileName` as a plain field.

**Red first:** a new `FileComponent, zoneless` spec calls `reset()` from a timer.
- Without the fix it **failed**: `expected 'attach_fileposter.pdfClear' not to contain 'poster.pdf'`.
- With it, it passes. `ui-kits-ngx-forms` passes 116 of 116.

**Why no GIS Day caller hits it today:**
- `submission-files` resets in an upload's `complete` and `error`, but right after setting the `uploading` signal. That
  redraws the parent, and an `Eager` child is redrawn with it.
- The image pickers reset in `choose`, which runs inside the picker's `fileSelected` event handler.

So this is a guard, not a visible fix. That is why the commit carries no release-notes entry.
