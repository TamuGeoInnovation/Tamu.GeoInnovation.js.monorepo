## The fourth hazard (not in the issue)

**With `ignoreInvalidLocations=true`, a batch in which no pair can be routed is not an empty answer.** It is
a 400 with a reason per pair, in two forms: `No route for "1089-1430" from location "1089" ...` and
`Location "1811" in "Stops" is unlocated. Need at least 2 valid stops for route "1089-1811"`. It happened at
33,000 pairs, where a whole batch started at 1089. `joinRoutes` now treats an error that names pairs from the
batch as every pair missing, to be asked again one at a time; an error that names no pair (an outage, a token,
a bad parameter) still stops the run. Commits `3053a9a4f` and `e07aa50c0`, each with a test. The first
("No route") was red before its fix; **the "unlocated" test was not run red**, it was written with the fix,
which I say rather than claim.
