Title: `fix(scripts): The branch sweep keeps a branch a remote still has, or one never pushed`

## What changed

`scripts/tidy.sh` decides a branch's fate in this order:
1. **A remote still has it** (any `refs/remotes/<remote>/<name>`): kept, before every other rule. This is the Dependabot branch the g123 sweep deleted.
2. **Its tip is in `origin/development`**: pruned only if it was published (its upstream is a branch of the same name) or its pull request merged.
3. **Made here and never pushed**: kept, with or without commits.

`scripts/check-in-volume.sh` passes the branch it checks as `TIDY_KEEP_BRANCH` to both of its sweep calls, so a sweep never removes what the check is about to fetch.

**A flaw in the first draft, caught by a dry run.** `git branch x origin/development` sets the upstream to `development`, so "has an upstream" read a never-pushed branch as published, and it would have been pruned. "Published" now means the upstream is `refs/heads/<its own name>`. That has its own red test.
