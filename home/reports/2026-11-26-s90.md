## Deployed code
- **#4, `js/request-forgery`, real.** A site copy file's `source` could be any `https://` host, and before this `http://localhost:<any port>` too. An import then fetched logos and photos from it, so an uploaded file could make the API request internal addresses. The endpoint needs three admin permissions, but the fetch should not depend on that. `copySource()` now returns the source only from `GISDAY_SITES` (addresses and `hosts`) or the API's own `ORIGINS`, and the fetch uses that returned value. Local sites come through `ORIGINS`, which `local.env.sample` already sets.
- **#14 and #15, `js/path-injection`: CodeQL's path is not exploitable today.** `upload.path` is chosen by the server: `SUBMISSION_FILE_UPLOAD` writes `uploadingDirectory()/<randomUUID>.part`, and its `fileFilter` admits only `.pdf`, `.ppt` and `.pptx`. A guard was added anyway, as the batch asked: `storeUpload` and `discardUpload` act only on a path inside the uploading folder.
- **#3, `js/polynomial-redos`, real.** `looksLikeEmail` took 526 ms on a 20,000-character address that fails at its end. It is now checked piece by piece, with the same meaning.
- **#2, `js/polynomial-redos`, real.** `getXmlStatusCode` took 3.3 s. It now reads by position.
  - **It also had a bug:** it returned the whole match, so every XML answer read as NaN and was thrown as an error. XML 200 answers now succeed, which is a behaviour change in geoservices for `responseType: 'document'`.
- **#13, `js/path-injection`, real.** `writeFileToDisk` wrote under the client's `originalname`, so `../../x.png` landed outside the folder. Only the name's last part is used now, `.` and `..` are refused, and the resolved target must sit in the folder.
