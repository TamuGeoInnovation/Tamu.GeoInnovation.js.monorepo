## What this changes

**A smoke test that times out waiting for a map to draw now says why.** `waitForMapDrawn` gave only the spec's message, so a slow draw read as a broken map. Muster failed three times as "never finished drawing both layers" with both layers drawn in its screenshot, and its order assertion never ran.

At the last reading before the timeout, it now names which condition was unmet:

- the page had no map probe (an older build, or not a map page);
- the probe was not ready: a layer was still loading;
- it was ready but still drawing;
- or it had finished drawing, but the layers were not the ones asked for, listed with each one's id, and whether it was hidden, not loaded or in error.

What passes and fails is unchanged: each reading returns the same answer as before, and only the failure message gains a line. The choice of one timeout for every caller, the rest of #3369, is not made here.
