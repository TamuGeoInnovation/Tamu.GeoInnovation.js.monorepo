## The changelog
jimp's packages ship no changelog, and the GitHub release read was not available here, so the published code of 1.6.1, 2.0.0, 2.1.0 and 2.2.0 was compared directly.
- **2.0.0:** Node 22 or later (we run 24.22.3). `plugin-resize` takes zod 4. Every call `libs/common/node/images` makes keeps its shape: `createJimp`, `fromBuffer`, `resize({ w, h })`, `getBuffer` with `quality`, `deflateLevel` and `colorType`, `bitmap` and `mime`.
- **2.1.0:** jimp's own JPEG and PNG codecs replace `jpeg-js` and `pngjs`. JPEG gains `chromaSubsampling` (default 4:2:0 below quality 90) and `progressive`.
- **2.2.0:** additions only for what we use: `image.apply()`, PNG `maxResolutionInMP`, and an EXIF refactor from a WeakMap to a symbol. Its output is identical to 2.1.0's.

## Red, then the fix (Q-s87-4 A)
**The first full check, on the plain upgrade, exited 1 on one test:** `fit-image.spec.ts`, "changes nothing the second time, so a re-run does not lose JPEG quality again".
- **The cause:** under 4:2:0, re-encoding `fitImage`'s own output saved 13%, which is more than the 10% threshold, so a second run compressed the photo again.
- **The fix:** `fitImage` now passes `chromaSubsampling: '4:4:4'`. The test is unchanged and passes.
- With the fix, a second run keeps the file on the synthetic image and on the real photos. The JPEG sizes come within 2% of 1.6.1's, replacing Q-s87-2's 4:2:0 choice.
