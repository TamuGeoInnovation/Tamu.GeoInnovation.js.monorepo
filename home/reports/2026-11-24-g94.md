## What this changes

<!-- What a reader needs to know. Why, not only what. -->

`GET /speakers/:guid`, which the public presenter page reads and anyone may call, loaded every session the speaker is in, hidden ones (`active` false) included. So a hidden session's name, time and details went to anyone who asked (#3345).

**What changed**
- **`getPresenter` leaves out the hidden sessions** after loading. It filters after loading rather than in the query, so a presenter whose every session is hidden is still found, with none.
- **The admin speaker form** reads the same route and uses none of its sessions, so it is unaffected.
- **The same file as PR 3344** (#441): that pull request adds guarded `speakers/sessions/season/...` routes to `speaker.controller.ts`. This one changes `speaker.provider.ts` and its spec only, so the two shouldn't conflict, but they touch the same feature.

**Checked and not fixed here:** every other public route that returns speakers or sessions. The event routes return hidden sessions too, six of them, and one feeds the admin Events list, so that fix needs an admin route of its own. It is [#3354](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/3354).
