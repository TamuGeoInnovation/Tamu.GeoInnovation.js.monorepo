## What looks wrong (not the migration)

1. **The smoke suite's garage check will fail after this.** `test/smoke/aggiemap/search-sources.spec.ts`, case `parking-garage`, types
   "Central Campus Garage" and expects that result and popup text. Under the new query that term matches **0 rows**, because the name is
   "Central Campus Parking Garage". The branch does not change the spec, so its next smoke run, on dev once deployed and on production
   after release, should fail that case. It needs `term` / `result` / `popupShows` moved to the new name, or the term changed to one both names
   contain, such as "Central Campus". **This change makes the spec wrong; the app is right.**
2. **The Parking Garage results now duplicate the Building results.** Searching "garage", both categories list the same five garages,
   in the same order, from the same layer (Building with the number in brackets). Before, the two differed because they came from
   different services. That is a design question for the director: hide one, or accept it.
3. **Only five of the ten garages appear** for "garage", before and after, since the source asks for 5 (`resultRecordCount=5`). Before,
   the five shown included Gene Stallings Blvd Garage; after, they include Polo Road Garage instead. Neither is wrong, but "garage" never
   lists every garage.
4. **`Y316`** is a `GARAGE` row with no name or code. It cannot match "garage", but a search for "Y316" would list a result with an empty
   name. GIS team data, for #3421's register.
