## The cause: Nx 24.0.6 and Angular's architect 0.2203.0 do not fit together

- **Every Angular app builds with `@angular/build:application`, run by Nx.** Nx loads Angular builders through its
  adapter, which at `nx/dist/src/adapter/ngcli-adapter.js:941` in **Nx 24.0.6** (the version on `development`) does:

  ```js
  await handleImport('@angular-devkit/architect/node/index.js');
  ```

- **`@angular-devkit/architect` moves 0.2202.7 → 0.2203.0 in this pull request**, as a dependency of `@angular/build`
  and `@angular/cli`. The new version declares an `exports` map that allows `./node` but not `./node/index.js`, so the
  deep import Nx makes is refused. Angular's own CLI imports `@angular-devkit/architect/node`, the allowed form, which
  is why the Angular packages themselves are fine.
- **Nx 24.0.7 fixes it.** I checked the adapter in the published tarballs:

  | Nx | `ngcli-adapter.js` imports |
  | --- | --- |
  | 24.0.5 | `@angular-devkit/architect/node/index.js` |
  | 24.0.6 (on `development`) | `@angular-devkit/architect/node/index.js` |
  | **24.0.7** | **`@angular-devkit/architect/node`** |

- **But 24.0.7 is too new to take.** It was published on 25 November at 12:52 UTC, one day ago, so it passes the
  seven-day rule on **2 December**.

So the Angular 22.3 group needs the `nx` group at 24.0.7 first, or in the same change. Neither can merge before
2 December. Q-a60-1.
