### The one decision I changed

The agent typed a submission's `participants` entries as never null and removed the old code's `p?.` guards. But `participants` is
user-typed JSON, so a stored null would then throw. The type now allows a null entry. The guards are back in the judging, user-submission
and speaker-edit code (the speaker-edit loop skips a null entry). A small `withoutEmptyParticipants` gives the shared review email its entries
without nulls, since gisday/common's type does not take them.
