## What this changes

<!-- What a reader needs to know. Why, not only what. -->

Admin pages chose their season three ways (#3329):
- **The admin lists' base:** it kept `?season=` in the address.
- **The judging pages** (Rubrics, Judging results, Winners): `seasonChoice()` kept it in a signal only, so a reload lost it.
- **Four dashboards** extended the list base only for its Season box: accounts, and the event dashboard behind RSVPs, check-ins and VGI.

**What changed**
- **`seasonPicker()`** in `platform/ngx/common` (`lib/utils/season-picker.ts`, exported). Called in a component's field initializer, it gives:
  - the seasons, and the season shown, as observables and as signals;
  - `choose(guid)`, which puts the season in the address.

  The season shown is the one the address names, else the active one, else none on a site with no season (#2076).
- **The list base** gets its season from the picker. It still reads the list again after a copy or a delete.
- **The judging pages** use the picker in place of `seasonChoice()`, which is deleted. Their season is now in the address, so a reload or a shared link keeps it.
- **The account dashboard and the event dashboard** (RSVPs, check-ins, VGI) use the picker and no longer extend the list base. Their templates are unchanged.
- **Speaker badges stays on the list base:** it also uses the base's search and the filters it keeps in history. It gets the picker through the base.

**What an admin sees differently:** on Rubrics, Judging results and Winners, choosing a season changes the address, and a reload shows the same season. A season the address names wrongly shows the active one, as the lists already did. Nothing else changes.
