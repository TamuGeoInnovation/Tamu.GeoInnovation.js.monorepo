## What this changes

<!-- What a reader needs to know. Why, not only what. -->

GIS Day loads gtag (GA4) in `index.html`, but its events went to angulartics2's analytics.js provider, `Angulartics2GoogleAnalytics`, which calls `ga()`. The page has no `ga()`, so no event was ever sent; only gtag's own page view arrived (#2275).

**What changed** (GIS Day only)
- **`apps/gisday-angular/src/app/analytics.ts`** names the provider, `Angulartics2GoogleGlobalSiteTag`, angulartics2 14's own gtag provider, which sends `gtag('event', ...)`. It also holds angulartics2's settings. `main.ts` and `AppComponent` use both, so the choice is made in one place.
- **Virtual page tracking is off.** gtag sends the page view on load, and GA4's enhanced measurement sends one on each change of address, so a second would double-count every page.
- **#2572 still holds:** `index.html` takes a check-in code out of the address before gtag loads, and angulartics2 now sends no address of its own.
- **No new provider was written.** angulartics2 has one for gtag, so nothing was needed in `libs/common`.
- **The events this lets through are the ones already written:**
  - `notification_action` from the shared notification components;
  - `submission_fail` from the competitions submission form, carrying the error's message.
  Neither carries the page address or a check-in code.

**AggieMap's half of #2275 is not in this pull request.** AggieMap uses the same analytics.js provider and sends no page views; that is the AggieMap work.
