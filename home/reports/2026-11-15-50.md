## What it does

**Dashboards > Check-ins**, under RSVPs in the admin menu, shows for the selected season:

- each event's check-ins by person type, with an **RSVPs** column beside them so turnout can be compared, and a total row;
- check-ins over time (running total by day, each day's check-ins beneath, the GIS Day week shaded);
- for an opened event, who checked in and the time each did, under their type, with **Export as CSV**.

## Reused, not copied

The RSVPs dashboard was already built on shared pieces (table, people list, chart). The rest became shared too:

- **API:** one `EventDashboard<T>` (`libs/gisday/platform/data-api/src/lib/dashboards/event-dashboard.ts`) runs the season
  and event queries over any record with an account, an event and a time. `RsvpDashboardProvider` is now just a
  subclass of it; `CheckInDashboardProvider` is another, adding each event's RSVP count. **A check-in does not load its
  event eagerly as an RSVP does**, so the shared query asks for it by name; without that every check-in would have
  counted for no event. A test pins it.
- **Page:** one abstract `EventDashboardComponent` (season loading, opening a row, the chart, the CSV name). The RSVPs
  and Check-ins pages name their service and CSV prefix and keep their own wording. The RSVPs page's selector, route
  and template are unchanged. The shared table gained one input, `totalHeading` ("Checked in").

## Admin only, this site only

- `GET check-ins/dashboard/season/:guid` and `dashboard/event/:guid` need `read:checkins`, like the existing check-in
  reads. The page is under the admin area's role guard.
- **`private-fields.interceptor.spec.ts`** gained a block that finds every dashboard route (`getDashboardFor*` on the
  RSVP and check-in controllers) and checks each keeps `JwtGuard` + `PermissionsGuard`, no `AllowAny`, and a
  `read:rsvps`/`read:checkins` permission. They answer with names and emails as plain objects, which the interceptor
  does not look into, so the permission is what keeps them private.
- Each event row now carries its place, and both dashboards keep only the site's own sessions with `siteListsSession`
  (#2986).
