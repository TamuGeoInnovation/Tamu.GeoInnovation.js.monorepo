## What changed

The VGI submission endpoint (`POST competitions/submissions`) now runs each photograph through `refuseUnsafeImage`. It
is the function itself, not a copy, exported from `gisday-platform-data-api` for this (the competitions library already
depends on it). So, the same as every platform image upload:

- not a JPEG or PNG by content → **400** "A photograph must be a JPEG or PNG image.";
- a header declaring more than the pixel limits → **413**;
- stored as the type it is, not the type the sender named.

It runs before anything is saved.

**`accept="image/*"` on the form is left as it is, on purpose.** The form already redraws every photograph it can decode
as a JPEG before upload (`shrinkImage`, #1786). Narrowing `accept` to JPEG and PNG would only hide gallery formats it
converts anyway. When a refusal does happen, the form's toast shows the server's message.
