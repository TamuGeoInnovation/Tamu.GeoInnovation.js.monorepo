## 1. Our two imports (the one production finding)

Three calls:
- `layer-sources.service.ts:91`: `deepmerge(source, override)`;
- `event.service.ts:138`: `deepmerge(source, correspondingOption.propOverrides)`;
- `event.service.ts:325`: `deepmerge(child, conversion.propOverrides)`.

**Every merged object is compile-time data from the definitions:**
- `{ visible: false }`, `{ popupComponent: null }`, or football's `{ native: { visible, listMode } }`;
- merged into a JSON round-trip copy of a definition, or into the compiled environment's layer sources.

URL parameters and saved settings only *choose* among predefined overrides, and are whitelisted against each option's choices
(`event-settings.service.ts:388-416`). No service JSON or URL value is ever an argument. **Not exploitable.**

**What the merge must keep:**
- it must not mutate its inputs;
- class references (`popupComponent`) are copied, not cloned;
- no override contains an array, so concatenation never matters.

**Nothing to reuse:** `libs/common` has no deep merge, and the root has no lodash, defu or similar. The right home is
`libs/common/utils/object` (`@tamu-gisc/common/utils/object`). `event.service.ts` already imports from it, it imports nothing itself,
and it has a spec file.

Proposed helper, about 15 lines with its tests:
- `deepMerge(target, source)` returns a new object;
- it recurses only into plain objects;
- arrays and everything else replace the target's value;
- it skips `__proto__`, `constructor` and `prototype`.

With it, `deepmerge` comes out of `package.json`.

## 2. The dev-only paths (the other 12 or 13)

They come only through `jest-config` 30.5.2 (`deepmerge.all(...)` and `deepmerge(...)`) and `fork-ts-checker-webpack-plugin` 9.1.0
(`deepmerge(...)`, reached through `@nx/webpack`). Both call deepmerge 4.x's default export, `.all` included. So:
- **an `overrides` target must be API-compatible**, which rules out the three libraries above;
- **the only API-compatible options are patched 4.3.1 republishes**:
  - `@oss-cve-patches/deepmerge` 4.3.2 (1 October 2026, 238 a week). Its diff against 4.3.1 is a check that drops `__proto__`
    keys. It has no install scripts and no dependencies, and its changelog cites a CVE id that could not be verified.
  - `@afeisite/deepmerge-clone` 4.3.2 (28 September 2026, 550 a week). It also drops `constructor` and `prototype`.

  Both are new, single-maintainer, low-download accounts, **which is a supply-chain question in itself.**
- **Proven in a scratch copy:** remove our direct dependency, add `"overrides": { "deepmerge": "npm:@oss-cve-patches/deepmerge@4.3.2" }`,
  then `npm install --package-lock-only`. The lock re-resolves both nested copies to the fork, and **`npm audit` reports 0**. **Not
  yet run:** jest and a Nest webpack build with the override in place.
- **Vendoring a patched copy with `file:` doesn't work:** npm 11 resolved it per dependent and produced broken links.
- **Removing the paths outright** would mean moving the 27 remaining jest projects to vitest and dropping `@nx/webpack`, which four
  Nest apps build with. That is a large migration.
