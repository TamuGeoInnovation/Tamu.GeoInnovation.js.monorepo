## Why

**The event maps resolve popup data in their own copy of the code.**
- `PopupService` (`libs/maps/feature/popup/src/lib/services/popup.service.ts:170-241`) and `EventService`
  (`libs/ts/events/ngx/src/lib/services/event/event.service.ts:814-860`) each have a private `resolvePopupData`, `resolvePopupDataEntry` and
  `getPopupDataLookup`, line for line. The event copy dates from #809.
- `dffd02eec` changed only `PopupService`'s copy, to `renderTemplateRows`. `EventService` still calls `new TemplateRenderer(...).render()`.
- With the event maps' default strategy, that renderer sets no `nullishReplacement`, so a null field leaves its `{attributes.…}` text in
  the popup.

So #2816 is fixed on the main map's popups and on no event or transportation map. Those maps include Sustainable Transportation, where the
fault is today.
