## jsdom 31.0.0's breaking changes, against our use

1. **The canvas backend moved from `canvas` to `@napi-rs/canvas`.** Neither is installed here, so jsdom's canvas has
   never worked in our tests (`getContext` returns null), before or after. **Not affected.**
2. **A new integrated CSS engine** for parsing, selector matching and computed styles. Computed values and CSS
   serialization can differ from 30.x. This is the one that could matter, for specs that read `getComputedStyle` or
   `style`. All 63 Vitest projects' specs pass with it. The Jest specs that read computed styles, such as gisday's
   `button-colours.spec.ts`, still run on jsdom 26.1.0. **No failures.**
3. **HTML and XML parsing pauses at blocking scripts**, so `new JSDOM(...)`, `JSDOM.fromURL()` and `JSDOM.fromFile()` can
   return a partly parsed document. Nothing here constructs a `JSDOM` directly (no `from 'jsdom'` or `require('jsdom')`
   in apps, libs, tools or test). Vitest builds its environment through its own wrapper. **Not affected.**

**Other changes worth knowing:**
- **Load events:** page-completion `load` events now fire only on the window, not the document.
- **Focus:** focus moves away asynchronously from an element that becomes non-focusable.
- **New APIs:** `window.reportError()` is added.

Nothing in the notes about `ResizeObserver` or `matchMedia`: jsdom still provides neither, as before. Any spec that
needs one stubs it itself, and those specs pass. Navigation is still not implemented. The notes' changes are to
`document.open()`, `document.write()` and `window.stop()`, which we don't use.

31.0.1 (13 November) adds performance work and small fixes (`tabIndex` parsing, CSS `ident()` serialization). It is 10
days old.
