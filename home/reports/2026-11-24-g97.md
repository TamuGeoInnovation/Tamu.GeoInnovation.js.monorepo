## What this changes

<!-- What a reader needs to know. Why, not only what. -->

The RSVP type and submission type pages were two copies, identical but for one placeholder, on `BaseAdminAdd`, `BaseAdminDetail` and `BaseAdminView`, which no other admin page used. Those classes only logged their results, and had no Escape, no "Leave without saving?" and no back-to-list (#2942, #2965), so every fix to admin pages missed these two (#3328).

**What changed**
- **One shared form, `TypeAddEditFormComponent`**, in `platform/ngx/common/.../forms/components/types`. Like the tag form, it has one field, and Save, Create and Delete go back to the list (#2965).
- **`TYPE_PAGE` (`type-page.ts`) says which type a route is for:** its noun, titles, the field's label, the list's address and its service.
- **One set of pages in `admin/pages/type`:**
  - the list, on `BaseAdminListComponent`;
  - Add and Edit, on `BaseAdminDetailsPageComponent`, so Escape goes back to the list and asks "Leave without saving?" with changes not saved, as on every other admin page.
- **`admin-type.routes.ts` gives `rsvpTypeRoutes` and `submissionTypeRoutes`**, each providing its `TYPE_PAGE`, in the tag section's plain frame.
- **Deleted:** the three old base classes, and both old page folders with their four route files. Nothing else used them.

**What the pages keep, pinned by `type-pages.spec.ts`:**
- the list's Type and Updated columns;
- each type's field label: "Type" for RSVP types, "Submission Type" for submission types, as before.

**What they gain** is what every other admin page has: a title ("Create RSVP Type", "Update Submission Type"), an Add link on the list, and a Delete button on the edit page, where the old pages had an edit list with a delete icon per row. **That is a visible change**, so it wants before and after images of the four pages, which the laptop takes, since this machine does not sign in to admin pages.

**Also found:** the old edit pages subscribed to their record in the base's `ngOnInit` before making the form it fills. A record answered at once would have hit an undefined form; real HTTP answers later, so it worked in practice. Gone with them.
