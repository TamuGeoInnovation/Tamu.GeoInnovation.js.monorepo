## What counts as "final uploaded" (what I found)

A submission's attachments are `Asset` rows with `type: 'submission-file'` and **no kind**, and the abstract is a text
column, not a file. So **any attached file is the final presentation or poster**, as you suggested. That is one rule,
`hasFinalFile` in `libs/gisday/common/src/lib/review-email.ts`, used by the column, the page's note and the API's skip.

## What it does

- **Final file column**, Uploaded or Missing (Missing in red), beside Files. It's a row field like Status, so the table's
  existing sort works; the Files count stays. I chose the column over making Files sortable: Files already sorts on
  `files.length`, but a count doesn't answer "uploaded or not".
- **Send final reminder** beside Send profile email, by the acceptance email's whole path:
  - `review-email.ts`: two kinds, `presentation-reminder` and `poster-reminder`, with the issue's draft as the text.
    The poster's keeps the poster finalist's details (print size, be at your poster), and both have the other emails'
    sign-off. Same placeholders.
  - The same `review-email-modal`, editable first; it gained an optional `verb`, so it reads "Send final reminder" and
    its button "Send N emails".
  - The same send: the provider's preview is now one `_preview` and its send one `_sendEmail`, used by both the review
    and the reminder. The review's repeated permission and id checks became one `checkReviewerAndGuids`. Same
    recipients (#2990), sessions (#2985), placeholders.
- **Skips submissions that already have a file**: the window says "1 of the 2 selected already has a file and is
  skipped", the API skips them too, and the toast counts them. Selecting only ones with a file opens nothing and says so.
- **Admins only**: `POST user-submissions/remind` and `remind/preview` need `update:competitions`. Nothing is recorded.
