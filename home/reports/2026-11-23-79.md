## 2. The change

- **`common.config.ts`:** ``api_url = `${window.location.origin}/api` ``, and `auth0.urls = [api_url]`. The token goes
  exactly to this address's API and nowhere else. It used to go to the API's whole origin.
- **`main.ts`:** the matcher loses its type assertion.
- **Local serving:** `proxy.local.json` and `gisday-local-static.conf` serve `/api/` instead of `/___ANGULAR_API_URL___/`.
- **Docs:** `docs/gisday-local.md` and the app README are updated, and both compose files drop the two variables.
- **Which site the API answers as is unchanged.** A same-origin GET has no `Origin`, so `siteHost` uses
  `x-forwarded-host`, then `Host`, which the ingress sets to the page's address.
- **The service worker is left alone.** Its `api` data group still matches txgisday.org's calls exactly as before.
  Widening it would bring its 5-minute cache, which answers from cache after 250 ms, to the other addresses' admin
  pages. That is a behaviour change for its own issue.

## What this changes

<!-- What a reader needs to know. Why, not only what. -->

The site called the API at one fixed address per deployment, `ANGULAR_API_URL`. txgisday.org's deployment also serves gisday.tamu.edu and tamu.txgisday.org, and their production bundles call `https://txgisday.org/api`. So those two addresses make cross-origin calls, which work only while each is listed in gisday-nest's `ORIGINS`. tamu.txgisday.org went live unlisted and showed no data (#2087).

Every address's ingress already sends `/api/` to the same API: txgisday.org, gisday.tamu.edu, tamu.txgisday.org and gisday.ucgis.org each answer `/api/seasons/active` themselves.

**The change**
- **`common.config.ts`:** the API is `${window.location.origin}/api`, so every call is same-origin and a new address needs no `ORIGINS` entry.
- **The token:** the Auth0 interceptor sends the access token to exactly that address (`auth0.urls: [api_url]`), so signed-in calls keep their token on every address and never send it elsewhere. Before, the list was `https://txgisday.org` (the API's whole origin).
- **`main.ts`:** loses the type assertion the placeholder needed.
- **Local serving:** the dev server's proxy (`proxy.local.json`) and the static nginx configuration (`gisday-local-static.conf`) serve `/api/` instead of `/___ANGULAR_API_URL___/`.
- **Removed:** `ANGULAR_API_URL` and `ANGULAR_AUTH0_URLS` from the README's variables and both compose files. `docs/gisday-local.md` is updated.

**Unchanged**
- **Which site the API answers as:** a same-origin GET sends no `Origin`, so the API's `siteHost` falls back to `x-forwarded-host` and then `Host`, which the ingress sets to the page's address.
- **Uploads:** already relative (`assets/uploads/...`).
- **The service worker:** its `api` data group (`https://txgisday.org/api/**`) is left as it is. It still matches txgisday.org's calls exactly as before, and widening it would bring its 5-minute cache to the other addresses' admin pages.

**Deploying it**
- `ANGULAR_API_URL` and `ANGULAR_AUTH0_URLS` become unused. Removing them from the configmaps is optional and can follow.
- `ORIGINS` stays as it is until this build is live on every address, so a tab still running the old build keeps working.
