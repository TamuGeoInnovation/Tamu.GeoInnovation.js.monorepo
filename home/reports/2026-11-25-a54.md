## 1. Which routes change destination: none

That is the list, and it is deliberate.
- **The inventory today:** 13 maps and 364 destinations. Every map has exactly **one** layer set, and its first
  destination is the map's first destination.
- **One-per-map selections are unaffected.** That covers `framing.spec`'s release scope and `building-clicks`, which
  pick the same 78 routes either way.
- **The full framing run is the risk.** Building `servedRoutes` on the per-layer-set choice would cut it from **428**
  routes to **78**, the same set as one per map.
  - **350 baseline keys** would leave `framing-baseline.json`.
  - Every other builder choice would stop being framed. That matters because those choices can move where a map opens
    without changing its layers: the event maps set a `mapView` per choice.
- **So I did not unify the selection. I unified the reading.**
  - `builder-destinations.ts` has the one reader, `readBuilderDestinations`, with the one declaration of the path and
    the shape. It returns every destination by map route, in order, with `borrowedFrom`.
  - `loadBuilderTargets` (one per layer set) is built on it, and so is `servedRoutes` (all, or the first per map).
- **Proof:** a throwaway spec, run on **production** through `run-local.sh`, wrote both `servedRoutes` modes and
  `loadBuilderTargets` to JSON before and after. **`cmp` reports identical**: 428, 78 and 13. The spec is not committed.

**So no baseline key moves, and there is nothing to regenerate.** This is your step 3: if they had moved, I would have
stopped, and they don't.

## What this changes

`test/smoke/aggiemap/builder-destinations.ts` and `framing.ts` each read `tools/builder-inventory`, each declaring
the file's path and shape, and only the first knew a destination could be borrowed from another environment (#1134).
Now there is **one reader**, `readBuilderDestinations` in `builder-destinations.ts`.
- It returns every recorded destination, by map route and in order, marked `borrowedFrom` where the inventory was
  crawled elsewhere.
- `servedRoutes` is built on it.

**Each use still chooses its own destinations, on purpose:**
- `loadBuilderTargets` takes one per layer set, as before. `maps.spec` and `map-layers.spec` ask about layers.
- `servedRoutes` takes every destination, or the first per map, as before. Builder choices can move where a map opens
  without changing its layers (the event maps' per-choice `mapView`), so framing must not take the per-layer-set
  shortcut.
- `tools/visual-baselines/capture.mjs` reads every destination on purpose and is left as it is.

**No route changes destination, so `framing-baseline.json`'s keys do not move.**
- Both readers' outputs on production were written to JSON before and after the change, and the two files are
  byte-identical: 428 routes in full, 78 one per map, and the same 13 builder maps' targets.
- Folding `servedRoutes` into the per-layer-set choice would have cut the full run from 428 routes to 78, the same set as one per map: 350 baseline
  keys dropped, and builder choices no longer framed.

**The borrowed flag, where it matters.**
- **Before:** a borrowed destination that lands on the builder never creates a view. So `framing.spec` skipped it as
  "gated behind a builder with no recorded destination". That reason is wrong: it has one, recorded on another
  environment.
- **Now:** it says so, as `map-layers.spec` already does. It was skipped before and is skipped now; only the reason
  changes.

**Checked on production first, as the issue asks.**
- The four inventory destinations missing from the baseline are April and November Ring Day, days 1 and 2.
- April Ring Day is not served on production at all, so it is never framed there.
- November Ring Day's two **do land on production**. They are missing only because the baseline was captured on
  4 October, before those dates existed.
- So no current borrowed destination fails to land on production. One that did would be skipped, never failed:
  - in a baseline update, at the builder check;
  - in a compare run, as not in the baseline.
