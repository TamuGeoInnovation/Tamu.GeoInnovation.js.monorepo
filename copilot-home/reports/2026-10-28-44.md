## What changed (22 files, +123 -19; LF)

- **New `ActivateDirective`** (`[tamuGiscActivate]`) in `ui-kits-ngx-interactions-keyboard`: host `role="button"`, `tabindex="0"`, `click`, `keydown.enter`, `keydown.space` (with `preventDefault`), emitting one output. The keyboard handling now lives in one place.
- **Nine call sites** now read `<div class="button" (tamuGiscActivate)="startDirections()">Directions To Here</div>`: `base-directions`, `bonfire`, `building`, `bus-stop`, `dining`, `markdown-w-directions-popup` (aggiemap), `parking-lot`, `poi`, and the events library's `markdown-w-directions-popup`. `parking-garage` renders `parking-lot`'s template, so it only needed the import (that is the tenth component).
- I found **nine templates**, not ten, with the block. The issue's "ten" is the ten components (garage shares the lot template). None is left as a copy.
- **Differences, none needing a new input:** `building`, `dining` and `base-directions` keep `[attr.building-number]`; `bus-stop` passes its label as an argument to `startDirections`; the rest call it with no argument. All of that stays in the template, since the directive only owns activation.
- **Why a directive, not a component:** the label and the `@if (directionsAvailable | async)` gate stay at each site. That keeps `directions-availability.spec.ts` meaningful and **unchanged** (it reads `Directions To Here` plus its gate from each template). Moving the label into a component would have hidden it from that guard.
