## What I did

**PR 2479 first.** It was right in outline (build the gallery's layer with `makeBaseLayer`, export it from `@tamu-gisc/maps/esri`) but it was also incomplete: it still copied only `baseLayers[0]`, so even restored it would have lost the construction hatch (`baseLayers[1]`). So this is not a plain restore:

- New `libs/maps/feature/basemap/src/lib/shared/gallery-basemaps.ts`: `makeGalleryBasemap(definition, Basemap, constructors)` makes **every** base layer of a definition through `makeBaseLayer` (cloned first), so `hiddenStyleLayers` runs and the hatch layer is carried. The gallery service now calls it; `FeatureLayer` is added to the modules it requires.
- `libs/maps/esri/src/index.ts` exports `basemap-layers` again (the export 2479 added and 2486 removed). Without it the first check failed to build: `No matching export ... for import "makeBaseLayer"`.
- The base layer used for the 3D "can this draw in a scene" check is still `getItemAt(0)`, which is still the tiles.

**The checks (the deliverable):**

1. `gallery-basemaps.spec.ts` (Vitest, 4 tests): every base layer present, hidden style layers hidden, no `type`/`hiddenStyleLayers` passed to the layer classes, and every gallery basemap on both environments keeps all its layers.
2. `test/smoke/aggiemap/basemap-gallery.spec.ts`, the existing round-trip test (vector, Streets, Light Gray, back): it now also counts the `Buildings under construction` layer, which its type filter used to miss, so "coming back brings back what the map opened with" fails when the hatch is lost.
