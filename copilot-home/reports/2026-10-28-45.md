# Batch 45 (aggiemap): controls a keyboard cannot reach or activate - read only

Done about 11:10 AM Central, 28 October 2026. Nothing fixed, nothing pushed but this report. One issue filed: [#2535](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/2535) (Task, label `bug`; Priority **Medium** is the director's to set - I did not touch the project fields).

## Method

`origin/development` at `54b8dd04f`, exported with `git archive` to a temp folder, then a Node script read every `.html` file (404) and every inline `template:` in non-spec `.ts` files under `libs` and `apps`. It parsed each opening tag and kept those with `(click)`, `(mouseenter/over/leave/out)`, `(dblclick)`, `(mousedown/up)`, `(pointerdown)` or an interactive `role`, then I read the context of every one that lacked a key handler. I separately counted `routerLink` on non-anchors, `@HostListener`/`host:` clicks, and looked for `tab-index`-style typos and imperative `onclick` / `addEventListener` (none in app code; Esri `view.on('click')` is map clicks, with `viewfinder` giving the keyboard route). The script and its JSON stay in `%TEMP%` and are not committed.

`tamuGiscActivate` is **not on `development`** (it is in PR 2534's branch `fork/refactor/2047-shared-directions-button`), so "fixable by it" below assumes that merges. It is `role="button"`, `tabindex="0"`, click/Enter/Space to an `output()`; it does not suit `routerLink`.

## What lint sees

- **The rules come from `nx.configs['flat/angular-template']`** and are on everywhere except **six projects that turn them off** (`apps/geoservices-angular`, `apps/mailroom-angular`, `libs/geoservices/{ngx,data-access}`, `libs/mailroom/{ngx,data-access}`: `click-events-have-key-events`, `interactive-supports-focus`, `mouse-events-have-key-events`, `role-has-required-aria`, `alt-text`, `label-has-associated-control`, `no-autofocus`). Everything found in Geoservices and Mailroom is therefore silent, not clean.
- **Suppressions elsewhere: 7, all justified in their comments** (autocomplete x2, copy, search x2, search-mobile x2). Each is a wrapper that forwards keys to children or a mouse shortcut with a keyboard twin. I checked `copy`, `search` and `modal-host` and agree.
- **Rule blind spots (the more useful finding):**
  1. `@HostListener('click')` / `host: {'(click)'}` is invisible: 13 places, 11 with no key handling (below).
  2. `(click)` on a custom element (`<tamu-gisc-sidebar-tab (click)>`, `<tamu-gisc-step-toggle (click)>`) is not checked: the rule only knows native elements.
  3. **`routerLink` on a non-anchor** is not checked: 48 elements.
  4. `(mousedown)` / `(pointerdown)` are not checked (`mouse-events-have-key-events` covers only over/out): 3 `<i>` in search.
  5. `click-events-have-key-events` passes on **any** `keydown/keyup/keypress`, wrong key or no tabindex included; 11 elements handle Enter only (Space neither activates nor stops scrolling).
  6. Misspelt attributes: `tab-index="0"` in `dining.component.html:8` passes everything.
  7. Elements with `role` + `tabindex` + keys are all fine and make up the bulk (about 120 of 131 keyed hits), so the 2046 work holds where the rules reach.

## Counts

Of those 81: **34 are `<tamu-gisc-button>`** and **13 are `<td (click)="$event.stopPropagation()">`** (noise, below), leaving **34 real or arguable**. ## Judgement: which actually matter

**Real, in this order of consequence:**

1. **Desktop sidebar tab** (`tamu-gisc-sidebar-tab`). It is the AggieMap desktop navigation: a keyboard user tabs to it, hears "button", and nothing happens. Same bug class as #2047 and more visible. One component.
2. **2D/3D toggle** and the **hamburger / mobile tile navigation**: the only control for each.
3. **`routerLink` on divs**, in particular the public GIS Day speaker cards and competition buttons, the AggieMap trip-planner Options link, and the Geoservices menu (the whole app navigation).
4. **Search icons** (`mousedown` only), **accordion headers**, **tooltips**.
5. The dining `tab-index` typo, one character.

**Noise or low value:** everything in the Noise table, the 11 Enter-only handlers (users can still Tab and press Enter; Space is a polish), and the admin-only list rows (administrators, but still real if the admin tools must meet the same bar).

**Geoservices and Mailroom:** most of the Group A rows are there only because the rules are off. If either app is staying (Geoservices response viewer removal is #1896), turning the rules on is the cheapest way to find the rest.

## What I would suggest the next batch be (director's call)

1. Fix the sidebar tab, the perspective toggle and the hamburger/tile family together (they share a `host:` pattern) with a unit test per component that fails first.
2. `<a routerLink>` swap for the AggieMap and TS Events cases, then GIS Day.
3. A lint rule or a small custom check for `routerLink` / `(mousedown)` on non-focusable elements, since the shipped rules cannot see them, then re-enable the rules in Mailroom/Geoservices with a baseline.
