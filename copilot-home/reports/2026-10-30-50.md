## Cause

The gallery asked for `GET /user-submissions/posters`. The controller has `GET user-submissions/:guid` behind `JwtGuard`, so `posters` was read as a guid and every signed-out visitor got a 401 (reproduced locally on `development` code: `{"message":"Unauthorized","statusCode":401}`). The page then showed only its heading and vote button.

## What changed

- **API:** a public `GET user-submissions/posters?season=<guid>`, declared before `:guid` and with no guard. A `season` that is not a GUID is a 400; none means the active season. It returns `PosterDto { title, authors: string[], link, year }` and nothing else: no emails, student ids, `accountGuid`, `guid` or reviewer `message`. A missing season or no active season returns `[]`. Ordered by title.
- **Gallery:** a season list (the active season first), the authors in place of the abstract, "No posters yet." for an empty season and "The posters could not be loaded." for a failure. No new CSS.
- `/competitions/posters/gallery` added to the e2e public route table.
- Release note `docs/releases/unreleased/2496-poster-gallery.md`; screenshots in `docs/screenshots/2496-poster-gallery/` (`before-gallery.png`, `after-gallery.png` for the empty 2026 season, `after-gallery-2025.png`).

## Things to know

- **"Accepted" is `acceptance = true`, not `reviewed and acceptance`.** I first used both, to match the admin's Accepted label (`SubmissionReviewStatusPipe`). In the scrubbed copy, all 16 posters of 2025 have `reviewed = 0, acceptance = 1`, so that filter would have kept the gallery empty. The pipe calls those "Unknown". Rejected and pending ones all have `acceptance = 0`, so none leaks. Question below.
- The scrubbed copy has no participants, so authors are empty in the screenshots and each card shows a blank line. The component test covers authors.
- The 2026 season has no posters in the local copy, so the page opens on "No posters yet." until some are accepted.
- The capture script could not be used as it is: this worktree has no install, and the Playwright image version differs from the one my borrowed `node_modules` held. I ran the image directly with a throwaway script (deleted) that proxied the page's calls to `localhost:3333`. Nothing from it is in the branch.

## Questions for the director (gisday)

1. Should the gallery require `reviewed` as well as `acceptance`? Options: (a) `acceptance` only, as now; (b) both, which shows nothing for 2025 until someone marks the posters reviewed, or a migration does. **Recommendation: (a)**, since the data already carries acceptance without review.
2. Should cards show the abstract again? The route leaves it out so that a poster's public data stays minimal. Options: (a) keep it out; (b) add `abstract` to `PosterDto`. **Recommendation: (a)** until someone wants it.
