## What changed (21 files, all under `test/smoke/aggiemap/` plus the smoke Playwright config)

`gis-hosts.ts` is now the one place that answers these questions:

| Question | Before | Now |
| --- | --- | --- |
| Is this hostname a development host? | `isDevelopmentHostname` | unchanged |
| Is this URL's host a development host (a request, or the environment)? | `isDevelopmentHostRequest` **and** `environmentIsDevelopment`, with identical bodies | one function, `isDevelopmentUrl` |
| Which GIS host is this environment on? | `hostname.includes('dev') ? ... : ...` typed in 4 specs | `gisHostFor(baseUrl)` |
| What is the environment under test? | typed in 15 places, 6 stripped a trailing slash, 9 did not | `smokeBaseUrl()` (trims, strips every trailing slash, production when unset or blank) |

- **`environmentIsDevelopment` did not survive.** It was byte-for-byte the same function as `isDevelopmentHostRequest`, so the suite had three names for two questions. Both are now `isDevelopmentUrl`; its comment keeps the "one-directional on purpose" explanation.
- The four specs (`portal-renderers`, `search-sources`, `service-metadata`, `services`) call `gisHostFor`. Every spec, `global-setup.ts`, `development-only.ts`, `directions.ts` and `playwright.aggiemap-smoke.config.ts` call `smokeBaseUrl()`, so the `baseURL` fixture is normalised too (`services.spec.ts` builds `${baseURL}${thumbnail}`). The nine redundant `const normalised = BASE_URL.replace(...)` lines are gone.
- README: the variable's row says a trailing slash is ignored.
- Not touched, as asked: the other nine findings, and the repeated `environments.json` lookup in each spec.

## Found on the way (not acted on)

- **The application itself uses the substring test.** `readsDevelopmentGisServer` in `libs/aggiemap/ngx/common/src/lib/connections.ts` is `address.hostname.includes('dev')`, plus `actingAsProduction`. So the four specs' `includes('dev')` was copying the app, and the regex in `gis-hosts.ts` now differs from the app for a hostname such as `devices...`. No real environment is affected, but the comment in `gis-hosts.ts` ("a substring test would [match devices.example.com]") describes the app too. Also `gisHostFor` ignores the `actingAsProduction` query option the app honours; no spec sets it for the host choice.
- The smoke runs are slow and flaky when 14 specs share one container (about 45 minutes on development), which is why the failure sets differ between identical runs.
