## Why it no longer shows, and why the hypothesis was off

- **The issue's own layer is gone.** `indoor-track-parking-team-bus` was removed in #2468 (the one-schema change); the service has no layer 5 and the map no longer declares it.
- **The template is dead code.** `{attributes.sp_sh_notes}` still sits in `IndoorTrackParkingColdLayerSources`, but the map draws `IndoorTrackParking_DevelopmentLayerSources`, which rebuilds every source with `athleticsDevelopmentSource()`: `popupData` is `name: 'attributes.name'`, `description: 'attributes.description'`. The service's building layer has no `sp_sh_notes` column at all (fields: `name`, `description`, `notes`, ...).
- **It was never the selection layer.** `TemplateRenderer` keeps a placeholder when its attribute is missing (`nullishReplacement` unset), so a template naming a column the layer lacks prints itself - from a click as well as a link. The selection-layer path is already handled: `PopupService.asOwnLayerFeature` (#1970) gives the popup the source layer's title, component and data, and `popup.service.spec.ts` has four tests for it. `main.definitions.ts` still lists `popupComponent: BUILDINGS.popupComponent` on `selection-layer`, but it is only the fallback for a building search result, which names no layer. Changing it would break that.

So there was nothing to carry through the selection, and a template guard would only hide a wrong definition. I wrote no fix and no test.
