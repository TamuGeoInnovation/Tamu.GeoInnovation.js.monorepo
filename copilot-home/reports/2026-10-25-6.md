## Findings

1. **None that breaks anything today.** The only chart in an app is the signage bar chart (`tamu-gisc-bar-chart`, `map.module.ts`); `summary.component.ts`
   in feature-selector extends `BaseChartComponent` but sets no options. No `[options]`, `title`, `colorschemes`, `yAxes`, `tooltips` or `legend`
   in v2 form is used anywhere.
2. **Registration is complete** for each type: bar `BarController, BarElement, CategoryScale, LinearScale`; line `CategoryScale, Filler, LineController,
   LineElement, LinearScale, PointElement`; pie and doughnut `ArcElement` plus their controller; the container registers `Legend, Title, Tooltip`.
   Nothing is missing a scale, legend, tooltip or title. (`Filler` is registered but never used; see 4.)
3. **Colour rules match the plugin's** for what these charts use: Paired12 default, line/radar/scatter get border and points at full colour and fill/point
   fill at alpha 0.5 (`rgba(r, g, b, 0.5)`, same format as `helpers.color().alpha().rgbString()`), pie/doughnut/polarArea one colour per slice, bar its
   fill, and the caller's colour is kept. Differences from the plugin, all latent:
   - The plugin set colours on every update and **removed them after**; the branch writes them into the dataset once and keeps them. If a caller reuses one
     dataset object whose pie data later has more slices, the colour array stays at the old length and the extra slices fall back to chart.js's default.
     Only matters when a source supplies its own `datasets` (`'datasets' in curr` in `base.component.ts`); built datasets are new each emission.
   - The plugin chose by `dataset.type || chart.config.type` (mixed charts); the branch uses the chart type only.
   - `scheme`, `fillAlpha`, `reverse`, `override`, `custom` are gone (documented in the code comment; none used).
4. **Line charts will look different from v2 (not used today).** chart.js 4 defaults `fill: false` (confirmed in `dist/chart.js`) and `tension: 0`; v2
   drew a filled area with curved (0.4) lines. The 0.5-alpha `backgroundColor` is now only the point fill, and `Filler` does nothing. If a line chart is
   ever used, `LineChartConfiguration` should set `fill: true` and `tension: 0.4` on its datasets to keep the old look.
5. **Visible change in the signage bar chart (screenshots):** the y-axis now starts at 0 (before, it started at 3, which exaggerated the bars). That is v4's
   `beginAtZero: true` for bars and is the better chart. The x-axis labels are cut off at the bottom of both screenshots, so I cannot tell from them whether
   they render after; the chart is taller in "after" and the crop is the same.
6. **`moment` and the plugin are gone from the code and the lock.** On `development` nothing imports `moment` or `chartjs-plugin-colorschemes`, and no
   package in the lock depends on `moment`, `chartjs-color`, `chartjs-color-string` or `@types/chart.js`.
7. **The lock beyond those packages: nothing.** At the merge base the only differences are: removed `@types/chart.js@2.9.41`, `chartjs-color@2.4.1`,
   `chartjs-color-string@0.6.0`, `chartjs-color/node_modules/color-convert@1.9.3` and `color-name@1.1.3`, `chartjs-plugin-colorschemes@0.4.0`,
   `moment@2.31.0`; `chart.js` 2.9.4 to 4.5.1; added `@kurkle/color@0.3.4` (its only dependency); and `color-name@1.1.4` now has `dev: true`.
   I checked that last flag: from the root's `dependencies`, `color-name` is no longer reachable (only through `nx` and `color-convert`/`color-string`
   under dev tooling), and no package anywhere is production-reachable yet marked `dev`. `chart.js@4.5.1` declares `engines: { pnpm: ">=8" }`, which npm ignores.
8. **14-day rule:** `chart.js@4.5.1` was published 13 October 2025 (a year old), `@kurkle/color@0.3.4` 19 November 2024. `4.6.1` was published 22 October 2026
   (3 days before the merge), so `~4.5.1` is right; `~` keeps 4.5.x patches (none newer exist) and will not take 4.6.
