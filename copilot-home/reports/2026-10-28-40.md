## What changed

- **Markup:** the name is first in the DOM on both pages and no style reorders anything. `map-columns.component.html`: a pictured entry is `label, img`; a glyph entry is still `icon, label` (it branches on `app.thumbnail`). `all-maps.component.html`: `label, img`.
- **`discover-shared.scss`:** `.map-entry--pictured` stays `flex-direction: column` (gap 0.5rem). `.map-entry-item > .map-entry--pictured` margin-bottom is **2rem at every width** (was 1rem on a phone only, and 0 on desktop).
- **`all-maps.component.scss`:** `.campus-tile` is now `display: flex; flex-direction: column; gap: 0` (it was a block; the shared rule's gap would add to the label's own margin). The label's margin moves from top to bottom (0.5rem). At max-width 768px: tile margin-bottom 1rem, and `.campus-maps-section .applications-list` gap 2rem. On desktop the grid gap is unchanged at 1rem.
- **Spacing scale:** `libs/sass/_spacing.scss` has whole-rem steps only, so 2rem is `trailer-2` and 1rem `trailer-1`. Where I looked: that file, the two templates, `map-columns.component.scss`, and the cascade between the shared and component stylesheets (the component's `.campus-tile` rule wins over the shared pictured rule, which is why the tile was a block before).
- **The `aria-label`:** the tile's `aria-label` ("Open the X map") replaces the link's content for assistive technology, so the name is announced once, as part of that phrase, and it still makes sense with the name first. I left it alone. On `/all-maps/campus` the link has no aria-label, so a reader hears the name and then the picture's alt ("X map"), the name twice; see question 2.
