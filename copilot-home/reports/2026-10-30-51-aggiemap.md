## What changed

- `connections.ts`: new `developmentRoutingBaseUrl` = `https://gis-dev.it.tamu.edu/arcgis/rest/services/RoutingProPublish`, pinned to the development GIS server like `busRoutesUrl` (any host, production's `routingBaseUrl` unchanged).
- `trip-planner-connection.service.ts`: where `TestingService.isTesting` is true (dev or localhost, not `?as=production`) the planner connects straight to `RoutingProPublish/Map` and skips the `Routing` folder discovery. Production still discovers the (empty) `Routing` folder and never requests the new network. It also reads `supportedTravelModes` from `Route?f=json`; if that cannot be read, no mode is offered. Also fixed: each network kept its own `baseServiceUrl` (it was always replaced with the one service URL).
- `trip-planner-travel-modes.ts` (new) + `trip-planner.service.ts`: **travel modes are matched by name, not number.** The planner hard-coded its modes 1-8 as the network's ids. On the new network id 1 is Bike, so a walking trip would have been solved as a bike ride with no error. Now a mode is offered only if the network has it by name, and at solve time the network's own travel mode is sent while the planner keeps its own mode numbers for results, URL and analytics.
- Smoke: `RoutingProPublish` added to `DEVELOPMENT_ONLY_SERVICES` (page `/map/d/trip`); two no-browser checks in `directions.spec.ts` that fail if the network's mode list changes (offered set must be exactly Walk, Walk_ADA, Drive x2, Bus, Bike = planner modes 1,2,3,5,7,8) or if any listed mode stops solving.
- Release note `docs/releases/unreleased/659-routing-new-network.md` with the *What to test on dev* row; screenshots in `docs/screenshots/659-routing-new-network/`.

## The name convention (conclusion)

`^(Routing/)\d{8}[A|B]$` and `^(Routing/)\d{8}$`. The A/B half is dormant (`_override` defaults to true, nothing calls `setOverride`, the "Use A/B Networks" checkbox is disabled). The live half is "newest dated network in the `Routing` folder wins", which is the republish mechanism. `RoutingProPublish` is neither dated nor in `Routing`, so discovery cannot find it. I did **not** widen the regex; the new network is pinned for development only. On dev, `Routing` holds only `20220119` and `ChrisRoutingTest`; `Routing_20261026` answers "Token Required"; production's `Routing` folder is empty.

## What the new network offers vs. the planner today

New network (5): Bike, Bus, Drive (AUTOMOBILE), Walk, Walk_ADA (WALK). Old network (9): Walk, Walk_ADA, Drive, Drive_ADA, Bus, Bus ADA, Bike, Visitor_Drive, Visitor_Drive_ADA. Planner modes: 1 walk, 2 accessible walk, 3 drive with parking pass, 4 accessible drive, 5 bus, 6 accessible bus, 7 bike, 8 visitor drive.

Differs: **4 (accessible drive) and 6 (accessible bus) are not offered** (the toggle is disabled via the existing restriction logic). **3 and 8 both use the single Drive mode**, so the visitor/permit distinction is lost on the network side (the parking-lot stop for permit holders is still added by the planner). Bike and Walk times came out about the same (35 min) for this trip.
