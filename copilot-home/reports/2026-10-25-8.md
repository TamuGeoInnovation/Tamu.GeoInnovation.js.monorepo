## Findings (not changed; the batch said permissions, defaults and pins only)

1. **Likely, small: no Dependabot ecosystem for `github-actions`.** `.github/dependabot.yml` has `npm` only (I read the first 30 lines). Pinned SHAs will now never move
   without one. Adding `package-ecosystem: github-actions` (weekly, the same 7-day cooldown) keeps the pins current. Suggest as a next batch.
2. **Certain, low: script injection in two `run:` blocks.** `main.yml` line 36-38 puts `${{ github.ref_name }}` and `${{ github.head_ref }}` straight into bash
   (`actionlint` flags it), and `build.yml` line 52 does the same with `github.ref_name`. A branch name may contain `$(...)` or backticks, so a branch called
   `x$(curl ...)` runs that command. For a fork pull request the token is now read-only and no secret exists, so the damage is bounded; on a push to this repository only
   a person with write access can make such a branch. Fix: pass the names through `env:` and use `"$BRANCH"`. I did not change it (outside the batch).
3. **Question (admin only): the repository's default workflow token setting** (Settings > Actions > General > Workflow permissions) and "Require approval for
   workflows from outside collaborators". I could not see either. With the branch, the default stops mattering for the files that had no block.
4. **Question (admin only):** whether `GITHUB_TOKEN` pushes to ghcr.io are limited to the repository (package settings > Manage Actions access).

## Azure Pipelines (what the files say; I could not see the project's settings)

- **Secrets:** the build job copies a secure file (`app_configs.zip`, "Copy secrets") **except** when `System.PullRequest.IsFork` is `True` (#2216): fork builds use the repository's
  environment files. The condition is on three steps in `templates/jobs/build.yml` (lines 32, 40, 48), which I checked.
- **Tag stage:** runs only for non-PR builds or PRs from this repository; fork builds have no tag access by design.
- **Token use:** `deltaConfigure.yml` passes `System.AccessToken` as `AZURE_DEVOPS_EXT_PAT` to `az pipelines build list` only. No other use in the templates.
- **Checkout:** `templates/tasks/checkoutFromMirror.yml` fetches from `Build.Repository.Uri` and checks out `Build.SourceVersion`, with a read-only mirror. `checkout: none` plus this step means no persisted credentials in `.git/config`.
- **Lab agent isolation** (`tools/build-agent/`): `--cap-drop ALL` (agent: `--cap-add SETUID SETGID KILL`), `--security-opt no-new-privileges`, a memory/cpu/pids limit, a private network
  behind a proxy that refuses every private address, and a token held where the job cannot read it (`start.sh` starts as root only to do that). Everything else I read was consistent with the README.
- **Questions for an admin:** whether Azure DevOps "Make secrets available to builds of forks" is off, whether fork builds need comment-approval, and the scope and expiry of the agent registration token. None of these are in a file.
