# Batch 56 - aggiemap: does the rebuilt date-time picker still work in the trip planner?

30 October 2026. Read only on `fix/2583-date-time-picker` (`75f2ae7b1`, on the fork); I did not push to it or open anything on it. Compared with `development` `21e69426e` in the same session.

## Verdict

**Yes, the rebuild does not break the trip planner, and nothing differs because of it.** Every observation below is identical on `development` and on the branch, except the picker's own fields. It should not be held for this.

**But the trip planner's Leave at is already unusable on `development`, for two reasons that have nothing to do with #2583.** Filed as **#2608** (Type Bug, project Todo, no Priority). This is a pre-existing fault, not a block on that pull request.

## What I did

The branch and `development` each served by `nx serve aggiemap-angular` from a Docker volume (node 24.22.1, no `--poll`), reached as `aggiemap-dev` so it counts as a development host (routing against dev); headless Chromium (Playwright 1.64.1) in Central time with the origin treated as secure. I read the planner's own state (`TravelOptions`) through Angular's debug API, not the panel's label.

## Findings, by the five checks

1. **What reaches `requested_time`.** Through a shared link (`&time=leave&at=2026-11-05T21:30:00.000Z`) the planner holds exactly `2026-11-05T21:30:00.000Z` (Thu 3:30 PM Central), seconds 0, on both. The value contract is unchanged: a `Date`, and `DateTimePickerChange` is still the same exported class, so the planner's `instanceof` test passes (its handler ran on every change).
2. **Typing.** Not testable as shipped, on either (below). With the picker given a proper `Date` (a local scratch edit I made to the planner and reverted, not pushed):
   - **`development` (old picker):** the first keystroke commits and closes the picker; the planner took **3:30 AM** (the #2583 bug, reproduced in the planner).
   - **Branch:** typing `11/12/2026` changed nothing until Enter (then 12 Nov 3:30 PM); typing `3:30 PM` ended at **Thu 12 Nov 2026 3:30 PM**, seconds 0. So typing "30" now behaves as it does in the Designer, with one caveat: the time field commits a **partial** value on the way (`3:3` is read as 3:03 AM before `30` arrives). It ends right, and the planner does not re-solve on a time change, so no harm here; but the picker's own comment says a time takes effect "when it is complete", and `3:3` is not.
3. **Clear.** Choosing Leave now sets `time_mode` to `now`, `requested_time` to `null`, and removes the picker, on both: back to leaving now, not an invalid time. (The address keeps the stale `&time=leave&at=...`, on both.)
4. **Solving with a Leave at.** Walking returns a route; bike, car and bus answer "No route from location", and the panel stays on "Calculating route. Please wait..." for all 90 s I waited, **on both**: that is the known no-network state (#2580's reason for disabling car and bus, and #2592), not the picker. Also, **nothing sends the time to the solve**: the solve requests carry `startTimeIsUTC=true` and no `startTime`; the time feeds only the bus switching and the shared link's `at`.
5. **Compared with `development`.** Done for each check above; all equal.

## The pre-existing fault (#2608)

On both versions, **Leave at cannot be used to choose a time**:
- Choosing "Leave at" in the menu draws no picker: the option's value is `depart`, the type and template say `leave`.
- A link with `time=leave` draws the picker **blank** (trigger 0 × 0 px): the template hands it a number of milliseconds where it takes a `Date`, so it reads as empty. After any choice it blanks again.
- **What that means for the rebuild:** the new picker takes its date from its value, so with the blank value, typing a date then a time ends at **today** at that time (12 Nov lost, 30 Oct kept). Giving it a Date (scratch edit, reverted) fixed that completely. The old picker could not be opened at all, so this is not a regression; it will matter the day someone fixes the binding, which is why #2608 says to fix them together.
