## Cause

Two changes in `basemaps.definition.ts` broke the spec's text parser, which reads that file with a regex:
1. `AggiemapRasterBasemap` is now typed `BaseMapProperties & { id: string }` (#1700 era), and the regex wanted exactly `: BaseMapProperties = {`, so the block was skipped.
2. Its URL is no longer written out: it is `TAMU_CAMPUS_BASEMAP_URL`, declared in `libs/common/datasets/geographic/src/lib/campus/campus-basemap.ts`, so even a matched block holds no URL.

The view limit still depends on the raster cache (`AGGIEMAP_BASEMAP_MAX_SCALE = 282`, used by both map components), so the check stays; it is not removed.

## Fix

The spec reads `TAMU_CAMPUS_BASEMAP_URL` from `campus-basemap.ts`, the regex accepts the `& { ... }` form, and a block that uses the constant gets that URL. Side effect, wanted: the raster basemap
now also gets its own "is public and answering" test (`AggiemapRasterBasemap: FCOR/TAMU_Basemap_20261008/MapServer`), which had silently gone missing.
