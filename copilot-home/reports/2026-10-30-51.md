# Batch 51 report: deepmerge, the last vulnerability (read only)

Written 30 October 2026, copilot-home. Nothing pushed except this report; no branch, nothing installed in the repository.
Evidence: `origin/development` sources (`git show`), and `npm view` / the npm downloads API read on 30 October 2026.

## 1. Our imports

`deepmerge` is a production dependency (`package.json` `^4.2.2`). There are **three** call sites in two files:

| File | Call | What is merged |
| --- | --- | --- |
| `libs/maps/esri/.../layer-sources/layer-sources.service.ts` | `deepmerge(source, override)` | a layer source from `LayerSource[]` and a per-layer `LayerSourceOverrides[layerId]` |
| `libs/ts/events/ngx/.../event/event.service.ts` | `deepmerge(source, correspondingOption.propOverrides)` | a layer source and `conversions[].propOverrides` |
| same file | `Object.assign(child, deepmerge(child, conversion.propOverrides))` | a child layer and `propOverrides` |

Reachability: the left side is a layer source and the right side is `propOverrides` / overrides, both parsed JSON from
layer-source configuration and event/accommodation configuration served by our own services (the layer sources and the
Events API). Nobody types into these merges; the data is authored by us and fetched at runtime. `JSON.parse` creates
`__proto__` as an own key, which is exactly the input `mergeObject()` mishandles, so the exposure is real only if that
JSON is attacker-controlled (a compromised or spoofed service response, or a third-party layer source). Exploitation
is therefore low likelihood but not zero. The advisory is rated low; the effect would be a polluted
`Object.prototype` in the browser tab, not on a server.

**Replacement options**

- A. **Small shared helper** in a new or existing `libs/common/utils/*` library (for example `libs/common/utils/collection`
  already exists; check first for a merge there; I found none): a ~25-line recursive merge that skips `__proto__`,
  `constructor` and `prototype`, clones plain objects, and replaces arrays (deepmerge's default is to concatenate arrays,
  so the helper must keep concatenation to preserve behaviour). Cost: we own the code; needs a spec that fails first
  (a `JSON.parse('{"__proto__":{"x":1}}')` merge must leave `({}).x` undefined) plus array-concat and nested-merge tests.
  Removes the dependency from our code entirely.
- B. **A maintained library.** `deepmerge-ts` 8.0.2 (21 Aug 2026; about 30.2 million weekly downloads; zero dependencies;
  TypeScript native; named export `deepmerge`; ignores `__proto__`; array default is concatenation, like deepmerge). Not
  API-identical (named export, different types), so the three call sites change but the change is mechanical.
  `@fastify/deepmerge` 3.2.4 (22 Oct 2026, about 10.2 million weekly) is also maintained and has options for array and
  prototype handling, but takes a factory call. Do not use `es-toolkit` merge for this; it is a large dependency.
- C. `@stackline/deepmerge` 1.1.0 (see section 2): drop-in but new and tiny.

## 2. The dev-only paths

Newest versions, each older than 7 days (published 18 Sept 2026 or 3 April 2025 for jest and fork-ts; `@nx/*` 24.0.2
published 29 October 2026, so **under 7 days**; 24.0.0 is what we have):

| Package | Newest | `deepmerge`? |
| --- | --- | --- |
| `jest-config` / `jest` | 30.5.2 (18 Sept 2026) = what we have | **still `^4.3.1`** |
| `fork-ts-checker-webpack-plugin` | 9.1.0 (3 Apr 2025), `latest` | **still `^4.2.2`**; only prereleases (`alpha 7.0.0-alpha.16`, `next 1.0.0-alpha.10`) are older lines |
| `@nx/webpack` 24.0.2 | pulls `fork-ts-checker-webpack-plugin` 9.1.0 | via fork-ts-checker |
| `@nx/jest` 24.0.2 | pulls `jest-config ^30` | via jest-config |
| `@nx/js` 24.0.2 | no direct deepmerge | no |

**No upstream has dropped `deepmerge`, and none has a pending fix.** `jest` `next` is `30.0.0-rc.1`, older than 30.5.2,
so there is no jest 31 to take. Upgrading anything will not clear the 13 dev findings.

**Overrides.** `package.json` already has an `overrides` block (`nx`, `@azure/identity`, `@angular/build`, ...), so an
entry `"deepmerge": "npm:<fork>@<version>"` is possible. Candidates found by `npm search deepmerge`:

- `@stackline/deepmerge` 1.1.0 (modified 13 Oct 2026, repository `alexandroit/stackline-deepmerge`, MIT, zero
  dependencies, one maintainer): describes itself as a "drop-in replacement for deepmerge 4" with the prototype-pollution
  fix, and exports both ESM and CJS. About 15,400 weekly downloads; the package was created 16 Aug 2026. Young and
  single-maintainer: I would not put it into a build tool chain without reading it. I have **not** installed it or run
  jest/webpack against it.
- `@bundled-es-modules/deepmerge` 4.3.2 is a re-bundle of the vulnerable code, no fix.
- `deepmerge-ts`, `@fastify/deepmerge` are not API-compatible with `require('deepmerge')` (jest-config calls it as a
  default-export function), so they cannot serve as an override target.

An override is safe only if the fork keeps the CommonJS default export `module.exports = deepmerge` (jest-config and
fork-ts-checker both `require` it). The package's CJS entry is `dist/index.cjs`; whether it sets `module.exports` or only
a named export is unverified.

## 3. Recommendation

`npm audit` cannot reach zero by upgrading: **no fixed `deepmerge` exists, and every dev path still depends on 4.3.1.**

Questions for the director (security)

1. **Production import.** Options: (A) our own guarded helper in `libs/common/utils/*`; (B) `deepmerge-ts` 8.0.2;
   (C) leave it. **Recommend B for the three call sites** (mature, 30 M weekly, zero deps, same array default), with a
   failing-first test using a `__proto__` payload. It drops `deepmerge` from `package.json` and the production finding goes.
2. **Dev-only findings (13).** Options: (A) override `deepmerge` to `@stackline/deepmerge` 1.1.0, after a trial branch
   running `jest` and one webpack build in Docker; (B) accept the 13 low findings with a documented reason (dev-time only,
   input is our own config files, no fix exists) and re-check when jest or fork-ts-checker release; (C) a `patch-package`
   patch of `node_modules/deepmerge/dist/cjs.js` adding the three-key guard (a patch we own, no new publisher).
   **Recommend C over A** if the goal of zero is firm, since it adds no unvetted publisher to the supply chain
   (the same concern as #2334), and B if not. Say which and I will do a branch.
3. Re-check after the `@nx/*` 24.0.2 packages are 7 days old (6 November): they are not going to change this finding, but
   the 24.0.x update is due anyway.

Not verified: that `npm audit` still shows exactly 14 findings (I did not install). That the three-key guard in a helper
preserves deepmerge's array-concat behaviour (needs the test).
