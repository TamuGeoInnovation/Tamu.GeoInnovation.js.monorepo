## The diagnosis in #2458 is not quite what is on the page

I measured rather than trusting the table (live DOM, dev server in Docker, Playwright `v1.64.1-noble`, 375 px and 1280 px, images loaded first):

- Name sits **8 px** below its own picture (`.campus-tile-label` `margin-top: 0.5rem`; the `gap: 0.5rem` of `.map-entry--pictured` does not apply, because `.campus-tile` sets `display: block` after it).
- The name sits **12 px** above what follows it, which is the card's **description**, not the previous card (`.campus-tile` `margin-bottom: 0.75rem`).
- Card to card is 16 px, and the next card's picture is a further 16 px of padding down, so the name is 160+ px from any other card's picture.

So the near-equal pair is picture-above (8) against description-below (12). That is the ambiguity, and the fix widens the second: **8 above, 16 below** on a phone. The batch said to judge by looking; the 8 px above already looks tight and reducing it made no sense (there is no spacing step smaller than 1rem to use), so I left it.

## Where I looked (Reuse before building)

- `libs/sass/_spacing.scss`: `leader-1..9`, `trailer-1..9`, `pre-`, `post-`, all whole rems, **no breakpoint-scoped variants**. `trailer-1` is exactly 1rem, so the value written is that step's.
- `libs/sass/_variables.scss`, `_mixins.scss`: colours, fonts, vendor-prefix mixins; no spacing scale or breakpoint variable.
- `apps/aggiemap-angular/src/styles.scss`: imports the spacing utilities; no spacing tokens.
- `discover-shared.scss`: `map-entry--pictured`, `map-entry-thumbnail`, `applications-list`, `application-card`; its own `@media (max-width: 768px)` blocks use a literal width, so I followed that.

**Why not the `trailer-1` class itself:** a utility class cannot be limited to a breakpoint, and putting it on the tile would have moved the desktop grid by 4 px, which the batch said must not move. Writing the same 1rem inside the existing breakpoint is the smallest change that respects both. **Why not `discover-shared.scss` (as the issue suggests):** the 0.75rem lives in `.campus-tile`, which is in `all-maps.component.scss`; `map-entry--pictured` carries no margin to change. The other All Maps sections (kiosk, events) use `application-title` headings, not a picture-and-name link, so the stacking problem is not there.
