# 12 October 2026

**The suite cleared this release on dev before production**: 446 passed, 0 failed, 1 flaky, 14 skipped of
461, in 28.9 minutes (about 7:03 to 7:32 AM Central on 12 October, release scope, 6 workers). Azure Release-463
deployed build 20261012.5, from `79cadfccc`, to dev; the commit is tagged `dev-2026-10-12`. The flaky test
was the basemap at the deepest zoom, which ran out of time twice at the start of the run while another
suite shared the machine; run alone against dev afterwards it passed three times out of three, in 45 seconds.

**This is the third build tested for this release, and the first to ship.** Build 20261011.3 (`df1768ab9`,
`dev-2026-10-11`) passed on dev on 11 October; checking it by hand found that a tent inside a highlighted
Tailgating zone opened an empty popup ([#1614](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1614)), so production was held. Build 20261011.10 (`c3a7945a4`,
`dev-2026-10-11-2`) carried the fix and passed with 446 and none failed; these notes were first written for
it. It was not released either: by the next morning `development` held a good deal more, and the
maintainer chose to test and release that instead of shipping a build already a day behind.

**Most of the release is invisible, and it is large.** Since the [8 October release](2026-10-08.md), the
Angular code lost its last NgModules and its constructor parameters:

- **No Angular NgModule is left** outside the OIDC admin and signage apps ([#1569](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1569)). About 150 routing
  modules became exported route arrays, the modules that only carried providers became self-providing
  services, and every app now starts with `provideRouter`.
- **Inputs, outputs and queries are signals** ([#1455](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1455)): 216 of 287 inputs, 40 of 44 outputs and 31 of 40
  view and content queries, by Angular's own migrations. What they left is listed in [#1657](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1657).
- **70 components use OnPush**, Angular 22's default: 12 in the shared UI kits and 58 in geoservices
  ([#1669](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1669)). They are checked when something they show changes, not after every event anywhere.
- **Dependencies are injected with `inject()`** ([#1453](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1453)): 345 files with constructor parameters became 7.

Each step was checked the same way before merging: the full affected lint, test and build; the smoke suite
against a local server on the branch (429 or 430 passed each time, the one failure being the build banner,
which fails on any local server); and every other app served and opened in a browser.

**GIS Day is not part of what was deployed.** Its code changed with everyone else's, but its site deploys
separately and its production build is still Angular 15. Its first deploy since then has its own test pass
([#1611](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1611)).

## Summary

- **The old standalone Ring Day app's code is removed** ([#1236](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1236)). Ring Day is
  served by the event map at `/events/ring-day`; the old app at `/ringday/` was a second copy with its
  own dates and its own notice. Its projects and library are gone, so Azure no longer builds it, and the
  dev-only Experimental Applications list no longer links it. **The deployed `/ringday/` folder on dev and
  production is still there**: deleting it, or redirecting `/ringday/` to `/events/ring-day`, is a step
  on the servers for the maintainer.
- **Football parking lot status reaches the map within a minute, without a reload** ([#1587](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1587)).
  Staff change a lot's class during game day, to Lot Closed for example, by editing the service, and
  visitors had to reload the page to see it. The Football Parking Lots layer, on every personal vehicle
  map and the RV map, now checks its service every minute and redraws what changed. Only that layer
  polls; the others do not change during a game.
- **GIS Day: the competition app's old login page is removed** ([#1608](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1608)). Opening
  `/app/login` threw an error and showed an empty page ([before](../screenshots/gisday-competitions-login/before-production.png)),
  on production too: the page signed in through the retired site login and depended on a service nothing
  provided. GIS Day signs in through Auth0 only, so the page, its service and its guard are gone, and an
  old `/app/login` link now leads to the competition app like any other address
  ([after](../screenshots/gisday-competitions-login/after-local.png)).
- **Tailgating: a tent inside a highlighted zone opens its own popup** ([#1614](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1614)). A link to a
  zone, opened in a tab that already had the map open, drew the yellow selection highlight over the zone
  and its tents, and a click on a tent then opened an empty popup reading ", TX"
  ([before](../screenshots/tailgating-tent-under-highlight/before-dev.png)). The click now goes to the
  tent under the highlight ([after](../screenshots/tailgating-tent-under-highlight/after-local.png)).
  Found on dev before the readable links ([#1574](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1574)) reached production.
- Not visible, but measurable: **a popup's code is downloaded when a popup first opens** ([#1617](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1617)), not
  with the page. The first download is 71 KB smaller (15%), and a phone on a slow connection paints the
  map page 0.4 to 0.5 seconds sooner; the first popup of each kind opens a moment later than before. The
  numbers are in [`docs/build-times.md`](../build-times.md#page-load).
- Not visible, but measurable: **four more cuts to the map's first download** ([#1454](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1454)). The All Maps pages
  ([#1633](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1633)), lodash and colornames ([#1635](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1635)) and the trip planner's components ([#1645](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1645)) are no longer in it,
  and the event definitions are loaded after startup instead of before the first paint ([#1638](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1638)). With the
  popups, the map page's JavaScript goes from 459 KB to about 330 KB gzipped, by adding the separate
  measurements; a phone on a slow connection paints 0.3 seconds sooner from the event definitions alone.
  The numbers are in [`docs/build-times.md`](../build-times.md#page-load).
- Not visible: **the modernization steps above** ([#1569](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1569), [#1453](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1453)).
- Not visible: Cypress and its e2e projects are deleted ([#1545](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1545)); the smoke suite fails a map that draws
  ArcGIS's default symbol, and every layer's symbology is inventoried in
  [`docs/layer-symbology.md`](../layer-symbology.md) ([#1578](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1578)); the smoke suite runs from a checkout with
  no install of its own ([#1459](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1459)); the local check lints what CI lints ([#1475](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1475)); and checks and smoke
  runs record their durations only when asked ([#1593](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1593), [#1647](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1647)).
