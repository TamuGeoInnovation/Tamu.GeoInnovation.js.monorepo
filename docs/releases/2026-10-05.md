**Previous release on production: [2 October](2026-10-02.md).** The Angular 16 release written up for
3 October was cleared on dev but never deployed on its own. Release files are named for the day they
reach production, so its notes became this file, and this release carries everything merged since.

The framework under every map moves from **Angular 15 to 18**, in three steps, one major version at a
time, with **NestJS 10** for the APIs and the **ArcGIS 4.27** runtime and type definitions for the maps.
Nothing is meant to look different because of any of it. What visitors will notice is smaller and was
found along the way: alerts that stack into one tidy card, and All Maps that fits a phone again. A third
fix, to event maps that opened zoomed out, corrects a fault production never saw: it appeared on dev
with ArcGIS 4.27 and is fixed before production gets 4.27.

---

## Summary

- **Alerts show one at a time**, with a stepper, instead of a stack tall enough to cover the map.
- **All Maps fits a phone again.** The campus cards no longer push their **Copy** button off-screen.
- **Event maps open on the chosen day or session**, as they do on production today. ArcGIS 4.27 broke
  this on dev during this release; it is fixed before reaching production.
- **The dining kiosk map shows its dining locations**, and only its own layers, to every visitor.
- **A map's layer settings stay on that map.** Going Back to the main map no longer brings another map's settings with it.
- **Angular 15 to 18**, in three steps, with Nx 16 to 19.8 and TypeScript 4.9 to 5.5.
- **The ArcGIS runtime moves from 4.23 to 4.27**, and its type definitions with it.
- **NestJS 9 to 10** for the APIs, which deploy separately from AggieMap.
- **Mailroom's production build is optimized**, as AggieMap's is. Mailroom also deploys separately.
- **Five unused applications removed**, each recorded before it went.

## Changed

### Alerts show one at a time

When several alerts were active, the main map stacked all of them, four cards tall, covering much of
the map on a laptop and all of it on a phone. They now share one card with a stepper to move between
them, the most important first.

### Event maps open on the chosen day or session

**Production never had this fault.** Some event maps frame themselves by the visitor's choice in the
builder: each Ring Day day, each Fish Camp session, each Move-In area. Once the ArcGIS 4.27 runtime
reached dev in this release
([#1219](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1219)), every one of
them opened zoomed out at the default campus view instead. The map asked to move before it was ready;
4.23 waited for it, and 4.27 silently ignores the request. It was found by eye while testing on dev, and
fixed before this release could carry it to production. Production still runs 4.23 until this release,
and opens these maps correctly.

| Before (dev, Ring Day day 1) | After |
| --- | --- |
| ![Ring Day day 1 zoomed out at the campus view](../screenshots/1379-choice-view-zoom/before-dev-ring-day-day1.png) | ![Ring Day day 1 framed on the ring pickup](../screenshots/1379-choice-view-zoom/after-local-ring-day-day1.png) |

Every layer still loaded and drew, so nothing in the suite noticed. A new check opens each choice and
checks where the map lands
([#1379](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1379)).

### The dining kiosk map shows its dining locations

**The dining kiosk map shows its dining locations** ([#1392](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1392)). The
sidebar-free dining map at [`/kiosk/dining/map`](https://aggiemap.tamu.edu/kiosk/dining/map), meant
for embedding elsewhere, opened on the basemap with no dining locations, on dev and production. Like
every event map it loads the main map's layers as well as its own, and both define a dining layer.
The kiosk's setting that turned dining on reached only the main map's copy, and whichever copy loaded
first was drawn: on most loads the kiosk's own, still hidden. Kiosk maps now load none of the main
map's layers: the dining kiosk draws the basemap, buildings and dining locations, and nothing else,
so parking lots, space numbers and the 150th event layers are gone from it too. Its dining layer is on
in its own definition. On production it is reached by direct link only; All Maps lists kiosk maps on
dev only, as before. A new smoke check opens it by link on both environments, several times, since
the fault came and went between loads, and checks it holds no main-map layers.

| Before (production) | After |
| --- | --- |
| ![The dining kiosk showing the basemap and no dining locations](../screenshots/1392-dining-kiosk/before-production.png) | ![The dining kiosk with its dining locations drawn](../screenshots/1392-dining-kiosk/after-local.png) |

### A map's layer settings stay on that map

**A map's layer settings stay on that map** ([#1397](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1397)). Some event and kiosk maps change
how they show a main-map layer: Break/Summer parking turns off the surface lots' popups, and the Ring Days, SEC Grounds and football hide construction.
Those settings were kept for the whole browser tab, so going back to the main map without reloading,
with the Back button for example, showed it with the other map's settings until the page was
reloaded. Each map now keeps its own. A new smoke check opens the main map, moves to such a map,
goes Back, and checks the main map is as it was.

## Not visible

### The app now remembers the previous page on production

On production the app never recorded where you had been. It recognised each navigation by a class
name, and production builds shorten class names: in production's code `NavigationEnd` is called `Wn`.
So its history stayed empty; development builds keep class names, which is why nobody saw it there.
The only thing that reads that history today is the **Report a bad route** form in directions, which
now closes back to the directions you came from instead of falling back to the browser's Back.
Directions are hidden on production, so **nothing a visitor reaches on production changes yet**; it
matters once directions return
([#1348](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1348)).

### GIS Day's date and time pickers are ready, but not in this release

The hour grid came from a library that only worked through `ngcc`, which Angular 16 removes. The shared
picker now shows the browser's own time and date inputs, and every page that uses it is unchanged
([#1220](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1220)). The change
is in this release's code, but **GIS Day is deployed separately, not by this release**, so visitors see
it when GIS Day next deploys.

![Before: the old hour grid for a GIS Day event start time](../screenshots/1220-native-date-time-picker/before-gisday-event-start-time-picker.png)

### Mailroom's production build is optimized

Mailroom's production build had never been optimized. It shipped unminified code with Angular's
template compiler, and compiled its templates in each visitor's browser: an initial download of
4.84 MB. It now builds ahead of time with the same production settings as AggieMap, at 408 kB
([#1368](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1368)). Found
because the Angular 17 upgrade pushed it past its 5 MB budget. Nothing is meant to look different, and
**Mailroom is deployed separately, not by this release**, so it changes when Mailroom next deploys.

### Angular 16

Angular 15.2 to 16.2, Nx 16.0 to 16.10, TypeScript 4.9 to 5.1
([#1343](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1343)), the first
version step of [#1218](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1218).
It needed `ngcc` gone first: four packages that relied on it were upgraded, replaced or removed, and the
install now fails if one returns
([#1276](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1276)–[#1279](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1279)).

### Angular 17

Angular 16.2 to 17.1, Nx 16.10 to 17.3, TypeScript 5.1 to 5.3
([#1365](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1365)). Angular 17's
new template syntax and build system are not adopted, so this stays a pure upgrade. Angular 17 reserves
`@` in templates, so every email address shown on a page is now written as its character code, which
renders the same.

### Angular 18

Angular 17.1 to 18.2, Nx 17.3 to 19.8, TypeScript 5.3 to 5.5
([#1371](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1371)). Every app's
HTTP setup changed form, from Angular's deprecated module to its provider function, keeping the existing
request interceptors working; data loading is what the team was asked to watch on dev. Angular 18's
optional features are not adopted.

### NestJS 10

NestJS 9 to 10 for the NestJS APIs: GIS Day, OIDC, Mailroom, VeoRide, Geoservices and UES Operations
([#1350](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1350)). It was held
out of the Angular 16 step to keep to one major version per change. AggieMap and the event maps are
Angular apps and do not use it, and **the APIs deploy separately, not by this release**.

### The ArcGIS runtime and its types move to 4.27

The maps loaded ArcGIS 4.23, from 2022, because nothing pinned the version
([#1219](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1219)). They now
load 4.27, and the type definitions the code is checked against match it
([#1322](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1322)). 4.27 is the
last release of those types. Moving them meant naming the line-marker type on every route arrow, which
is what ArcGIS already assumed, and removing two unused query helpers that 4.27 no longer provides.

The one difference 4.27 made on the maps is the framing fault [above](#event-maps-open-on-the-chosen-day-or-session),
fixed in this release.

### Five unused applications removed

Three UES applications UES confirmed it no longer uses
([#1325](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1325)), Geocode
Correction Lite, which the Geoservices site no longer serves
([#1339](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1339)), and the
2019 Tree Inventory experiment
([#1352](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1352)). Each is
recorded in [`docs/applications/`](../applications/) before it went. The UES Operations map is in daily
use and stays.

### Builds are tagged with their applications again

Nx 16.10 broke the step that tags each build with the applications it holds, so the first development
build after the upgrade carried none, and a release filtering on those tags could fall back to a
different build ([#1354](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/1354)).
A deployable build that tags nothing now shows as an error.
