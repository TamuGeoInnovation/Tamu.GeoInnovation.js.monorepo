## How each column was decided

**The four APIs: what the image installs.** `nx build <app> --configuration production` writes no `package.json` into
`dist/apps/<app>`. `publish.yml` copies the **root** `package.json` and `package-lock.json` there, and the Dockerfile runs
`npm ci --omit-dev` with `NODE_ENV=production`. So every API image installs the **production closure of the whole
root `package.json`**, the same 2,458 package folders in all four, whatever the API uses. I built the `gisday-nest` image
that way and listed its `node_modules`. `@nestjs/core` and `typeorm` are present, and `@angular-devkit/build-angular` and
`webpack-dev-server` absent, so dev dependencies really are left out. The other three APIs' Dockerfiles are identical and
install the same two files, so I did not build them separately. A package is **runtime** for the APIs when a vulnerable copy
of it (its exact path in the lock) is in that list.

- (`--omit-dev` is not an npm flag; `--omit=dev` is. It works only because the Dockerfile also sets `NODE_ENV=production`.)

**"Loaded by API code"** is the narrower question. `main.js` inlines no package (no `node_modules` path in any of the
four), so what an API loads is what its `main.js` `require()`s: gisday 23 packages, geoservices 8, mailroom and
mailroom-helper 22 each. I walked each one's dependencies through the lock (peer and optional dependencies included),
which gives 494, 146, 471 and 471 packages. This is a static reading, so a package loaded only by a computed `require`
would be missed. "none" means no API's `require` reaches it.

**The Angular apps: what is in the bundle.** `nx build <app> --configuration production --statsJson` for
aggiemap, gisday, mailroom, geoservices and ues-operations, all exit 0. The builder writes `browser-stats.json`, the
esbuild metafile. A package is **runtime** for an app when a vulnerable copy of it contributes bytes to any output file
(lazy chunks included). **ues-operations-angular has no Dockerfile**, so it is not one of `publish.yml`'s images; it is in
the table because the batch named it. The images `publish.yml` builds are the eight apps with a Dockerfile: the four APIs
and aggiemap, gisday, mailroom and geoservices.

**build-only** means every copy of the package in the lock is a dev dependency. **absent** means it is a production
dependency that this app does not ship.

**The fix column is what `npm audit` names.** "npm audit fix (in range)" means the fixed version is inside the range
`package.json` already allows, so only the lock changes. Otherwise it names the package to change, and I compared the
version named with the version installed: patch, minor or major, with 0.x minor changes counted as major. **Three of the fixes `npm audit`
names are downgrades** (`@angular/build` 22.2.3 → 22.1.9, `@nx/node` 23.3.0 → 23.2.1, `csurf` 1.11.0 → 1.2.2). Those
are not usable fixes, so they are labelled "a downgrade" rather than given a bump size.

## Questions for the director (home)

1. **The API images install every production dependency in the repository, including the front ends'.** That is why
   `swiper`, `@koa/cors`, `koa` and `node-forge` count as runtime in all four APIs without any API loading them, and it is
   about 2,450 packages per image. Options: (a) leave it; (b) let Nx generate each API's own `package.json` and lock
   (`generatePackageJson`) and stop `publish.yml` copying the root ones over it, so each image installs only what its API
   loads. **Recommendation: (b), as its own issue.** It would take 4 of the 17 runtime packages out of the APIs, and most
   of the attack surface with them. It changes how images are built, so it needs its own check. Not filed.
2. **Where to start.** Of what is loaded, the in-range fixes are lock-only updates (`tar`, `axios`, `follow-redirects`,
   `dicer`, `multer`, `jws`, `validator`, `http-cache-semantics`, `brace-expansion`). **`class-validator` (critical, 0.13.2 →
   0.15.1) and `nodemailer` (6 → 10) are the two loaded ones that need a real upgrade**, and `form-data` in gisday-nest has no
   fix named. For the front ends, `swiper` 11 → 14 is a major bump on two maps.
