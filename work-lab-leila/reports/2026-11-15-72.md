## First: the API already sorted by name (question 1)

**What was already there:** all three broadcast reads already had `ORDER BY name ASC`, since 2024.

**What that does:** SQL Server ignores case, but compares numbers as text. So "Zoom 10" lands between "Zoom 1" and
"Zoom 2".

**Why that doesn't explain #3047:** that can't put "Zoom 4" first, or "TTU 1" among the TAMU ones, as the issue
describes. That only fits if production's names differ from the local copy, for example a leading space. The local
2026 broadcasts were already in order.

## What changed

- **Where:** `EventBroadcastService` (`libs/gisday/platform/data-api/.../event-broadcast.service.ts`) now sorts its three
  list reads: every broadcast, a season's, and the active season's.
- **Why there:**
  - Admin, Broadcasts reads a season's broadcasts.
  - An event's drop-down reads the active season's.
  - Those are the only callers, so one place keeps every list in agreement.
  - The list's own column sorting is unchanged.
- **Reused:** `class.provider.ts` already had the same `Intl.Collator`. It moved to a shared `_base/natural-order.ts`, with
  a `byName` helper, and classes and broadcasts both use it.
