## The design: one table

All in `libs/gisday/common/src/lib/submission-deadlines.ts`:
- **`DEADLINE_COMPETITION_TABLE`** lists poster, presentation, paper and cartography, each with the label the admin
  section shows. `DEADLINE_COMPETITIONS` is built from it, and `DEADLINE_KINDS` is submissions and files.
- **Generated from the table:** the field names, the `SubmissionDeadlines` type and `SUBMISSION_DEADLINE_FIELDS`. The
  four existing names, and their order, are unchanged.
- **The admin section** takes its blocks and labels from the table, so the poster-or-presentation label ternary is gone.
- **The checks didn't need changing.** The submission provider, `submission-files.service.ts`, `deadlinesProblem`
  (behind the PATCH endpoint) and the submission page's notice already went over the table. They now cover paper and
  cartography.
- **A new guard test** fails if a field the rules name has no column on `Season`, so the table and the entity can't
  drift apart.

**Poster and presentation behave exactly as before.** One existing test changed: `saves all four moments` expected
exactly four fields in the update. The endpoint writes every deadline, so it now also expects the four new fields (as
null), and is renamed `saves every moment`. Every other #2934 test passes unchanged.

**Where I looked for something to reuse:**
- `libs/gisday/common`: the rules themselves, extended rather than copied.
- `SUBMISSION_TYPE_OPTIONS` in ngx/common: its labels say "Paper", not "Paper competition", and the API can't import a
  site library.
- The API's `PRESENTATION_SUBMISSION_TYPE` enum: it lives in the entities, which the site mustn't import.
