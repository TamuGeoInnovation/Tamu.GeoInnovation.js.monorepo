## 2. How it finds the steps

A new function, `lint_steps`, reads `.github/workflows/lint.yml` **from the branch being checked**, by `git show`, as `excluded_projects` already
does. It takes every `run:` line and sorts it into one of three kinds:

| Kind | What the script does | Examples |
| --- | --- | --- |
| Nx, or the install | **Left out**; the nx runs and `npm ci` already cover them | anything containing `nx ` or `nx.js`, `npm ci`, `npm install` |
| A one-line command | **Runs** after the nx runs, in every mode (affected, all, a project list), in the same container and volume, each as its own logged `=== lint.yml: <command>` step; **the check fails if any does** | today, only `npx tsc -p test/smoke/aggiemap`. Surrounding quotes are removed |
| A step it cannot run as CI does | **Stops the check before it starts** (exit 2), naming the step and saying to make it one line or teach `lint_steps` | a multi-line `run: \|` block, or anything using `${{ }}`, which only GitHub expands |

**Why stop rather than skip:** passing without the step would claim more than was checked. That is the failure this issue is about.

**A branch whose `lint.yml` is missing** gets no extra steps in project-list mode. Affected and all modes already refuse such a branch, for
the exclusion lists.

The script prints the steps it will run in its header, beside the exclusions: `lint.yml: npx tsc -p test/smoke/aggiemap`.

**`bash scripts/check-in-volume.test.sh`: 10 cases, all ok.** The four new ones use fixture workflows:
- today's `lint.yml` shape gives exactly the typecheck;
- a quoted step is unquoted, `nx.js format:check` is left out, and a block and `${{ }}` give `cannot`;
- a `lint.yml` with no `run:` steps gives nothing;
- a missing `lint.yml` is an error.
