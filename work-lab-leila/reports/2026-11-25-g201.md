## Why the `data-api` libraries stayed on Jest

**What went wrong:** converted the same way, `gisday-platform-data-api` failed 67 of 1,238 tests in 34 files, and
`gisday-competitions-data-api` 3 of 189 in 8 files.
- **Almost all were one error:** `DataTypeNotSupportedError: Data type "Object" in "Sponsor.logoSize" is not supported by
  "mssql" database`.

**Why:**
- `logoSize` is typed `SponsorLogoSize`, a string union declared elsewhere.
- `ts-jest` type-checks, so it emits `String` as the property's `design:type`.
- Vite 8's transform (oxc) sees one file at a time. It can't resolve the alias, so it emits `Object`, and TypeORM refuses
  the column.
- `tsconfig.base.json` sets both `experimentalDecorators` and `emitDecoratorMetadata`, and oxc honours them, so it isn't a
  setting.
- Any entity property typed by an alias, enum or interface declared elsewhere will do the same.

**Kept for later:** the conversion as a patch, `g201-data-api-vitest.patch` (6,936 lines), in my scratch folder, not the
mailbox. It's mechanical and can be regenerated in minutes.
