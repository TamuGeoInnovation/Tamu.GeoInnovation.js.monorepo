## What this changes

Two families of hand-written copies, from the #2591 audit, are now each built by one factory. The factories follow
`move-out.definitions.ts`'s `moveOutPeriod`. Each map's file now holds only the facts that differ, so a new filter rule,
popup or wording is made once for the whole family.

**The date filter.** `periodDateConversions(periods, startField, endField)` in `common.definitions.ts` replaces
`ringDayDateConversions`, `novemberRingDayDateConversions` and `aprilRingDayDateConversions`. Those were the same function
in three files, differing only in the constant's name.

**Ring Day.** `ringDayMap(facts)`, in the new `ring-day.definitions.ts`, holds the shared parts: the three layers and
their popups, the filters, the configuration and the Campus Maps entry. Each map gives only:
- its `id` and `name`;
- the name its notification uses (October's says only "Ring Day");
- its builder question, which the three word differently;
- its column and its periods.

**Graduation.** `graduationMap(season, dates)` sits in `graduation.definitions.ts`, beside the sources both maps already
shared.
- **The dates stay written out per season.** The fall map's dates were corrected under #2759. `value` is midnight in
  College Station, which is 05:00Z in May and 06:00Z in December, and the weekday labels are the registrar's. A factory
  that derived them would have to be right about both. A comment beside each map's dates now says which offset it uses.

**Every export keeps its name,** so the library's `index.ts` and `all.definitions.ts` are untouched. November's and
April's layer enums are October's, under the names they've always had: the three had the same values.

**The two popup spellings** (`'{attributes.name}'` and `'attributes.name'`) are no longer within this family.
- **Fall and spring** already share one source list, which uses `'{attributes.name}'` throughout.
- **Summer's map** (`graduation-summer.definitions.ts`), which isn't part of this change, uses `'attributes.name'`.
- **Both resolve:** I checked the services. `GraduationParking_view` layers 0, 1 and 3, and `Summer_Commencement_view`
  layer 1, all have `name` and `description`.
- **So I left both as they are.** Changing either would change a map's output, which this pull request is meant not to
  do.

**Not changed:** the eight athletics parking definitions in the same folder (PR 3600).
