## The option

- **The inputs:**
  - `clearable`, off by default;
  - `clearLabel`, which defaults to `Clear`. The three GIS Day boxes pass `Clear the search`, as their old copies said.
- **Off adds nothing to the page.** A test checks that a textbox without the input has an empty action slot and no
  button, even with text in it.
- **When it shows:** only while the box holds text and isn't disabled.
  - It sits in the textbox's existing `.textbox-actions` slot, after anything a page puts there.
  - So the Presenters page's Copy link stays to its left.
- **Clearing sets the value the same way typing does.** The form control's `valueChanges`, `ngModel` and the
  `valueChange` output all fire, so each page's filter updates. Focus goes back to the input.
- **Accessible:**
  - It's a real `<button type="button">`, reachable with Tab, with an `aria-label` and a tooltip.
  - The browser's focus ring is kept.
  - In the local site, Tab and then Enter emptied the Sessions box and put focus back in it.

**The pages:**
- **Presenters (`people-view`):** its own `span.search-clear` (with `role="button"`) and the `.search-clear` style are
  removed.
- **A presenter's page (`people-details`):** its own `span.search-clear` is removed.
- **Sessions (`event-view`):** gains the button. It had none.

**Where I looked for something to reuse:**
- **`libs/ui-kits/ngx/forms/**`:** no control has a clear or icon button, and the textbox's `.textbox-actions` slot is
  used as it was.
- **`libs/ui-kits/ngx/search`:** its right-hand icon is an `<i>` that reacts to mouse-down only, so it can't be reached
  by keyboard. It isn't a good model.
- **`libs/sass/components/_button.scss` and `_copy-button.scss`:** neither is an icon button.

The button's style is five resetting declarations in the textbox's own stylesheet, so it looks like the bare icon the
pages had.
