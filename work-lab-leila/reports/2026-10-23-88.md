## 1. The cause

- **Where it is called:** each of the four `/services/*` pages (`geocoding`, `reverse-geocoding`, `address-processing`, `census-intersection`
  components in `libs/geoservices/ngx/.../public/pages/services/pages/`) runs a **demo request** (`apiKey: 'demo'`) for the code runner's
  **Result** tab. Its `catchError` returns `err.toRenderableJSON(true)`, a method of the library's `GeoservicesError`.
- **On what:** the request is axios. A rejection goes through `ApiBase._request`'s `.catch(this.handleResponse)`, which correctly throws
  `new GeoservicesError(axiosError)`.
- **Why it lacks it:** `GeoservicesError`'s constructor read **`badResponse.response.status`**, and a request that **got no answer at all**
  (refused, offline, blocked by CORS, timed out) is an `AxiosError` with **no `response`**. So the constructor itself threw
  `TypeError: Cannot read properties of undefined (reading 'status')`. That plain `TypeError`, with no `toRenderableJSON`, is what reached the
  pages' `catchError`, which then threw again. A request the server **did** answer with an error was handled correctly all along.
- **Locally:** the demo request goes to `http://localhost/wap.api.geoservices.tamu.edu.5.0.0//Api/Geocode/V5/...` (the local environment's
  `geoprocessing_api_host_override` placeholder) and is refused (`net::ERR_CONNECTION_REFUSED`), so every load hits it. On a deployed site it
  happens whenever the demo request gets no answer. I did not call production's API to see what it answers today.

## Does a user see anything wrong? Yes: an empty Result tab

The result stream errored instead of emitting, so **the Result tab showed an empty code panel**: no result and no error. Before and after,
`docs/screenshots/2267-geoservices-result-tab/`:

"Unknown error" is the library's own normalisation (`errorNormalize`), which names every status it does not list that way. The typo "ocurred"
is the library's existing text.

## 2. Red first, then the fix

`libs/geoprocessing/core/src/lib/errors.spec.ts`, the library's first spec (Jest):

- **"describes a request that got no answer"**: `new GeoservicesError(new AxiosError('Network Error', 'ERR_NETWORK'))`. On `development`
  (`scripts/check-in-volume.sh ... geoprocessing-core`, exit 1): `TypeError: Cannot read properties of undefined (reading 'status')`.
- **"describes an error the server answered with, as before"**: an answered 401 becomes *API key missing*, code 401. It **passed before and
  passes after**.

**The fix** is in the constructor: with no response, the status is `0` and the type is the error's code (`badResponse.response?.status ?? 0`,
`badResponse.response?.statusText ?? badResponse.code`). The pages' `catchError` is unchanged; they now always get a `GeoservicesError`.
