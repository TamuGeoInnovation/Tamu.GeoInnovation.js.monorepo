## Task 2: #2144, a capture from a worktree silently records no commit

**The cause, confirmed:** a worktree's `.git` is a one-line file, `gitdir: C:/TAMU/Tamu.GeoInnovation.js.monorepo/.git/worktrees/<name>`.
In a container with only the worktree mounted that path does not exist, `git rev-parse` fails, and
`releaseCommit()` swallowed the error and returned `null`.

**What changed:**

- **`tools/visual-baselines/release-commit.mjs`** (new), which `capture.mjs` now imports. Its `releaseCommit(repo,
  release)` returns `{ commit, why }`:
  - `.git` a **directory**: git as before.
  - `.git` a **file**: its `gitdir:` line is read and resolved. If that gitdir exists, git runs against it (`GIT_DIR`).
    If not, `why` says so, names the path, and says what to do.
  - no `.git`, a `.git` file naming no gitdir, or a release git cannot resolve: each gets its own `why`.
- **`capture.mjs`**: where it printed `release <name>`, it prints `releaseLine()`. The manifest takes
  `commitFields()`: `releaseCommit` as before, plus **`releaseCommitMissing: <why>`** when there is no commit. Nothing
  else in `capture.mjs` changed: the capture, the comparison and the output layout are untouched (5 lines in, 11 out,
  the old function among them). A missing commit is not fatal.
- **`tools/visual-baselines/release-commit.test.mjs`** (new), three tests, each on a throwaway git repository built in
  a temporary folder; no network, no Docker beyond the Node container that runs them.

**Red first.** I first moved the old function into the new module **unchanged** (it still returned `null` with no
reason) and ran the tests against that. `node --test "tools/**/*.test.mjs"` in `node:24.22.1`: **exit 1, 13 passed, 1
failed**, the third test, for the right reason:

```
✔ a worktree, whose .git is a file naming its gitdir, finds the commit (35.638072ms)
✔ the main checkout, whose .git is a directory, still finds the commit (11.268103ms)
✖ a worktree whose gitdir cannot be reached says so, and the manifest records why (11.06913ms)
  AssertionError [ERR_ASSERTION]: The input did not match the regular expression /worktree/. Input:

  ''
```

The first two pass even on the old code, which is worth knowing: **git follows a `.git` file by itself when its gitdir
can be reached**. The silent `null` happens only when it cannot, which is what the third test reproduces.

**Green.** The same command after the fix: **exit 0, 14 of 14 passed**, the 11 existing tools tests (`event-dates`,
`security-findings`) included.
