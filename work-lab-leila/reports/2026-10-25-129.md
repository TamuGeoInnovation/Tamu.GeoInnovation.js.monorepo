## The test (step 2): red, then green

**What it is:** `libs/gisday/platform/data-api/src/lib/_base/query-checking-data-source.ts`, a helper for specs.
- It builds the API's **real entities** (`GISDAY_ENTITIES`) on a **real typeorm `DataSource`** of type `mssql` that never connects.
  `initialize()` would connect; the helper runs only the metadata build that `initialize()` does next.
- Its repositories run each query's find options **through typeorm's own query builder** (`createQueryBuilder().setFindOptions(...).getQuery()`)
  and then return nothing.
- **Why not a database started in the test:** the entities use SQL Server types (`datetimeoffset`), so SQLite (`better-sqlite3` is installed)
  cannot load them, and CI has no SQL Server. No database is needed anyway: **typeorm 1 throws this error while it builds the query, before
  any database is contacted**, so the helper exercises exactly the code that failed. CI runs it as an ordinary unit test.

**Two specs use it**, each running the provider itself on an event as the API loads it (`capacity: null`):
- `user-rsvp/user-rsvp.provider.queries.spec.ts`;
- `event/event.provider.queries.spec.ts`.
