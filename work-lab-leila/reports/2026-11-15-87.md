## What changed

**For speakers (`session-files`), with no sign-in, all behind the guard:**
- `GET link/:token` lists the speaker's sessions this season, with their slides.
- `POST link/:token/:event` uploads or replaces. A session has one set of slides (question 1).
- `DELETE link/:token/:event` removes them.
- **The guard runs before Multer,** so a bad link is refused before any of the file is written.
- **Refusals:** another speaker's session, last season's, or a made-up id answers 404, and the upload is deleted.

**For admins (`update:events`):**
- `GET event/:guid` and `event/:guid/:file` list and download a session's slides.
- `GET season/:guid` lists which sessions have them.

**Storage:** an `Asset` of type `session-file`, under `APP_DATA/sessions/<guid>`.

**The pages:**
- **The edit-link page** gets **Your sessions**: each session's name, day, time and room, with Upload slides, Replace and
  Remove. The speaker sees the name, size and date, but can't download (1A). I looked at `after-edit-link-uploaded.png`
  myself.
- **A session's admin page** gets a Slides section, with downloads.
- **The season list:**
  - **Where:** in the existing admin Events list, rather than a new page. It gets a Slides column (the upload date, or
    None) and an "Only sessions with no slides" filter, as #3034's tag filter does.
  - **Why there:** it already has the season picker, search and filters, and each row opens the session page with the
    download.
