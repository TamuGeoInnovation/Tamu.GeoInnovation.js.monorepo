### #300: closed, and #2614 filed

**The implementation in the screenshot is gone.**
- In 2022 the bus mode picked its own boarding stop (`BusService.getStopAtPoint`, the nearest by distance), from the old
  Transportation Services API.
- That API no longer exists, and `bus.service.ts` says those methods are kept only so it compiles.
- Since PR 2577, a bus trip is solved by the network's own `Bus` travel mode.

**Run on dev:** a bus trip from about 25 m beside the Reed Arena stop to the MSC
(`/map/d/trip?mode=5&stops=30.60725,-96.34830@30.61403,-96.34313`). The stop's location came from `TS/Bus_Routes/MapServer/0`. The
directions **start on the bus**: *"Go southwest on 40 toward Bus Stop"*. That's what #300 asked.

**What it turned up:** that trip rides route 40 for **6.19 miles, 26 minutes in all**, to a stop 0.6 miles away, though route 05 serves
both. That's route choice, not stop choice, so it's a new issue.

### #205 and #274: kept

Both still hold against `21e69426e`:
- **#205:** `updateSettings()` only updates the in-memory store. Writing local storage happens only in a `tap()` inside the observable
  `init()` returns.
- **#274:** stored values are read only by `init()`, for the branch it is given. `getSimpleSettingsBranch()` reads memory only. The
  example component, the experiments basemap override, still exists.

**Each comment** says what a fix would be and the test to prove it. **They are two sides of one design point:** storage is touched only
inside `init()`. They'd be best fixed together.
