## 1. The cause

The stack, from `/?poi=2` on the AggieMap dev server (`development`):

```
TypeError: Cannot read properties of undefined (reading 'name')
    at TripPlannerConnectionService.connection
    at Object.next   (its fetchNetworks subscription)
```

- **What reads `name` from what:** `TripPlannerConnectionService.connection()` reads `this._store.latestNonAbNetwork.name`.
- **Why that is `undefined`:** when the service is created, it asks `<gisHost>/arcgis/rest/services/Routing?f=pjson` for its networks, keeps the
  latest one named `Routing/YYYYMMDD`, and then calls `connection()`.
  - **The production GIS server's Routing folder lists nothing**: `gis.it.tamu.edu/.../Routing?f=pjson` → `"services": []`. No NAServer is
    listed anywhere on that server.
  - So the latest network is `undefined`, and `connection()` dereferences it.
  - The development server still has `Routing/20220119` (and `Routing/ChrisRoutingTest`), so dev-backed builds do not log it. **Localhost reads
    the production GIS server**, which is why the local run shows it.
- **Why a POI popup:** the service is created by whatever first injects it. The POI popup extends `BaseDirectionsComponent`, which injects the
  trip planner, and through it this service. So it is not about POIs: **any popup that can offer directions** triggers it, once per page load.

## Visible, or only noise? Only noise

- `directions.spec.ts` already records that **routing is unpublished on production (#1003)**: directions are hidden there, and offered only on
  dev and localhost for whoever rebuilds routing. So on production, the failed lookup changes nothing a visitor can see.
- On localhost, directions are offered but have no network to route on, with or without this error.
- The error left the service in its starting state (an empty network), which is exactly where the fix now leaves it, quietly.

**So no screenshots and no release notes**: nothing on screen changes.

## 3. The fix

In `trip-planner-connection.service.ts`, the latest network is kept, and `latestNonAbNetwork` emits, **only when one was found**. Otherwise the
empty network the service starts with stays, and `connection()` **returns nothing** when there is no network to connect to. The comments cite
#1003 and #2259.

- The spec passes.
- **Live:** `/?poi=2` on the dev server after its rebuild logs **no console errors** (before: the one `TypeError`).
