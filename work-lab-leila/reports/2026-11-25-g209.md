## Each wrapper, traced

| Wrapper | The value | Comes from | Done |
| --- | --- | --- | --- |
| Session form, `activeSeasonDays$`: `date: new Date(day.date)` | each day's date | `SeasonService.activeSeason$` | `date: day.date` |
| Session form, `_timeStringFromEvent$`: `new Date(event?.day?.date).toDateString()` | an edited session's day | `EventService.getEntity` (`entity$`) | `event?.day?.date?.toDateString() ?? null` |
| Session form, `_readableTime`: `new Date(event.day.date).toDateString()` | the same | the same | `(event?.day?.date ?? new Date()).toDateString()` |
| Season form, `addDay`: `day ? new Date(day.date) : new Date()` | an edited season's days | `SeasonService.getEntity` (`entity$`), or none for a new day | `day ? day.date : new Date()` |
| `groupEventsByDay`: `new Date(event.day.date)` | each session's day | its one caller, the admin session list, reads `EventService.getEntitiesForSeason` / `ForActiveSeason` | `event?.day?.date ?? null` |
| Landing countdown: `new Date(new Date(season?.days[0].date).toDateString() + …)` | the first day | `SeasonService.getActiveSeason` | `new Date(season.days[0].date.toDateString() + …)`; the outer `new Date`, which joins the day and the time, stays |

**Edge cases:**
- **`_timeStringFromEvent$`, a session whose day isn't loaded:** this gave "Invalid Date" text before and gives `null`
  now. Both reach the same default (`isNaN(parsed)` or `=== null`).
- **`addDay`:** I kept the `day ? … : new Date()` shape. That way a day with no date behaves exactly as before.

**No copy is needed:** nothing in these files mutates a date (`setHours` and the like: none). The date-time picker the
season form uses builds new Dates (`withDate`, `withTime`) and never changes its input.

**Left alone:**
- `site-email.ts` and the API's `season.service.ts`, as #3574 says;
- `review-email.ts`'s `new Date(session.day.date)`, which is shared `@tamu-gisc/gisday/common` code that the API also
  runs.
