## The cause

**Nx 23's recursion detector reported any database error as a recursion.** Nx tracks running tasks in a local SQLite database
(`TaskInvocationTracker`, in `.nx/workspace-data/machine-v6.db`, table `task_invocations`: `root_pid`, `pid`, `task_id`, ...) to catch a task's
command re-invoking itself through nested Nx processes. In **Nx 23.3.0** (`dist/src/tasks-runner/task-orchestrator.js`):

```js
try {
    this.taskInvocationTracker.registerTask(process.pid, task.id);
    this.registeredInvocations.add(task.id);
}
catch {
    // Unique constraint violation — task already invoked by an ancestor Nx process
    const chain = this.taskInvocationTracker.getInvocationChain();
    ... output.error({ title: 'Recursive task invocation detected', ... })
```

- **Every** exception from `registerTask`, not only the unique-constraint violation its comment assumed, was reported as a loop, and the run
  exited 1. A transient SQLite error, such as a locked or still-being-created database while eight lint tasks register at once, did that.
- **The "chain" it printed was every task registered so far in the run** (`getInvocationChain()`), which is why it read as a string of
  unrelated lint tasks, `maps-esri → common-ngx-pipes → maps-feature-trip-planner → … → maps-esri`, rather than a real loop.
- That fits everything seen:
  - intermittent;
  - **both times on the first run in a check volume**, when the database is new;
  - the same kind of chain each time;
  - passing on an immediate rerun.

**Nx 24 fixed it.** In **24.0.0** (what `development` runs) and 24.0.1:

```js
try {
    chain = this.taskInvocationTracker.registerTask(process.pid, task.id, hashTaskOverrides(task));
}
catch {
    // Loop detection is diagnostic only; a DB failure must not fail the run
    // or be mistaken for a loop.
    return;
}
if (!chain) { ...; return; }   // a chain is returned only when an *ancestor* process runs this task
```

A database failure is now ignored. A loop is reported only when an ancestor Nx process already holds the same task, with the same overrides.
Sibling processes are explicitly allowed, and leftover rows are swept as stale. **Both failures (batches 80 and 87) were on branches still on
Nx 23** (`chore/1218-angular-build`, `chore/1218-maplibre`).
