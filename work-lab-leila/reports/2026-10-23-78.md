## Sanitising: the answer first

**Is the markdown untrusted? No, so I carried on. Is the output sanitised? Also no.**

- **The only call site** is `MarkdownParsePipe` (`libs/common/ngx/pipes`). It returns `bypassSecurityTrustHtml(marked(value))`, and every caller
  binds it with `[innerHTML]`.
  - So **Angular's sanitiser is switched off** for this HTML. Nothing else sanitises it: no DOMPurify, and marked has no `sanitize` option
    any more.
  - **marked 18 changes none of this.**
- **Who writes what it renders:**

| Where it shows | Field | Written by |
| --- | --- | --- |
| GIS Day session page | event `abstract`, `requirements`, broadcast `details` | holders of `create:`/`update:events` and `…:event-broadcasts` (JwtGuard + PermissionsGuard) |
| GIS Day presenter page | speaker `description` | `create:`/`update:speakers` |
| GIS Day sponsor page | sponsor `description` | `create:`/`update:sponsors` |
| AggieMap POI and bonfire popups | `description` | the university's ArcGIS Online Points of Interest service |
| AggieMap dining popups (also ts-events) | `description` | `api.aggiemap.tamu.edu/dining/locations/geojson`, i.e. the dining department's text |

- **None of it is anonymous or public input**, so this is not the "stop" case. Two weaker spots, though:
  - **Every one of the 115 AggieMap descriptions is raw HTML**, not markdown: `h1 h2 h4 p span div a strong em u br`, with `href`, `target` and
    `data-*` attributes.
  - **The dining text comes from another department's system** through an API that is not in this repository, so nothing here checks it. A
    `<img onerror>` typed into it would run on aggiemap.tamu.edu. There is none today: the corpus has no event-handler attributes.
- **Recommendation: a separate small change.** Stop bypassing, and let `[innerHTML]` sanitise.
  - Its allow-list covers every tag above and `href`. Which of the other attributes it keeps (`target`, `data-*`) I have not checked; the
    spec should.
  - It is one line in the pipe, plus a spec asserting that an `onerror` is stripped.
  - Not done here: it is not the upgrade.

## 2. The upgrade

- **`marked` `^9.1.5` → `^18.1.1`.**
- **The lock**, by batch 41's method: `node_modules/marked` removed, then `npm install --package-lock-only --ignore-scripts`. Key by key, the
  only changes are **`node_modules/marked` 9.1.6 → 18.1.1** and the root's own range. **`@arcgis/core` keeps its nested `marked` 18.0.14**
  (`~18.0.5`).
- **The pipe:** `marked(value, { async: false })`. In 18, `marked()` is typed `string | Promise<string>`, and it is a promise only when asked
  for. Its callers are templates and need the string, which is what this gives them.
- **ESM-only:** the first full check failed in **`gisday-platform-ngx-core:test`**: two Jest suites that reach the pipe got *Must use import to
  load ES Module: …/marked/lib/marked.esm.js*. Its `transformIgnorePatterns` lets `.mjs` through, and marked ships `.js`. So I added
  `marked/` to it, the way lightgallery was already listed there. No other project needed it; the vitest projects load ESM as is.
