## 2. The fix: option (b), and the check that stops the drift

- **`parseDefinition` reads `type` (default `event`), `mapType`, and `mapTypes` as a list**, and passes them to the
  suite's own `mapSegment`. That's a line-for-line copy of the application's, with the same signature, and its doc
  comment names the original. `SECTION_BY_TYPE` is deleted.
- **Only the two routes moved.** I compared every definition's route, old rule against new, over the real files: **69
  the same, 2 different**, `/parking/micromobility` and `/parking/sustainable-transportation`, both now
  `/transportation/`.

**The check against the application, without importing it.**
- The repository already has a bridge. `declared-layers.spec.ts`, a library spec, runs the **real** `mapSegment` and
  records each development-only map's `address` in `test/smoke/aggiemap/declared-layers.generated.json`. It fails until
  that file is rewritten, so the file is always the application's own answer.
- The new test in `scope.spec.ts` reads that file and requires the suite's route to equal the recorded `address` for
  every map that has one. So **if the rule changes in the application, the snapshot changes, and the suite fails until
  its copy matches.** That's the check you asked for, and it's entirely inside `test/`.
- **Its limit:** the snapshot records an address only for development-only maps: three today, `micromobility`,
  `ncaa-volleyball` and `sustainable-transportation`. Both maps this bug was about are among them, but a future rule
  change affecting only non-development-only maps would get past it. Extending the snapshot to every map's address
  would close that; it's one line in `declared-layers.spec.ts`, but that's in `libs/`, so it belongs with (a).
- **Smaller checks:** `tsc -p test/smoke/aggiemap` exit 0. `definitions.ts` and `scope.spec.ts` were already unformatted
  on `development`, so I left their formatting alone.
