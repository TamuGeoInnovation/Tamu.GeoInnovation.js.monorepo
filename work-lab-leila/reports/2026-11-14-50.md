## Approve and Reject: one endpoint for a list

- **The request:** `POST /user-submissions/review`, with `@Permissions(['update:competitions'])`. The body is
  `{ submissions: [guid], acceptance: boolean, message?: string }`.
- **The response:** `{ reviewed: [title], failed: [{ title, reason }] }`.
- **Reviewed exactly as Submit Review does.** The body of `updateUserSubmission` moved into a private `_update`, which
  records the decision and returns the function that sends the review email.
  - A single review still sends without waiting, as before.
  - The list reviews one submission at a time, and waits for each email.
  - It passes `siteHost(req.headers)`, so an approval sends #2957's email from the reviewer's own site.
- **Refusals:**
  - **403** to anyone without the permission, even though the single review lets owners edit their own.
  - **400** for an empty list, a missing decision, or an id that isn't a guid.
- **Partial failures:**
  - One failure doesn't stop the rest.
  - A submission that no longer exists is listed as "it no longer exists". Any other error reads "the decision could
    not be saved".
  - A submission whose email failed still counts as reviewed, and is also listed as "reviewed, but the email could not
    be sent".
  - A guid named twice is reviewed once.

## Send profile email: participants matched to speakers

- **The request:** `POST /speaker-edits/send-for-submissions`, with `{ submissions: [guid] }`. It needs both
  `update:speakers` and `read:competitions`, because it reads participants and emails speakers.
- **The response:** `{ sent, skipped, unmatched: [{ name, submission }] }`.
- **The matching:** each participant is matched by email (trimmed, any case) to the speakers of **the submission's own
  season**.
  - For this year's submissions, that's the active season the batch named.
  - It differs only for an older season's submissions, where this is the right season (question 2).
- **Sending:** each matched speaker gets **one** link through the existing `sendLinks`, even if they're on several
  submissions.
- **Anyone unmatched** is returned by name (or by email, if the name is blank), with the submission's title.

## The page

- **The buttons:** **Approve**, **Reject** and **Send profile email** sit beside Delete in the selected-rows bar. Each
  is one request for the whole selection.
- **Each asks first, in the page,** through `AlertModalComponent`/`ModalService`:
  - "Approve N submissions and email their submitters?" (or Reject). It adds how many were already reviewed and will
    be emailed again.
  - "Send profile emails to the N people of M submissions?", counting each person once.
- **The results:**
  - A review's result goes in a new `reviewSubmissionsToast`.
  - The profile emails' result uses `sendEditLinksToast`, which gained an optional `unmatched` list ("No speaker
    record - name (title)"). The Speakers list's toast reads as it did.
- **After a review, the list reloads**, so the statuses update.
- **A wording fix:** in the live try, the review toast said "and emailed their submitters" above a list of failed
  emails. `75e1015b8` says that only when every email went.
