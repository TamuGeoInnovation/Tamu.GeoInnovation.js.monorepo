## 1. Each animation, and what it became

| Trigger | Where | Kind | Now |
| --- | --- | --- | --- |
| `topBun`, `patty`, `bottomBun` | hamburger button (geoservices, GIS Day, phone) | state | an `up` host class and CSS transitions: 0.3 s for the outer bars, 0.2 s after 0.1 s for the middle one |
| `baseShowHideAnimation` | the phone tile menu | enter/leave | `animate.enter`/`animate.leave`, keyframes from and to `scale3d(0,0,0)`, 0.3 s in, 0.4 s out |
| `tileStaggerAnimation` | its tiles, as the menu opens | stagger (reverse, 30 ms) | a CSS animation per tile (0.25 s, delay `0.3s + (position from the end) × 30ms`, by `:nth-last-child`), while the menu carries `staggering` |
| `submenuShowHideAnimation` | the tiles and a tile's submenu replacing each other | enter/leave | `animate.enter`/`animate.leave`, 0.3 s in, 0.4 s out |
| `submenuListStagger` | a tile's submenu | stagger | **removed, with nothing in its place: it queried `.body p`, which no submenu in geoservices or GIS Day has** (their rows are `.submenu__body .submenu__row`), so it has animated nothing |
| `growAnimation` | geoservices header's submenu rows | enter/leave | `animate.enter`/`animate.leave`, `max-height` keyframes 0 ↔ 250px, 0.5 s |
| `inOutAnimation` | geoservices' 8 interactive forms and their results | enter/leave | global `animate.enter`/`animate.leave` classes in geoservices' stylesheet: 0.3 s in, 0.25 s out, losing its height (`interpolate-size: allow-keywords`) |

**Two behaviours of Angular's animations had to be kept by hand,** because `animate.enter`/`animate.leave` do not do them:
- **A child's entrance was blocked while its parent entered.** So as the menu opened, its tiles did not scale in; they only staggered. The
  tiles' entrance is now switched off while the menu is `staggering`. The menu sets that flag on opening and clears it when the first tile
  arrives (the stagger runs last-first). So tiles shown again on leaving a submenu scale back in without staggering, as before.
- **A child's leave waited on its parent's.** In the first "after" recording, closing the menu with a submenu open made the submenu shrink on
  its own as well as with the menu (scale 0.159 on both). The child's animation is now off while the menu is leaving; re-recorded, the submenu
  holds `1 none` until the menu removes it, as before.

**Reuse rule:** every movement is a mixin in `libs/sass/_motion.scss` (`hamburger-bars`, `tile-menu`, `tile-stagger`, `tile-submenu`, `grow`,
`interactive-form`), with each trigger's timing and easing.

**Removed:**
- the trigger files;
- **`libs/ui-kits/ngx/animations`**, which held only the grow builder, with its path in `tsconfig.base.json` and its `nx.json` entry;
- `BrowserAnimationsModule` from geoservices, GIS Day and signage;
- `@angular/animations` from `package.json`.

`git grep` finds no import of `@angular/animations` or `platform-browser/animations` left.

- **The differences are timing jitter**, a few percent at the same moment, not changed timing: GIS Day's own *before* run read the menu closing
  at **0.159**, the value the after runs show. Durations and end states are the same everywhere.
- **The forms' entrance did not play on a page load before** (the box was at full opacity when first seen), and it does not after. Their leave
  only happens when a request returns a result, which the local API cannot give, so **the leave was not recorded live**; it is the trigger's
  keyframes, unchanged.
