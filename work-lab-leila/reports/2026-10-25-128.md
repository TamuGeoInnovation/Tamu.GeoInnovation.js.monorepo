## The release blocker first

**On `gisday-nest:sha-eab737d` (the release), every session registration answers `500`** once a profile is complete:

```
POST /rsvps/ 500
{"message":"Error creating RSVP. TypeORMError: Null value encountered in property 'UserRsvp__UserRsvp_event.capacity' of a where condition.
 To match with SQL NULL, the IsNull() operator must be used. Set 'invalidWhereValuesBehavior.null' to 'ignore' or 'sql-null' in connection
 options to skip or handle null values.","error":"Internal Server Error","statusCode":500}
```

- **The cause:** `UserRsvpProvider.insertUserRsvp` (`libs/gisday/platform/data-api/src/lib/user-rsvp/user-rsvp.provider.ts`, lines 57 to 62
  at `eab737da7`) checks for an existing RSVP with `where: { event: event, accountGuid }`. That passes **the whole loaded event entity** as a
  where value.
  - typeorm 0.3 ignored the event's `null` columns there.
  - **typeorm 1 refuses them.** typeorm 1 arrived in #2195 (`9f7258f70`, 23 October), which is in this release. Production's `36b962a04`
    still has typeorm `^0.3.26`.
- **Who it hits:** every event whose `capacity` is `null`. That is **all 313 events in the seed**, so production presumably looks the same.
  After this release reaches production, nobody could register for a session.
- **Not caught before** because:
  - the unit spec mocks the repository;
  - the release checks never got past *Profile Incomplete* until this batch;
  - batch 141 ran before the profile was complete.
- **The fix, which I have not made:** look the RSVP up by the event's key, `where: { event: { guid: event.guid }, accountGuid }`. The connection
  option typeorm names (`invalidWhereValuesBehavior`) would hide the whole class of mistake instead.
- **The same pattern elsewhere** (a whole entity as a where value), at `eab737da7`. These all pass a season:
  - `competitions/data-api/.../form/form.service.ts:36` and `:52`;
  - `sponsor.provider.ts:42`;
  - `user-submission.provider.ts:40`.
  
  Seasons have no `null` columns (`updated`, `created`, `guid`, `year`, `active`), so these work today, and batch 139's public pages
  (Sponsors included) passed. They break the moment a nullable column is added to seasons. Check-in looks events up by `guid` and is not
  affected.
