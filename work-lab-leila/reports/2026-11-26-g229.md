## What it does

- **The page:** a **Session tag** choice in the toolbar beside Season.
  - **The choices:** the tags of the season's sessions, each once, by name, after **Every tag**.
  - **What choosing one does:** it leaves only the speakers in a session with that tag.
  - **Built as Events' Organization choice is** (#434): `sessionTagChoices()` mirrors `organizationChoices()`, from
    `listed$`, so it follows the season. The control is one of `listFilters()`, so it's kept in the history entry
    and cleared by Clear.
  - **No new CSS:** the shared `tamu-gisc-select` and `post-1`, as the Season and Organization selects use.
  - **Placement:** first built below the "no session" box, where it stretched the width of the page. I moved it into the
    toolbar to match Events. The #3370 phone spec still passes.
- **The API:** the admin list's own route (`GET speakers/sessions/season/:guid` and `.../active`, behind
  `update:speakers`) now brings each session's tags, with `events: { tags: true }` in `getSpeakersForSeason(_, true)`.
  The public season list is unchanged, with no sessions and no tags.

**Why on the client:** "Only speakers in no session" (#441) filters the loaded list on the client, and so does Events'
Organization choice, so this follows the page's own pattern. The query change is only that the admin route now brings
the tags the filter reads.
