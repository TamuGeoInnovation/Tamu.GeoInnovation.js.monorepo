## Mapbox

- The map's container is now `viewChild.required`: it is the template's one element, created before `ngOnInit` reads it,
  as it already did. A new spec pins that the map is made in that element with the inputs as given; it **passed before
  the change and after**, which is the point of it.
- The four map inputs are typed `| undefined`, as they start; the service already defaults each.
- `createMap`'s options are required: its body always read them, and its one caller passes them.

## Esri: what each fix does to a map that works today

**Nothing, by design.** Esri had 60 own errors under its own configuration, about twice the laptop's 31 (which came from
the app's build, which reaches fewer of them). Because every map in the repository uses this library, I took the
strictest reading of "no behaviour change": where a value can only be missing in a state the code assumes never
happens, the read still fails exactly as it did, with a comment saying why the value is there. None of them is guarded
into doing something new. The body has the same table:

| Fix | On a working map |
| --- | --- |
| `currentMap` and `currentView` return exactly what the service holds, typed as set (`makeMap` and `useView` set them first) | The same objects |
| The private store typed with its `undefined` (before a map, after destroy); the public `store` already filtered it, and now its type says so | Nothing |
| Signed-in sources narrowed by the filter that already chose them; one helper, `credentialUrl`, for the two places that picked the URL inline | The same URL, by the same rule |
| `findLayerById`, `findLayerOrCreateFromSource`, `removeLayersById` and `createLayer` keep their public types, with a comment on each cast saying what a missing layer returns, which is what it returned | Nothing |
| `computeZoomLevel` typed `Promise<number \| undefined>`, as it behaves; `zoomTo`'s zoom was already optional | Nothing |
| `LayerProperties` an intersection, since under the flag an interface may not extend TileLayer's and WMSLayer's properties both | Types only |
| `EsriMapComponent`: `config` may be unset (`ngOnInit` already refuses it); elements read after a draw are the ones it rendered | Nothing |
| `PolygonEditorComponent`: `send` takes the `null` a create event can carry, which it already handled | Nothing |

**Two public types still say less than the truth**, on purpose, because widening them would reach into every map
library: `createLayer` (and so `generateLayer`) resolves `undefined` for a source type it does not know, and
`findLayerById` returns `undefined` for a missing layer, though both are typed as a layer. Both are commented where
they happen. Making them honest is a change to their callers, not to this library, and belongs with those callers'
own #3804 steps.
