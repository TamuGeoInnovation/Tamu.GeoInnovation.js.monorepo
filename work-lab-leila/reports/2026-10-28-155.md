## The new test failure, and the fix

In `test/smoke/aggiemap/services.spec.ts`:

```ts
const basemapRoots = [...new Map(basemaps.map(([constant, url]) => [serviceRoot(url), constant])).entries()];
```

**The lookup is one line:** a `Map` built that way keeps the last constant for each root. The test should find the raster basemap
by its own entry, not through the de-duplicated list. For example:

```ts
const raster = basemaps.find(([constant]) => constant === 'AggiemapRasterBasemap');
```

That uses `serviceRoot(raster[1])` for the request. Alternatively, `basemapRoots` could keep the **first** constant per root.

**It isn't a blocker.** The test shows an unrelated change can silently break its lookup, but the view limit itself is right today.
**Recommended:** its own small issue and pull request, Task, `testing`, Low. I haven't filed it or made the change: the batch said
report and stop.
