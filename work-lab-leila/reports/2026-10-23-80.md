## 2. The fix

- **`MarkdownParsePipe.transform` returns the HTML as a `string`.** It no longer injects `DomSanitizer`, so `[innerHTML]` sanitises it.
- **The return type changed from `SafeHtml` to `string`.** Every caller binds it with `[innerHTML]`, in templates only, so none needed a change.
  The full check built all four apps that render the pipe: `aggiemap-angular`, `gisday-angular`, `ts-events-angular` (dining) and
  `ues-operations-angular` (POI).
- **The old test** read the result back through `DomSanitizer.sanitize`. Given a plain string, that now encodes marked's trailing newline as
  `&#10;`, so the test reads the pipe's string directly. Its point is unchanged: the shape of an `<h1>`, not an exact string.
