## What this changes

Any new AggieMap event map needed someone to remember to add uptime monitors for the layers it depends on (#497).
Every map's definition already says which layers it draws, so the list now comes from there.

- **`scripts/event-map-monitors.mjs`** prints one row for each production layer every event map draws: the map, the
  layer, its production URL, a suggested monitor name and the keyword to match. Its options are `--json`, `--unique`
  (one row per URL, with every map that reads it, which is the list to build monitors from) and `--offline`. It creates
  and changes nothing in Kuma.
- **The keyword is the layer's own name**, read from the service. An ArcGIS layer answers HTTP 200 with the error in
  the body (#2510), so a monitor that only checks the status stays green on a broken layer. An error body never
  supplies a keyword.
- **`event-map-monitors.spec.ts`** loads every definition at a production address, so `Connections` resolves the
  URLs as it does for a visitor. It writes `scripts/event-map-layers.generated.json`, as `declared-layers.spec.ts`
  does for the smoke suite. A definition that changes a layer fails it until the file is rewritten with
  `nx test ts-events-ngx -u`. Production is never development with the host swapped: men's basketball is a
  different host and a different service on each.
- **Left out, with their reasons in the output:**
  - development-only maps;
  - retired maps, which `RetiredEventGuard` never shows (#1098) and whose services are often stopped;
  - layers in `DEVELOPMENT_ONLY_LAYER_SOURCES`;
  - `developmentSources`.
