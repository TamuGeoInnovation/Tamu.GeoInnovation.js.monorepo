## 1. Which was wrong: the component

**`SelectComponent` typed its value as `string`, and the value is not always a string.** Its options bind
`[ngValue]="getDataItemValue(item, valueTemplate())"`, so:
- **with a `valueTemplate`**, the value is that property of the chosen item;
- **without one**, it is **the item itself**.

**53 uses** of `<tamu-gisc-select>`: 52 pass a `valueTemplate`, and **one does not**. The layer filter's attribute list
(`libs/maps/feature/layer-filter/.../layer-filter.component.html:5`) has `(changed)="field.next($event)"`, where `field` is a
`Subject<esri.Field>` and it reads `field.type` and `field.name`. So that caller depends on the object.

The spec tested exactly that case: it set the value to an object and expected `changed` to emit it. **The spec was right and the type too
narrow.** (I first fixed the spec, then found the layer filter, and changed course before pushing.)

- **The fix:** the value, the `changed` output, `writeValue` and the change callback are typed **`T | string`**, `T` being the select's item
  type. A comment on the model says why.
- **The spec is unchanged** and now typechecks: `tsc -p libs/ui-kits/ngx/forms/tsconfig.spec.json --noEmit` exits **0**.
- **Every caller still compiles.** Every app compiles its templates with `strictTemplates: false`; only `mailroom-angular` is strict, and it does
  not use the select. **`scripts/check-in-volume.sh fix/2256-select-spec-types`** (affected, a superset of the `ui-kits-ngx-forms` check the
  batch asked for), finished before 1:48 AM Central: **exit 0**, *Successfully ran target lint for 27 projects*, *test for 25*, *build for 5
  projects and 3 tasks they depend on*.
