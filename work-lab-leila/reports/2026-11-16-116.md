## The change

`dashboard-people.component.scss`: the variables import, and a `thead th` rule, `position: sticky; top: 0; z-index: 1;
background: $background;`. With several groups in one box, each group's headings stay up while its own table is in view.

## Red first, then green

- **The spec:** `DashboardPeopleComponent › keeps each table's column headings at the top of the capped box as it scrolls`.
- **On the unfixed stylesheet** it failed: `Expected pattern: /position: sticky;/`, received `""`.
- **With the fix,** the dashboards' four shared spec files pass (43 tests).
- **What it proves:**
  - the rule is in the stylesheet;
  - every heading belongs to a table inside the capped box;
  - nothing sets an `overflow` that would make the table, rather than the box, scroll.
- **What it can't prove:** that the headings stick in a browser, since jsdom lays nothing out. The browser measured that.
