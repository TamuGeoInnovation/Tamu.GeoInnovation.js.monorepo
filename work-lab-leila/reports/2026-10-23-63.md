## 1. The change

- **One network per agent**, `tamu-agent-internal-<name>`, `--internal`, a **/28 of `172.31.251.0/24` picked from the name**, so it is the same at
  every start:

  | Name | Slot | Subnet | Proxy address |
  | --- | --- | --- | --- |
  | `<machine>-1` … `-12` | 1 … 12 | `172.31.251.16/28` … `.192/28` | `.18` … `.194` |
  | `<machine>-test`, `-test2`, `-test3` | 13, 14, 15 | `.208/28`, `.224/28`, `.240/28` | `.210`, `.226`, `.242` |

  Every other name is refused with a line saying which names work (`lab-0`, `lab-13`, `lab-test4`). Both scripts were tested on the same
  eight names and give the same slots.
- **A new range rather than slices of the old one**: Docker refuses a subnet that overlaps another, and the old shared network holds
  `172.31.250.0/24`.
- **The one proxy joins every agent's network** with its fixed address there. Agents are not on each other's networks.
- **`squid.conf`** accepts `172.31.251.0/24` **and** the old `172.31.250.0/24`, so an agent not yet reinstalled keeps working. **The old
  shared network removes itself**: before each job, if the proxy is on `tamu-agent-internal` and nothing else is, it disconnects and removes
  it.
- **Two bugs the test found, fixed:**
  - **Agents started together raced to create the proxy**, and the loser stopped. It happened on the first run, and two logon tasks would
    do the same. The loser now finds the proxy there and carries on, on both Windows and Linux.
  - **The same Windows PowerShell 5.1 trap as batch 68**: redirecting a native command's stderr under `Stop` ended the script. That call
    now runs under `Continue`.
