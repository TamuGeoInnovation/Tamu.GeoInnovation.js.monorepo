## 1. The change

In `templates/jobs/build.yml`, each of the three steps carries
`condition: and(succeeded(), ne(variables['System.PullRequest.IsFork'], 'True'))`, under a comment saying why:

| Step | Before | After |
| --- | --- | --- |
| `DownloadSecureFile@1` (`app_configs.zip`) | always | not on a fork pull request |
| `ExtractFiles@1` (into `$(Agent.TempDirectory)`) | always | not on a fork pull request |
| `CopyFiles@2` *Copy secrets* (`app_configs/**` into `$(System.DefaultWorkingDirectory)`) | always | not on a fork pull request |

On a branch build `System.PullRequest.IsFork` is unset, so `ne('', 'True')` holds and the steps run as before. On a pull request from this
repository it is `False`, so they run. Only a fork's pull request skips them. A YAML parse of the file lists each step with these conditions and
leaves the others unchanged.

**The rest of the pipeline, read in full** (`azure-pipelines.yml`, all six files under `templates/`), **has no other secure file and no secret
variable**. Two things come close; neither needs the condition:

- **`$(System.AccessToken)`** in `templates/jobs/deltaConfigure.yml` (the *Last SHA* job's `az pipelines build list`). This is the build's own
  job token, not a secret of ours. Azure gives fork builds a restricted, read-only one whatever the secrets setting, and the job only reads build
  history. Unchanged.
- **The Tag stage** already skips fork pull requests (`System.PullRequest.IsFork` is `False` in its condition). Unchanged.

**Not visible from the repository:** variables set on the pipeline in the Azure DevOps UI, and variable groups linked there. None is
referenced in the YAML. If any were marked secret, the fork setting would withhold them, and nothing in the YAML reads them.
