## 1. The change

- **24 builder names in the 8 Angular apps' `project.json`**: `@angular-devkit/build-angular:application`, `:dev-server` and **`:extract-i18n`**
  (the third the batch anticipated) → `@angular/build:` with the same name. `@angular/build` 22.2.3 (already a direct dependency, pinned like
  Angular 22.2) provides all three: its `builders.json` lists `application, dev-server, extract-i18n, karma, ng-packagr, unit-test`.
  **Nothing names `build-angular` any more.**
- **`@angular-devkit/build-angular` dropped.** In the lock it was needed only by two **optional** peers (`@analogjs/vite-plugin-angular`,
  `@nx/angular`).
- **`postcss-import` and `postcss-preset-env` dropped from `package.json`.** No file names either: no import, and no configuration file
  (`git grep` outside the lock and `package.json` finds nothing). **`postcss-import` stays in the lock as `@nx/webpack`'s own dependency**
  (`~14.1.0`); `postcss-preset-env` and its plugins go.
- **`webpack` becomes a direct dev dependency**, `^5.111.0`, the version already installed. This was not in the batch. **Without it**, removing
  `build-angular` left `webpack` installed only as a *peer* (`"peer": true` in the lock), because `build-angular` was what depended on it. The API
  builds (`webpack-cli` through `@nx/webpack`, batch 50) need it. `npm ci` installs peers by default, but `--omit=peer` or a change of npm default
  would break every API build without a word, so I made it explicit.
