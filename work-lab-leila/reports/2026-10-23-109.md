## 2. The fixes

**The tests**, keeping each assertion able to fail:
- **The null reads** use `?.`. The kiosk spec, which destructures `configuration` and `sources`, now first asserts that both exist, so a later
  `toBeUndefined()` cannot pass on a missing configuration.
- **The `never` subjects** are made as the typed object and then given their stand-ins with `Object.assign(subject, {…})`. The result type is
  no longer used, so the class's private members never meet the stand-ins. Run time is identical. `search-sources`' private `env` is assigned
  through a cast, the idiom that file already uses on the very next line.
- **`url`** is read only where `'url' in source`, with a small `urlOf` in the micromobility spec.
- **The rest:**
  - `popupData?.['name']`;
  - `effect.conversions ?? []`;
  - the subscription's variable is typed `| undefined`;
  - the dismissal helper accepts `null`;
  - the overrides spec uses `title`, a real `LayerSource` property, for the same remove/keep checks;
  - the GLightbox mock declares its options argument (its spec's cast went with it);
  - the basemap spec returns early after its `toBeInstanceOf` checks, which is what TypeScript needed to narrow.

**The code: what each does at run time, and whether a user could see it.** All are type-only, and no user sees any of them:

| Line | At run time today | Visible? | Fix |
| --- | --- | --- | --- |
| both `map.component.ts`, `isMobile`/`threeDLayers` | they start `undefined` until the first breakpoint or the 3D layers arrive, and the code already treats `undefined` as "not yet" | no | `signal<… \| undefined>(undefined)` |
| `markdown-popup`, `markdown-w-directions-popup`: `this.data.layer.title` | it would throw if a feature had no `name` **and** no layer. Every popup here opens from a feature on a layer, so I could not make it happen from the UI | no (not reachable) | `this.data?.layer?.title`, a guard, not a behaviour change |
| `campus-building-popup`: the fallback title | a structure with no name falls back to the layer's title. ArcGIS types it `string \| null`, while the content's title is `string \| undefined`. Either way the heading is drawn the same | no | `?? undefined` |
| `aggiemap-ngx-common/definitions.ts:5` | a type-only re-export. The app's own settings do not use `isolatedModules`, so it builds and runs the same | no | `export type { … }` |
| `basemaps.definition.ts`: `AggiemapRasterBasemap.id` | always set; only its declared type said it might not be | no | typed `BaseMapProperties & { id: string }` |
