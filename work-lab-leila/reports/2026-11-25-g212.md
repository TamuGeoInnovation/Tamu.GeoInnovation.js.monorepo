## 3. The fixes (no `!`, no casts, no caller changed)

**Types now admit what already flows through them:**
- **24 `input`s and `model`s** declared with an `undefined` or `null` start now say so in their type, for example
  `input<string | undefined>(undefined)`.
  - **Why callers are unaffected:** they pass exactly what they did, since a wider input accepts it.
- **The value accessors:** `AbstractValueAccessorFormComponent`, `SelectComponent` and `RadioGroupComponent` and its
  `SlideToggleComponent`.
  - their `value` setters, `writeValue` and change callbacks take the `null` a form writes and the `undefined` a
    cleared control holds, which they already turned into `undefined`;
  - the radio group's `onInitialValue` and `renderTemplate`, and the slide toggle's override, take the `undefined`
    they already handle.
- **Outputs that emit `undefined`:** `FileComponent.fileSelected` now says `File | undefined` (it emits `undefined` on
  reset), and `SelectComponent.changed` says `T | string | undefined` (it emits `undefined` once cleared).
- **`getPropertyValue`** in `common-utils-object` takes `object | null | undefined` and `string | null | undefined`,
  which it already answers `undefined` for. That's a wider parameter, so every caller still compiles.

**Smaller ones:**
- **The date-time picker's tooltip** is `viewChild.required`: it's the root of its template, never behind an `@if`. Its
  value model says `Date | null`, which it already set.
- **`setDisabledState(disabled: boolean)`** on the checkbox: the forms API always passes one, and no caller omits it.
- **The file input's extension:** `pop()?.toLowerCase() ?? 'unkown'`, the same result, since `split` always gives one
  part. The `unkown` typo is kept, as callers may compare it.
- **The textbox's delayed autofocus** uses `?.`, and the select list reads its search fields once.
- **The range's arithmetic** reads a private `numericValue`, `NaN` with no value. That's what arithmetic on `undefined`
  gave, so its tooltip offset, direction and bound check are unchanged. Its `value` getter now says `number | undefined`.

## Two behaviours change, on paths that threw before (step 5: red first)

| Spec | On the old code | Now |
| --- | --- | --- |
| **Range, with `showTooltip`:** takes the form value it starts with before its tooltip is drawn | `TypeError: Cannot read properties of undefined (reading 'nativeElement')` | passes |
| the same: shows each value set after that in its tooltip | the same `TypeError` | passes |
| **Select list, no options yet:** answers a search with no matches | `TypeError: Cannot read properties of undefined (reading 'filter')` | passes |

- **The range:** a reactive form writes its first value in the directive's `ngOnChanges`, before the slider's view is
  drawn, and the setter wrote into the tooltip's `<output>`, which didn't exist yet.
  - **Where it applies:** **Geoservices' pricing slider** has `[showTooltip]="true"` on a `formControlName`, so this has
    probably been throwing there on every load. The tooltip now waits until it's drawn.
  - **A note on the spec:** jsdom has no `innerText`, so the spec reads the property the component writes, with a
    comment saying so.
- **The select list:** before its `[options]` arrive, a search threw. It now searches an empty list.
  - **What's on screen:** its template tests `(options$ | async)?.length > 0`, which is the same for `undefined` and
    `[]`. So it shows "No items to show…" exactly as before, without the error.
