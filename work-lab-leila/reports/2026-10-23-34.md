## 3. The five fixes, as the rules intend

All four `preserve-caught-error` sites throw a plain `Error`, never a Nest `HttpException`, so `new Error(msg, { cause })` (ES2022) is
the form. Every project's TypeScript `lib` includes `esnext`, so it typechecks. A runtime without `cause` support ignores the
second argument.

```diff
--- libs/common/node/fs/src/lib/common-node-fs.ts:64
-    throw new Error(`Error writing file to disk. ${error.message}`);
+    throw new Error(`Error writing file to disk. ${error.message}`, { cause: error });

--- libs/maps/feature/trip-planner/src/lib/services/trip-planner.service.ts:1240
-      throw new Error(err);
+      throw new Error(err, { cause: err });

--- libs/gisday/platform/data-api/src/lib/assets/assets.service.ts:58
-      throw new Error('Could not save asset.');
+      throw new Error('Could not save asset.', { cause: err });

--- libs/ts/events/ngx/src/lib/services/settings/event-settings.service.ts:313
-      throw new Error((err as Error)['message']);
+      throw new Error((err as Error)['message'], { cause: err });

--- libs/gisday/competitions/data-api/src/lib/export/export.processor.ts:114   (no-useless-assignment)
-        let formValues = {};
+        let formValues: object;
```

On the last one, the `{}` was never read: the `try` assigns `formValues` and the `catch` assigns `{}`, so every path assigns it
before the spread that uses it. The annotation keeps its type, since `let formValues;` alone would make it `any`. The messages and
behavior of the other four are unchanged; each error now also carries what caused it.
