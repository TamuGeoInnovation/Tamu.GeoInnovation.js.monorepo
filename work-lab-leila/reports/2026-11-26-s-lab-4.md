**Why `basemapUrl` isn't ArcGIS's, though it passed on `development`:**
- **What the check does:** it asks the GIS server directly through Playwright's `request` (`services.spec.ts:86`,
  `:274`). It never opens a page, so it never loads ArcGIS's JavaScript.
- **Identical on both builds:** the branch doesn't change `connections.ts`, `services.spec.ts` or `service-layers.ts`
  against `development` (the diff is empty). So both builds send the same queries to the same server, and the ArcGIS
  version can't affect the answer.

  answers, which were refusals. `TAMU_Basemap_20261008` layer 4 (16,212 features) said "Pagination is not supported",
  and layer 5 (94,007 features) said "Failed to execute query", past their `maxRecordCount` of 2,000.
- **On `development`, a few minutes later:** the same layer paged, and the check passed.
- **It's recurring:** this layer timed out in a59 and a65 too.

## A finding, not filed

The `local` environment fails two checks on every build: the build banner, and NCAA Volleyball's development host. So a
local release tier can never be fully green, and someone has to sort these out by hand each time, as here and in the
laptop's s10. The fix would be an allowance for each on `local`, as `development` and `production` have for theirs. I
haven't filed it; the security chat or the maintainer may want an issue.
