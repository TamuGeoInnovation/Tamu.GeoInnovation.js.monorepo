## The cause, measured in the browser (`3cb0c6d3f`, season 2025)

| Case | Box client / scroll width | Table width | Rail |
| --- | --- | --- | --- |
| RSVPs, fresh at 1024 | 669 / 669 | 796 | none |
| RSVPs, 1280 resized to 1024 | 669 / 669 | 796 | none |
| Check-ins, fresh at 1024 | 669 / 669 | 871 | none |
| Check-ins, loaded at 1280 | 867 / 867 | 871 | **none, the last column cut by 5 px** |
| Check-ins, 1280 resized to 1024 | 669 / 669 | 871 | none |

**Neither suspect was it:**
- **ngx-datatable did recompute** on the resize. RSVPs' columns shrank to their minimums, with one `recalculateColumns()`.
- **The scroll box did see the resize:** its `ResizeObserver` fired, and `measure()` ran twice.

**The real cause:** the table's frame, the shared `.datatable-container` (`overflow: hidden`), was only as wide as the box,
and clipped the table. So `measure()` never saw anything wider. Before #3121 that frame was itself what scrolled. #3121
moved the scrolling to `tamu-gisc-dashboard-scroll`, and left the frame clipping.

**Proof:** with only that clip removed, by an injected style, every case drew the rail, and the rail reached the last column.

**Batches 104 and 105** measured the markup from before #3121, which is why fresh at 1024 worked then.

## The fix (`dashboard-table.component.html`, `dashboard-scroll.component.*`)

- **The frame** takes the table's minimum width as its `min-width`, so the box scrolls the whole table.
- **On a width change,** `DashboardScrollComponent` waits until 250 ms after the last change, then measures the rail again. A
  content-only change, or the first observation, measures at once.
- **The spinner:** while it waits, the box is veiled and the spinner shows over it.
  - **Where I looked:** `libs/ui-kits/ngx/**` has only `tamu-gisc-page-loader`, a full-window splash for first load, and
    `libs/common/**` has nothing.
  - **What's reused:** the site's global `.loader small` (`apps/gisday-angular/src/styles.scss`, used in 14 GIS Day
    templates), with the shared `flex flex-row justify-center` classes.
  - **The only new CSS** is the overlay's position, in the component's own stylesheet.
- **About the 250 ms:** that's the maintainer's spinner plus robustness, not the bug itself; the clip was the whole cause.
  The PR body says so.
