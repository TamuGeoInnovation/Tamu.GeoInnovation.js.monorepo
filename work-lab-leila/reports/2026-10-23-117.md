## 2. Production: is the vulnerable code reachable from ours?

**1 and 2, `got` 9 and `jose` 1 under `openid-client` 3: not reachable from anything deployed. Very sure.**
- **No API image contains `openid-client`.** The four images' generated `package.json`s, from batch 123's production builds, list no
  `openid-client`, `jose` or old `got`. `npm prune` removes it from each image.
- **Its only users** are `libs/oidc/client`, `libs/ues/common/nest` and **`ues-operations-nest`**, which CI excludes and nothing builds or
  deploys.
- **No front end imports it:** `libs/common/ngx/auth` names `@tamu-gisc/oidc/client` only in its README.
- So "production" here is npm's view of the root lock, not what ships. If `ues-operations-nest` were deployed, #1 would matter only if a token
  endpoint we call redirected to a UNIX socket, and #2 only if it decrypted a hostile JWE.

**3, `uuid` 8.3.2 under `bull`: not reachable. Very sure.**
- The flaw needs the **`buf` argument** of `v3`, `v5` or `v6`. **`bull` calls only `uuid.v4()`, with no arguments**: `lib/queue.js:120`
  (`this.token = uuid.v4()`), `:1412`, and `lib/timer-manager.js:74`. No code of ours imports `uuid` 8.
- It is in **gisday-nest's image** (`bull` 4.16.5, `@nestjs/bull` 12.0.0).

**`accepted-advisories.json`** gates only **high and critical**: the daily scan and the publish gate compare `npm audit` and Trivy at those
levels. So none of these moderate or low advisories needs an entry to keep the scan quiet. An entry would only record the reasoning, and the
file's comments describe it as the record of what the scans report. **Recommendation:** record the reasoning in #2111, not in the file.

## 3. The lists

**Fix now**
- **#3 `uuid` under `bull`: a scoped override, `"bull": { "uuid": "11.1.1" }`.** It removes the only moderate in a deployed image. It is cheap:
  `uuid` 11 still serves `require('uuid').v4()`, so `bull` is unaffected, and 11.1.1 is already in the lock (`auth0-legacy` and `auth0` use it).
  Proof needed: gisday-nest's image starts, and a Bull queue adds and runs a job, against the local Redis. **About 30 minutes as a listener
  batch.**

- **#1 `got` 9.6.0 and #2 `jose` 1.28.2**, both under `openid-client` 3, used only by `ues-operations-nest`, which nothing deploys. They go
