## 2. The upgrade

- **`^6.1.3` → `^14.0.1`.** The lock, by batch 41's method, key by key:
  - `ngx-highlightjs` 6.1.3 → 14.0.1;
  - **`highlightjs-line-numbers.js` 2.9.0 removed**: 14 brings its own line numbers;
  - the root's range.

  `highlight.js` stays at 11.11.1.
- **Set up once, as before**, in `apps/geoservices-angular/src/main.ts`: `HIGHLIGHT_OPTIONS` became **`provideHighlightOptions`**. It loads the same
  lazy core, the **same three languages, lazy-loaded as before** (xml, json, javascript), and line numbers from `ngx-highlightjs/line-numbers`.
  **The same theme**: the global `highlight.js/styles/atom-one-dark.css`, untouched (the code background is `rgb(40, 44, 52)` before and after).
  No other module sets highlighting up, so the reuse rule needed nothing more.
- **Directives:** 6's `[highlight]` auto-detected the language; in 14 that is **`[highlightAuto]`**, and line numbers are their own directive
  (`lineNumbers`, `HighlightLineNumbers`). Changed in the response viewer, the implementations page and the code runner. `codeFromUrl` stays in
  `ngx-highlightjs/plus`.
- **Found by reading 6's source: the whole app got its `HttpClient` from ngx-highlightjs.** 6's `HighlightPlusModule`, imported at the root, imports
  `HttpClientModule`, and nothing else in geoservices provides it. `AuthService` and the `AuthInterceptor` depend on it. 14's module does not
  import it, so **`main.ts` now says so itself**: `provideHttpClient(withInterceptorsFromDi())`, with a comment. Without this, every request in the
  app would have failed to inject.
- **The code runner's spec** imported `HighlightPlusModule` (for that same `HttpClient`). In 14 the directives need `HIGHLIGHT_OPTIONS`. The first
  full check failed there with *NG0201: No provider found for HIGHLIGHT_OPTIONS*, so the spec now provides the options the app uses.
