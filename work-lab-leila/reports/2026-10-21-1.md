## The cause: two lookups, not one

The batch's hypothesis was a race inside `EventService`. It is a race between two services.

- `EsriMapService.useView()` (`libs/maps/esri`) selects a link's feature itself as soon as the map's layers are
  added, from the application's `SearchSources` (College Station's lots), through `selectFeaturesFromUrl()`.
- `EventService` looks for the same link among the event map's own layers once it has drawn them.

Both select, and the last answer wins. So the fix had to be partly in the shared map library, not only
`EventService`: `EsriMapService` gains `selectsFeaturesFromUrlOnLoad` (default `true`, so every other map is
unchanged), `EventService` turns it off when it is made, and calls `selectFeaturesFromUrl()` itself only when the
map's own layers do not have the feature or cannot be asked. #1952's and #1954's code is untouched.
