## What I tried, in order

**1. The batch's approach: `npm ci --omit=dev` from the root pair, then the generated `package.json`, then `npm prune
--omit=dev`.** In the image's builder stage, from the build output plus `root-package.json` and `root-package-lock.json`. It
built for all four, and `geoservices-nest` was exact (222 of 222). But **`gisday-nest`'s prune also *added* 2 packages**, and
the version check found three images carrying copies the root lock does not have: `node_modules/@types/got/node_modules/form-data@2.5.6`
(three images) and `node_modules/auth0/node_modules/form-data@3.0.5` (`gisday-nest`).

**Why:** the root `package.json` has `"overrides": { "form-data": "$form-data" }`, which pins every `form-data` to the root's
own 4.0.6 (`npm ls form-data` at the root shows every copy `4.0.6 deduped`). **Nx's generated `package.json` keeps only the
`better-sqlite3` override and drops that one**, so prune saw `auth0` (`^3.0.1`) and `@types/got` (`^2.5.0`) asking for old majors
and fetched them from the registry. These are the same copies batch 31's `npm ci` reported missing. **It was the missing
override, not the root lock**, so this is a gap in approach 1, not a reason for approach 2.

**1, completed: put the root's `overrides` back into the app's `package.json` before pruning** (one `node -e` line). Then prune only
removed, for all four, and every package matched the root lock.

**And the driver, as you foresaw:** `gisday-nest`'s real start then failed with `DriverPackageNotInstalledError: SQL Server package
has not been found installed. Please run "npm install mssql".` TypeORM loads its driver by name, so Nx cannot see it, and prune had
removed `mssql`. **Batch 31's step 5 remedy, applied:** `apps/gisday-nest/package.json` and `apps/mailroom-nest/package.json`, each
`{ "name": "<app>", "dependencies": { "mssql": "^11.0.1" } }` (the root's range). Those are the two APIs that connect through
TypeORM; `geoservices-nest` and `mailroom-helper-nest` do not. Nx merged them into the generated `package.json`, `mssql` and
`tedious` are in both images, and the real start then passed.

**A false start worth knowing about:** my first rebuild after changing the Dockerfile still used the old one. `docker build` reads
`dist/apps/<app>/Dockerfile`, which the Nx build copied there earlier, not `apps/<app>/src/Dockerfile`. I copied the new one in,
and checked from then on that the two match. In CI the build always copies the current one, so this is only a local trap.
