## 1. #2771: the escape fixed, and what it was hiding

**The fault:** line 270's `not.toHaveClass(/<BS>visible<BS>/)` used two literal U+0008 characters. Checked in Node, that
pattern matches none of `layer-item visible`, `layer-item` or `layer-item invisible`, so the assertion always passed.
It's now `/\bvisible\b/`, which matches the first only, as the two assertions above it already do.

**What it was hiding: nothing.** The corrected test ("a layer that loads hidden is listed once it is switched on in the
Layers list, and leaves once switched off") **passed on development and on production**. In it, Visitor Parking and
Construction Zones are each switched on, then off, then on again. So the legend's "on" state does follow a layer
switched off. The check was empty, and the behaviour it was meant to watch was fine.

**How it was fixed:** by a script, after two attempts that didn't change the file:
- The shell collapsed `\\` to `\`.
- In JavaScript `'\b'` is itself a backspace, so the first script replaced a backspace with a backspace.

I mention it because it's exactly how a fault like this gets written: an escape that means one thing in a regular
expression literal and another in a string. The fix builds the backslash from its character code. `cat -v` and a count
of U+0008 confirm none is left.

## The rest of the suite, and whether a check could catch this class

**Others:** none in source. `git grep -I -l -P '[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]'` over every tracked file finds, after
this fix, only nine Illustrator logo sources (`apps/gisday-angular/src/assets/images/logos/<year>/logo/tamu-block-logo-source.ai`,
2019 to 2027). They're binary design files that git reads as text, and nobody edits them as text.

**A general check: what I think, not built.**
- **ESLint already knows this fault.** Pointed at the old `legend.spec.ts` with the repository's own configuration, it
  reports `270:92 error Unexpected control character(s) in regular expression: \x08, \x08 no-control-regex`.
- **The smoke suite is never linted.** It isn't an Nx project, and `lint.yml` runs `nx affected:lint` on projects only;
  the suite gets `tsc` and nothing else.
- **Linting the whole suite in one ESLint run** with the root configuration trips Nx's module-boundaries plugin ("please
  open an issue on nrwl/nx"), because the files belong to no project. So "lint the suite" is a small project of its own,
  and would bring up whatever else the suite has never been linted for.
- **The cheaper, narrower option:** one `lint.yml` step that fails on a control character in any tracked text file,
  excluding `*.ai`. That's the `git grep` above, about a second to run. It catches this class everywhere, not only in
  regular expressions, for any language.
- **My recommendation: the `git grep` step now**, as its own small change if you want it. Linting the suite with ESLint
  is worth an issue, but it's a bigger question than #2771.
