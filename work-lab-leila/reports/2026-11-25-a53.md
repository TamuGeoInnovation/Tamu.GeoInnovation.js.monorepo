## What changed

- **The helper:** `libs/maps/esri/src/lib/watch-as-observable.ts` adds `watchAsObservable(reactiveUtils, read)`,
  exported from the library's index beside `viewEvent`.
- **The handle, in one place:** `add` returns `reactiveUtils.watch(read, handler)`, and `remove` receives that same
  handle from `fromEventPattern` and calls `handle?.remove()`.
- **`startWith` stays with the callers:** the helper emits on a change only. The layer list still starts from `-1` and
  the legend from `undefined`, as before.
- **The pair, in both doc comments:** `watchAsObservable` names `arcgisSignal` as its other half, and `arcgisSignal`
  gains a paragraph naming `watchAsObservable`. Each says to pick by need: an observable to pipe, or a signal for a
  template.
- **The two services:** `LayerListService` and `LegendService` call the helper. Their watched expressions and their
  #1939 and #1857 comments are unchanged, and their `fromEventPattern` imports are gone.

**One change from the issue's shape: `reactiveUtils` is an argument.** The issue wrote `watchAsObservable(read)`.
`reactiveUtils` is an ArcGIS module both callers already load through `EsriModuleProviderService` beside their view
models. Loading it again inside the helper would add a second, asynchronous load to each call. Taking it as an argument
matches how `viewEvent` takes the view.

**One thing the issue didn't name, found by a test.** My first draft kept the handle in one variable, as `viewEvent`
does. With two subscribers to the same observable, the first unsubscribe then removes the **second** one's handle and
leaves its own registered. The helper now takes the handle `fromEventPattern` passes to `remove`, so each subscription
removes its own.

## What this changes

This is the second half of #3493. PR 3603 replaced the hand-written `fromEventPattern` wrappers around `view.on(...)`
with `viewEvent`. The same shape was still written around `reactiveUtils.watch(...)` in the layer list and the legend.
Both called `handle.remove()` without checking the handle existed, so a subscription that ended before ArcGIS handed one
over threw.

- **`watchAsObservable(reactiveUtils, read)`** sits in `libs/maps/esri`, beside `viewEvent` and `arcgisSignal`.
  - **The handle:** each subscription removes its own handle, because `fromEventPattern` hands `remove` whatever `add`
    returned. An absent handle is skipped.
  - **`reactiveUtils` is passed in:** callers load it through `EsriModuleProviderService` with their other modules,
    so the helper doesn't load it again.
  - **The first value stays with the callers:** the helper emits on a change only, and each caller adds its own
    `startWith` (`-1` and `undefined`).
- **`LayerListService` and `LegendService`** use it. Their watched expressions and their comments (#1939, #1857) are
  unchanged.
- **The pair:** the doc comments of `watchAsObservable` and `arcgisSignal` each name the other, so the next caller picks
  by what it needs: an observable to pipe, or a signal to read in a template.
