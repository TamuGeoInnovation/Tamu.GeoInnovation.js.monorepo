## 3. The change

In `restore`, after the login is created and mapped:

```bash
    # A backup is only as new as the schema it was taken at, and the seed predates the newest migrations: without this,
    # the API answered 500 on the sponsors and on a season day's events until someone ran `migrate run` (#2196).
    migration "$DB_NAME" run
    echo "Restored $bak into $DB_NAME, mapped gisday_app, and ran the migrations."
```

`migration "$DB_NAME" run` is **exactly what `migrate run` calls** (`migrate)` → `migration "$DB_NAME" "$step"`), so it runs with the
same settings: as `sa`, on `gisday-nest-eh`, from `tamu-js-dev-nm`, with the password staying in the container. It applies to a
production backup restored by name too, which is what you want: any backup older than the code needs the same.

**The test**, three new checks in `scripts/gisday-local.test.sh`. They run `restore` against its stand-in `docker`, with a settings
folder of its own holding an empty `local-db.env`: it restores the database; it then runs `nx.js run ... gisday-nest:migration-run` with
`-e TYPEORM_DATABASE=gisday-nest-eh`; and that call comes after `RESTORE DATABASE`.
