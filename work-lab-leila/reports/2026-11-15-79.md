## What changed

- **The entity:** `EventBroadcast.place` is a nullable link to `Place`, as a venue's is.
- **The migration, `AddBroadcastPlace1794772810966`:**
  - `up` adds `event_broadcast.placeGuid` (nullable) and its foreign key to `places`;
  - `down` drops the key, then the column. That's the exact reverse, checked by hand.
- **The API:** the broadcast reads return the place. The routes stay admin-only (#3054).
- **There's no API-side site filter.** The page filters, as Admin, Events does, so an admin can switch to every
  organization's.
- **The shared rule:** `siteListsPlace(site, place)` in `libs/gisday/common` is the existing body of `siteListsSession`,
  which now calls it. So there's one filter, used by both pages.
- **A broadcast's admin page:** "Select organization" is the first field. It's required, as a venue's is.
- **Admin, Broadcasts:**
  - On gisday.tamu.edu it lists Texas A&M's broadcasts plus any with no organization yet.
  - It adds an Organization column, and a "Show every organization's broadcasts" switch.
  - txgisday.org and UCGIS list them all.
- **An event's Broadcast drop-down** uses the same rule. It always keeps the event's current broadcast, so opening an
  event never drops it.
- **Copying broadcasts to another season** doesn't carry the place, as with venues, because places belong to a season.
