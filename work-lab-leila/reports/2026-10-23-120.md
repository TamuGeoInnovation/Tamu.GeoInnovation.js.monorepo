## Why `chore/1218-better-sqlite3-13` stopped: npm needs an entry my report 127 called stale

- **Step 3 said to remove `better-sqlite3`'s `allowScripts` entry,** and `install-scripts.mjs` agreed: *Not installed any more, so these
  entries can go … better-sqlite3*.
- **I removed it (`5e914fd66`) and the check's `npm ci` refused to install:**
  ```
  npm error code ESTRICTALLOWSCRIPTS
  npm error --strict-allow-scripts: 1 package(s) have install scripts not covered by allowScripts:
  npm error   better-sqlite3@13.0.3 (install: node-gyp rebuild)
  ```
- **Why:**
  - 13.0.3 has no install script in its `scripts`, and the lock records none (`hasInstallScript` absent);
  - **but it still ships a `binding.gyp`**, and npm treats any `binding.gyp` as an implicit `install: node-gyp rebuild`;
  - 13.0.3's `package.json` sets **`"gypfile": false`**, which is meant to stop exactly that, **but npm 11.19's strict policy flags it
    anyway**;
  - the lock-based check cannot see `binding.gyp` at all.
- **So report 127's "13 has no install script, so its entry becomes stale" was wrong for npm's own policy.** It is right for the lock, which is
  what our check reads.

**Tried, not committed:**
- the lock and `.npmrc` of `5e914fd66`, but with the entry as **`"better-sqlite3": false`** (denied) instead of removed;
- then a clean `npm ci --omit=dev` in `node:24.22.1`.

The result:
- **`npm ci` passes**, exit 0, with no `ESTRICTALLOWSCRIPTS;
- **no `node-gyp` build runs**;
- **`better-sqlite3` loads its own prebuilt binary** (SQLite 3.53.4).

So **a denial is the right entry**: we want the shipped binary, never a build. It is also the honest one. The old `true` would now allow a
`node-gyp` build we do not want.

**What blocks it:** `install-scripts.mjs` reports **any** entry whose package has no `hasInstallScript` in the lock as *Not installed any
more*. That includes a denial for a package that is installed but whose only "script" is npm's implicit `binding.gyp` one. The check only
reports this and still exits 0, but step 3 asks for no stale entries, which the right entry cannot give.
