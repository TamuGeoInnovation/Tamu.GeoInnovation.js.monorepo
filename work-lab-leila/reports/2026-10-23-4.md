## Things worth knowing before this is pushed

- **Clone it with `core.autocrlf=false` on Windows.** This machine has `core.autocrlf=true`, and my first clone checked
  `entrypoint.sh` and `tokenSubstitute.sh` out with CRLF endings (the repository stores LF). An image built from that
  copy would have a broken `#!/bin/bash\r` entrypoint. I caught it before testing and rebuilt from an LF clone; every
  result above is from the LF one. The repository has no `.gitattributes`; one with `*.sh text eol=lf` would stop this
  for everyone.
- **The workflow's last line ends with a stray backtick**: `labels: ${{ steps.meta.outputs.labels }}``. The published images
  build, so it is evidently tolerated, but it belongs in the same commit.
- **`tokenSubstitute.sh` only processes files at the top of `FILES_DIR`**, not `assets/`. That is fine today, since every
  placeholder is in a top-level `*.html` or `*.js`, but a token placed under `assets/` would never be replaced.
