## Why, and it is the repository's problem as much as knip's

knip's Jest plugin evaluates each Jest config it finds. The root one is:

```js
const { getJestProjects } = require('@nx/jest');

module.exports = {
  projects: [...getJestProjects()]
};
```

In this checkout's own install, `@nx/jest` is **23.3.0**, and:

```
getJestProjects: undefined | getJestProjectsAsync: function
```

So **the root `jest.config.ts` cannot be loaded at all** under the Nx this repository installs: `getJestProjects()` is
`undefined()`. It was last changed in #1465 (the upgrade to Nx 22), and Nx 23 seems to have dropped the synchronous helper in
favour of `getJestProjectsAsync`. Nothing in CI notices, because `nx test` uses each project's own Jest config and never
loads the root one. But anything that does load it fails the same way: knip, running `jest` from the root, or an editor's
Jest extension.
