## The route approach: it holds up, and here is what it took

**Your three questions:**

1. **Can a Discover entry point at an arbitrary route? Not before this.**
   - **What I found:** `getApplicationRoute` built `/<type>/<id>`. Every internal entry came from an event definition
     (`DiscoveryService.getInternalDiscoverApplications` maps `EventDefinitions`), and each carried that definition as
     `configuration`.
   - **What I added:**
     - type **`'main-map'`** and an optional **`route`** on `InternalDiscoverApplication`, which `getApplicationRoute`
       returns as is;
     - **`configuration` optional**, because such an entry has no definition. Its only three readers are the event-date
       code for Upcoming Events, and they now take a missing one into account;
     - **`MainMapDiscoverApplications`**, a small list beside `ExternalDiscoverApplications`, holding the bus map.
       `DiscoveryService` lists it after the definitions' maps.
   - **Where that puts it:** under Transportation, and in All Maps' search. Not in All Events (campus and athletics
     only), not in Upcoming Events (no dates), not on Parking.
2. **Does the route open the bus panel, and does leaving it behave? Yes.**
   - `/map/d/bus` opens the main map with all 23 routes listed.
   - Back returns to Transportation, Forward reopens the panel, and the Features panel replaces it as on any visit.
3. **Does it need different framing? No.**
   - It opens at the campus framing, and a list of routes needs nothing more.
   - **Choosing a route already zooms to fit it:** route 47 goes from zoom 16, centred on campus, to zoom 12, out to
     RELLIS.
   - **Existing, not this change:** that fit doesn't allow for the side panel, so the far end of a long route can sit
     behind it; route 47's campus end does at 1280 wide. It's the bus panel's own behaviour, the same from `/map`. I'd
     file it separately if you want it fixed.

**Why it's not ugly:** the cost is one optional field and one type value, plus `?.` in three places. The next main-map
panel listed as a map (directions, say) is one entry in the same list.

**One cosmetic thing:** All Maps' search shows each result's type in capitals, so the bus map's chip reads **"MAIN-MAP"**
where others read "PARKING" or "EVENT". It's consistent but plain. A label map would be a separate small change; I left
it.

**The gate:** `visible: false`, the structural gate, per #2753. The Transportation page already applies it with
`TestingService.isTesting`, as for the development-only campuses. Nothing here reads a service, so no build-time
exclusion.

## The smoke suite

- **The crawl:** `MAP_ROUTE` in `global-setup.ts` accepts `/map/d/<panel>`, and the detail pages' link selector includes
  `a[href^="/map/d/"]`. So the crawl **finds and loads the bus map**, the issue's last point. It found 83 maps on local,
  `/map/d/bus` among them. A new exported `isMainMapPanel()` names the rule.
- **`map-layers.spec.ts` leaves main-map panels to `/map`.**
  - Its first run on `/map/d/bus` failed "layers the map holds that the Layers list does not". The bus panel replaces
    the Features panel, whose Layers list that test reads.
  - The layers are the main map's, already checked at `/map`, so checking them again from a page that can't show them
    is wrong. The bus content itself is `bus.spec.ts`'s.
- **`DEVELOPMENT_ONLY_CONTROLS`** gains the entry: the selector `a.map-entry[href="/map/d/bus"]` on
  `/all-maps/transportation`, required on dev and forbidden on production.
  - **Why that list:** `DEVELOPMENT_ONLY_SECTIONS` covers only the sidebar tab, the entry has no service of its own for
    `DEVELOPMENT_ONLY_SERVICES`, and `DEVELOPMENT_ONLY_ALL_MAPS_TILES` is the Visit Maps row. The comment says why.
- **`framing.spec.ts`** skips it ("not in framing-baseline.json"), as for any development-only map; production's
  baseline can't have it.
- **A wrong turn I corrected:** my first smoke run served the `development` configuration at `localhost`. There,
  `maps.spec` failed `/map/d/bus` on the dev GIS server's missing services, which the `local` environment doesn't
  expect. On the default serve, the one `local` describes, it passes, as `/map` does.
