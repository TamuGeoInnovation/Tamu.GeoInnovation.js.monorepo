## The regression: the class banner on an existing photo

| | Before (`f45cd01ed`) | After (`778db5e8c`) |
| --- | --- | --- |
| Admin, Speakers, edit an existing speaker with a photo, Louisiana State University and 2026 | **"LSU '26"** on the photo | the banner element is there but **empty**: no banner |
| Speakers, Add: Texas A&M University and 2027 set, **then** a picture chosen | (no banner on the strip; the old bug) | **no banner** on the chosen photo, until a field is changed again (then *TAMU '28* appears) |

The two pictures are in `work-lab-leila/reports/2026-10-30-163/` (`before-speaker-edit.png`, `after-speaker-edit.png`). The seed
has no years, so for this I gave that speaker a year in the throwaway database.

**The cause** is in `speaker-add-edit-form.component.ts`:

```ts
this.bannerSpeaker$ = combineLatest([
  this.form.valueChanges.pipe(startWith(this.form.getRawValue())),
  this.universities$.pipe(startWith([] as Array<Partial<University>>))
]).pipe(map(...));
```

- **`startWith(this.form.getRawValue())` reads the form once, in `ngOnInit`, while it is still empty.**
- Before PR 2570, the banner was always in the template, so it subscribed at once and saw every later change.
- Now it sits inside `@if (photo.showing())`, so it's **created later**: when the saved photo arrives on the edit page, or when a
  file is chosen. It then subscribes and gets the empty starting value, with no university.
- The banner stays blank until the next `valueChanges`.

**A fix:** make the starting value lazy, so each new subscriber reads the form as it is then:

```ts
this.form.valueChanges.pipe(startWith(undefined), map(() => this.form.getRawValue()))
```

Other fixes would work too: `defer(() => …)`, or `shareReplay(1)` on the whole stream. A unit test would create the banner after
`patchValue` (the edit path) and expect the acronym. **The speaker-card and people-details changes aren't affected**: they bind
`speaker()` directly.
