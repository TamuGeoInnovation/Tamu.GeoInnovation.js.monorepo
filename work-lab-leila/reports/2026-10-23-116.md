## 2. The fix, green

**`getUsers`** now walks every page with auth0 7's `Page`, still sorted by name and mapped as before:

```ts
let page = await this.client.users.list({ sort: 'name:1', per_page: USERS_PER_PAGE });
users.push(...page.data);
while (page.hasNextPage()) {
  if (pages >= USERS_MAX_PAGES) { Logger.warn(`Stopped listing users after ${pages} pages (${users.length} users).`, 'ManagementService'); break; }
  page = await page.getNextPage(); pages++; users.push(...page.data);
}
```

- **`per_page: 50` is passed explicitly.** auth0 7's `hasNextPage()` ends the walk on a short page only when `per_page` is given; without it,
  every list would ask for one more, empty page.
- **The runaway guard:** 100 pages, logged with the count. A **fourth new test** gives the stand-in 6,000 users: the walk stops at 100 requests
  and 5,000 users, and logs *Stopped listing users after 100 pages (5000 users).*
- **The API's own limit:** the Management API pages through only the **first 1,000 users** (20 pages of 50). Past that it refuses, and listing
  every user needs its export job. It is noted in the code; the guard is far above it.
- **The older test** that asserted *the first page … as auth0 3 did* is renamed: it now checks the first request is page 0, 50 to a page,
  sorted, and that with 2 users no second page is asked for.
