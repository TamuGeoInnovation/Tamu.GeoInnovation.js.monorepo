## What changed

All of this is in `scripts/tidy.sh`.

1. **Two kinds, kept apart.** `unregistered_kind` calls a `wt-*` folder git doesn't list `orphaned` when it has no
   `.git` at all, and `own-git` when it has one: a file or a directory, readable or not. Each kind gets its own heading.
   The `wt-k8s-*` kind lands under "with their own .git ... another repository's worktrees or clones. Never removed
   here."
2. **Totals.** Each heading starts with its count and its size added up, as in "17 folder(s) with no .git ... 130 MiB
   in all". `kib_human` gives GiB to one decimal from 1 GiB, then MiB, then KiB, so a near-empty folder doesn't read
   "0 MiB".
3. **`--remove-orphans`, and only behind that flag.** It removes the orphans and nothing else. `--yes` doesn't include
   it, and neither does the scheduled `--if-due` sweep. `orphan_removable` checks each folder again at the moment of
   removal. It refuses:
   - a folder with any `.git`, giving that reason;
   - a folder git's worktree list names;
   - a folder not named `wt-*`;
   - a folder not directly in the main checkout's parent.
4. **The closing hint.** After a report, the sweep says the orphans are kept by `--yes` too, and names the flag.
5. **`CLAUDE.md`:** one paragraph beside the other `tidy.sh` rules, giving the two kinds and the flag.

## What this changes

`scripts/tidy.sh` reclaims by reading git's worktree list. So a `wt-*` folder whose registration and `.git` are both
gone is invisible to `--yes`, and nothing else looks for it. The sweep did name the folders git doesn't list, but under
one heading with other repositories' worktrees. So a warning about three folders of residue read as one about seven, and
nobody added up the sizes.

- **Two kinds, each with its total size:**
  - *orphans*, with no `.git` at all: old worktrees nothing can check;
  - folders with their own `.git`: another repository's worktrees, or clones.
- **`--remove-orphans` removes the orphans and nothing else.** It is never the default, and `--yes` doesn't include it.
  At the moment of removal it checks each folder again, and refuses:
  - a folder with any `.git`, whether a file or a directory, readable or not;
  - a folder git lists;
  - a folder not named `wt-*`;
  - a folder that isn't directly beside the main checkout.
- **Sizes:** a near-empty folder reads in KiB, not as "0 MiB".
- **`CLAUDE.md`:** one paragraph beside the other `tidy.sh` rules.
