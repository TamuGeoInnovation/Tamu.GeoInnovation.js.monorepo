**The runtime risk.** The compile errors are mechanical. The `where` change is not: a `where: { guid: params.guid }` that receives
`undefined` used to match every row (0.3 drops undefined keys), and now throws. **No literal `null` or `undefined` is in a `where`
here**, so the compiler and grep cannot find these; only running each endpoint can. That is what makes this medium rather than small,
and it calls for the GIS Day local stack (`scripts/gisday-local.sh`) run across the admin pages after the change.
`invalidWhereValuesBehavior` can be set back to 0.3's behavior as a first step, which would make the upgrade small and leave this
for later.

## The recommended order

1. **ESLint 10 first.** It installs as it is, every plugin accepts it, and it is five one-line fixes in five files. It also does not
   touch the Nx 24 work beyond `@nx/eslint`, whose 23.3.0 already accepts ESLint 10.
2. **typeorm 1 second**, with `mssql` 12 and `ts-node` 10.9.2, and `invalidWhereValuesBehavior` set to 0.3's behavior at first.
   Then the 65 `relations`, 1 `select` and 3 globals are mechanical, and a local GIS Day run proves the APIs. Turning the strict
   `where` on is a later step of its own.
3. **TypeScript 7 last**, and not before Angular and typescript-eslint publish versions that accept it. Nothing here can move it
   sooner.
