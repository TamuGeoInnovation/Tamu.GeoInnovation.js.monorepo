## `deepMerge`

**Where:** `libs/common/utils/object/src/lib/deep-merge/deep-merge.ts`, exported from `src/index.ts`.

**What it does:**
- **It never changes its inputs:** it returns a new object, and nested plain objects and arrays are copied.
- **It merges only plain objects**, key by key, at any depth. Plain means made by `{}`, `JSON.parse` or `Object.create(null)`.
- **Anything else in the source replaces what the target had.** Arrays replace; `deepmerge`'s default would concatenate, and none of our
  inputs has one. Class references, class instances and `Date`s are kept as the same reference.
- **It skips `__proto__`, `constructor` and `prototype`** at any depth.

**The tests:** `deep-merge.spec.ts`, 8 of them.
- **The first three take their expected values from `deepmerge` 4.3.1**, which I ran on 6 November on the same inputs: a football layer
  source (plain data, an array, a nested renderer and a `popupComponent` class), merged with football's
  `SHOW` (`{ native: { visible: true, listMode: 'show' } }`), with `{ visible: false }` and with `{ popupComponent: OtherPopup }`:

  | Input | deepmerge 4.3.1 | deepMerge |
  | --- | --- | --- |
  | `SHOW` | `native` merged, `outFields` and `renderer` kept, `popupComponent` the same class | the same |
  | `{ visible: false }` | `visible: false` added at the top | the same |
  | `{ popupComponent: OtherPopup }` | replaced, by reference | the same |

  In all three, `deepmerge` returned new nested objects and arrays and left the input unchanged, and so does `deepMerge`.
- **The other five:**
  - a changed result can't reach an input;
  - arrays replace;
  - non-plain values replace;
  - `JSON.parse('{"__proto__":{"x":1}}')` leaves `({}).x` undefined and the result's prototype `Object.prototype`;
  - `__proto__`, `constructor` and `prototype` are ignored when nested.
- **Red first:** the spec, run before the helper existed, failed (`Failed to resolve import "./deep-merge"`). `common-utils-object` now
  passes 24 of 24.

**The three calls:** `layer-sources.service.ts:91` and `event.service.ts:138` and `:325`, the last two now at `:136` and `:323` since the
import moved. Each is `deepmerge(a, b)` to `deepMerge(a, b)`, with the import from `@tamu-gisc/common/utils/object`; `event.service.ts`
