## What it does

`node scripts/event-map-monitors.mjs` prints one row for each layer every event map draws on production:
- the map;
- the layer's id;
- its production URL;
- a suggested monitor name;
- the keyword the monitor should look for.

It has three options:
- **`--json`** prints the same rows for a machine.
- **`--unique`** prints one row per URL, with every map that reads it.
- **`--offline`** prints the rows without asking any service, so no keywords.

It creates and changes nothing in Kuma.

**Where the layers come from.** I read the definitions; nothing is re-typed.
- **The problem:** the definitions are TypeScript with Angular inside, so a script can't import them.
- **The spec:** a new spec, `event-map-monitors.spec.ts` in `ts-events-ngx`, loads every map at the address
  `https://aggiemap.tamu.edu/`. So `Connections` resolves the production URLs exactly as it does for a visitor.
- **The file:** the spec writes the result to `scripts/event-map-layers.generated.json`, which is committed.
- **Already used here:** `declared-layers.spec.ts` serves the smoke suite this way. A definition that changes a layer
  fails the spec until the file is rewritten with `nx test ts-events-ngx -u`, so the file can't drift from the maps.

**Which layers count.** A layer counts if the map draws it: its id is in `references`, which is what `EventService`
loads. A drawn group counts its children too. Each URL appears once per map.

**The keyword.** It's the layer's own `name` from `<url>?f=json`, read live. A MapServer whole-service URL uses its
`mapName`, and GeoJSON uses `FeatureCollection`. The monitor requests `?f=json` for every ArcGIS URL. An error body, even
one answering HTTP 200, never supplies a keyword, so a monitor on a broken layer goes red.

**Monitor names.** They come from the service and the layer, as in `AggieMap: MBskt_view 0 (Basketball Icons)`. A URL
that several maps read gets one name, so it needs one monitor, not one per map.

## Questions

**Q-a44-1: what happens to the four past-event maps whose services are stopped?**
- **(a)** File one issue (Bug, AggieMap project), to retire the four maps or mark them as ended. Meanwhile the generator
  lists them, and its "gave no name" section shows them.
- **(b)** Add a way to mark a map as ended in its definition. The generator would skip it, as it does a
  development-only map, and say why.
- **(c)** Leave them.

I recommend **(a)**, with (b) as that issue's fix if the maintainer agrees. A red-forever monitor is what the batch
warned against. The generator already shows these layers rather than giving them a keyword they don't have. I didn't
file it, because whether those maps should still be on production is the maintainer's call.

**Q-a44-2: should one monitor cover a URL that many maps read?** 261 rows come to 230 URLs, and `--unique` prints one
row per URL with its maps. I recommend one monitor per URL, named as the generator names it. Monitors per map would
duplicate 31 of them.
