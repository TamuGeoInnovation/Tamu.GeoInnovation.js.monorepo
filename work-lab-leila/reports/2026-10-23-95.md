## 1. Before

**geoservices**, no sign-in. No toast comes up naturally on a page load, so the script raises one through the container's own
`NotificationService.toast()` (dev mode's `ng.getComponent`), then closes it through the toast's own `close()`. It samples the toast's box
every 10 ms; here that gave 60 readings on entry and 80 on closing.
→ `docs/screenshots/animate-enter-leave/notifications-{enter,close}-{before,after}.png` and `notifications-frames-{before,after}.json`.

## 2. What the trigger did, and the change

- **Entering:** the box starts at `translateY(110%)` (its stylesheet's default), and the trigger's state `true`, set at once, moves it to
  `translateY(-110%)`, in view, over 250 ms. **A true enter, so `animate.enter`:** `animate.enter="entering"` with a keyframe from
  `translateY(110%)` to `translateY(-110%)`.
- **Closing:** `close()` sets the state `false` (`translateY(10%)`, back down), and **emits to the container 500 ms later**, which then
  removes the toast. The toast holds that state while still on the page, so this part stays a **CSS transition between two states**
  (`[class.closing]`) with the same 250 ms. `animate.leave` would have moved the slide to the removal itself and changed when the container
  removes the toast; I kept the existing timing instead.
- **Reuse rule:** both are one mixin, `notification-toast($entering-class, $closing-class)`, in `libs/sass/_motion.scss`, with the trigger's
  easing (`cubic-bezier(.25, 0, .25, 1)`, the shared `$motion-easing`).
- **Removed:** the trigger; `provideNoopAnimations()` from the toast's spec. The toast was the only trigger left in **ts-events, UES
  operations, mailroom and GIS Day competitions** (the remaining ones, the tile navigation, hamburger, forms and header, are only in geoservices
  and GIS Day's own header), so **their bootstrap no longer provides animations**. geoservices and GIS Day keep theirs for batch 109.
