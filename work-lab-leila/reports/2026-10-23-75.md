## 1. Node in the tool cache

- **Where `UseNode@1` looks:** `azure-pipelines-tool-lib` checks `$(Agent.ToolsDirectory)/node/<version>/<arch>` **and** a marker
  `<arch>.complete` beside it. The image now sets **`AGENT_TOOLSDIRECTORY=/azp/_work/_tool`** (the agent's own default, made explicit) and
  installs Node **24.22.1** at `/azp/_work/_tool/node/24.22.1/x64`, with `x64.complete`.
- **The same checksummed download as before** (nodejs.org's `SHASUMS256.txt`), **installed once**: `node`, `npm` and `npx` on the `PATH`
  (`/usr/local/bin`) are links into it. Before, it lived only in `/usr/local`.
- **Who can write what.** The Node tree is **root's**: as `agent`, `touch …/x64/bin/probe` gives *Permission denied*, so a job cannot alter
  the Node later jobs use. The tool cache folder itself is the agent's, so a job can still install other tools, and `_work` is writable.
- **Proven in the built image:** `azure-pipelines-tool-lib`'s own `findLocalTool('node', '24.22.1', 'x64')`, run as `agent`, returns
  `/azp/_work/_tool/node/24.22.1/x64`, and `findLocalToolVersions('node')` returns `["24.22.1"]`. Its log line is
  **`Found tool in cache: node 24.22.1 x64`**.
  - **That is how the job log will show the hit**: under *Install Node.js 24.22.1*, that line in place of a `Downloading:` line from
    nodejs.org, and the step should take about a second instead of 9.
