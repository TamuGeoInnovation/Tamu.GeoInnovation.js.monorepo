  library.

**The known list holds the 8 that were failing long before** this check, with the counts above.

- **If you'd rather** nothing fails before g208's pull request merges, see Q-g210-1.

**Where it runs:** one `lint.yml` line, beside the spec check, so `check-in-volume.sh` runs it. The local check's log
shows `lint.yml: node scripts/check-strict-libs.mjs` and "No strict library changed since origin/development; nothing
to type-check."

**Its tests: `scripts/check-strict-libs.test.sh`, 12 cases.**
- **Why a `.test.sh`:** the batch said a `*.test.mjs`, but every suite in `scripts/` is a `.test.sh`. `run-script-tests.sh`,
  which `pre-pr-check.sh` and `scripts-tests.yml` run, runs every `scripts/*.test.sh`, and none of them runs a
  `scripts/*.test.mjs`. So it's a `.test.sh` like `check-spec-types.test.sh`, and needs no wiring. It ran in
  `pre-pr-check`'s "scripts test suites" step: `scripts/check-strict-libs.test.sh: exit 0`.
- **The cases:**
  - reading a tsconfig with comments and trailing commas, and a `//` inside a string;
  - what's strict: strict from the `tsconfig.json` it extends; its own `strictNullChecks` either way; a base outside
    the project; an `extends` without `.json`; and `strictNullChecks` in a base beating a nearer `strict: false`;
  - the list: judged as the spec check's, each naming its own list.
