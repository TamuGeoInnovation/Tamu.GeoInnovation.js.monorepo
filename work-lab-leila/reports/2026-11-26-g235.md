## The cause

The dashboards' charts are all `tamu-gisc-line-chart` (`libs/ui-kits/ngx/charts`), which redraws in an `effect`
whenever what it shows changes, disposing of the last drawing first. Its drawer awaits the amCharts import before
`am5.Root.new(host)`. When the data arrived twice in quick succession, both draws waited on the same import and resumed
one after the other, so the second made its Root before the first draw's promise had handed back what disposes of it.
For a moment the element had two Roots, and amCharts warned. The chart still drew because the first was disposed a
moment later.

## The fix (`8a890d51d`)

Each draw waits for the one before it to settle, so the last drawing is disposed of before the next one begins. A draw
replaced before its turn comes draws nothing; a failed draw does not stop the next. The component's inputs and the
`LINE_CHART_DRAWER` interface are unchanged, and since every dashboard chart is this component, all of them are
covered.
