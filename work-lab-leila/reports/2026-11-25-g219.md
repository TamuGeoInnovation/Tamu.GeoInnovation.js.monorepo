## What changed

**`libs/ui-kits/ngx/forms/tsconfig.lib.json`** now has `strict`, `noPropertyAccessFromIndexSignature` and
`noImplicitReturns` (modal's settings), in place of `strictNullChecks` alone. Forms' own **34** errors are fixed with
types only, behind the existing interface:

- **Value accessors** (checkbox, checkbox group, date-time picker, file, radio group, select, the abstract form):
  `registerOnChange`, `registerOnTouched`, `writeValue` and the change callbacks are typed with the value each carries.
  - **Note:** the default callbacks that returned their argument are now typed as returning `void`.
- **Radio group:** its value is `Value | Option | undefined`, which is what `valuePath` picks, or the option itself without
  one (`getPropertyValue<Value>`). The slide toggle's `evaluateSetValue` override now returns the base's value instead of
  `void`. The templates ignore the return, so nothing reads it.
- **File:** `handleFileChange` takes `{ target: { files: ArrayLike<File> | null; value: string } }`, the shape the template's
  change event and the specs' fakes both have. `files[0]` replaces the tuple destructure.
- **Index signatures:** `changes['customDataMap']` in range and `changes['options']` in select-list.
- **Turnstile:** `window.turnstile` is declared (`declare global`), with the callback's `token: string`.
- **Two specs** (`abstract-value-accessor-form`) passed `writeValue(true)`'s `undefined` as the callback. They now write,
  then register a no-op. That's the test they meant; the assertions are unchanged.

**Behaviour:** none changes, so there are no red-first specs or images.
