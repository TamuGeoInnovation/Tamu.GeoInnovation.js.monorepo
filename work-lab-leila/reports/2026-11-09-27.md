## Part 2: GIS Day's MapLibre maps draw VTBase3

**What I found first.** Given the style URL as it is, maplibre-gl 6.16 draws nothing:
- it refuses the sprite: `Invalid sprite URL "../sprites/sprite", must be absolute`;
- it resolves the source's `url: "../../"` against the **page**, and fetched the page's own HTML as TileJSON.

The style's paths are written relative to itself, as ArcGIS clients read them, and MapLibre resolves none of them. So
"give MapLibre the style URL" is right, but not enough on its own.

**The change** (`libs/maps/mapbox/src/lib/services/mapbox-map.service.ts`):
- **`DEFAULT_MAP_STYLE`** is the style URL, `Hosted/VTBase3/VectorTileServer/resources/styles/root.json`.
- **`absoluteCampusStyle`**, passed as MapLibre's own `transformStyle` hook whenever a caller names no style:
  - makes `sprite` and `glyphs` absolute against the style's address, keeping `{fontstack}` and `{range}` (a plain
    `new URL` would percent-encode the braces);
  - replaces the vector source's `url` with the service's own tiles, keeping its `minzoom`, `maxzoom` and `bounds`;
  - credits "Texas A&M University", as the raster source did. The published source credits no one, and my first
    "after" had lost the credit.
- **A caller that names its own style is unaffected.** None does today.
- **`TAMU_CAMPUS_VECTOR_BASEMAP_URL`** is new in `campus-basemap.ts`, beside the raster constant. The stale comment
  ("not published on production", "Texas State Plane, which MapLibre cannot draw") is replaced, and the raster constant
  is marked abandoned.

**Red first:** the new `mapbox-map.service.spec.ts`, the library's first spec, failed on the unchanged service, **4 of 4**:
- the default style contained the raster service's address;
- the fix-up didn't exist.

With the change, **5 of 5**, the fifth being the credit.

**Proved in a browser, twice:**
- **A bare page, maplibre-gl 6.16:**
  - the published style as-is: no tile requested, two errors;
  - with the transform: `idle`, 115 layers, 0 errors, and every request 200 (style, 9 tiles, sprite JSON and PNG,
    glyphs).
- **The real GIS Day pages,** on a GIS Day dev server of its own, `gisday-b27` on port 4300 (`gisday-dev` untouched):
  - signage, sidewalk, stormwater and light pole **each requested VTBase3 alone, every answer 200, the raster service
    not at all**;
  - production's signage page requested 12 raster tiles;
  - the credit reads "Texas A&M University | MapLibre" on both.

**Captured:** `docs/screenshots/gisday-maplibre-vector-tiles/before-production-signage.png` (production) and
`after-local-signage.png` (the branch). The headers differ because the dev server serves the TxGIS Day site. The map is
the same component.

**What looks different, from the style, not the code:**
- **Garages are blue**, as on AggieMap's vector basemap (#2063 is that styling).
- **Buildings under construction** draw as the style's own pink-and-white pattern. AggieMap hides those two style layers
  and draws its hatch from the abandoned service's layer 2. GIS Day has no overlay, so it keeps the published pattern.
  If you want AggieMap's look there, that's a decision and a follow-up; I'd say the pattern is fine for these maps.
- **Labels** differ a little: numbered lots, and fewer place names.

**The full check caught something the library's own tests didn't, and the second commit answers it.**
- `basemaps.definition.spec.ts` has a guard: the vector basemap's service may not be named outside its definition, so
  every ArcGIS map takes it from `aggiemapBasemap()` and environment gating stays in one place.
- The new constant named it in `campus-basemap.ts`, so the guard failed, correctly.
- **I didn't just exempt the file.** The guard now allows exactly two places: `campus-basemap.ts`, which declares the
  address, and `libs/maps/mapbox`, the MapLibre maps, which can't take an ArcGIS basemap definition.
- **Anywhere else, the constant counts as naming the service**, as its address does, so the guard is stricter than
  before. Proved: naming the constant in `connections.ts` fails it.
- That's commit `2bb8ca695`. It touches the same spec as part 1, in a different test. **The two branches merge with no
  conflict, and the library passes 26 of 26 with both** (tried on a throwaway branch, since deleted).

**Not changed:** `basemaps.definition.ts` still writes VTBase3's URL out twice, rather than using the new constant. That's
#1700's question ("named in three files"), and it's in part 1's file, so I kept the two branches apart.

**Seen while capturing, not touched:** on `txgisday.org`, the signage page's request for submissions from
`gisday.tamu.edu/rest/Signage/Get/Submissions/?geoJSON=true` is blocked by CORS (`gisday.tamu.edu`'s own copy of the
page loads them). That's production today, and it may mean the TxGIS Day site shows no submissions on any competition
map. Worth an issue for GIS Day.
