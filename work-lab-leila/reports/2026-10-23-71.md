## 2. The change

- **`maplibre-gl` 6.15.0** (BSD-3-Clause) in place of `mapbox-gl` 1.13.3 and `@types/mapbox-gl` (MapLibre ships its own types). The library
  keeps its names (`MapboxMapComponent`, `MapboxMapService`, `maps-mapbox`), so its callers change only by losing an attribute.
- **The basemap.**
  - It was Mapbox's **`light-v10`**, a hosted style that needs Mapbox's terms and a token, and that MapLibre cannot load (`mapbox://`).
  - It is now **OpenFreeMap's `positron`** (`https://tiles.openfreemap.org/styles/positron`, `DEFAULT_MAP_STYLE` in the service): **a light
    grey vector style from OpenStreetMap data that needs no account, key or token**, and the nearest open match to what the pages showed.
  - Others considered: MapTiler and Esri's vector basemaps need keys; raster OpenStreetMap tiles carry a usage policy against this kind of
    use.
- **The token.** The component's `token` input is gone, and so is the **Mapbox public token in the four templates**. Nothing reads a token
  now. **It is still in git history, and it is live**: if it is not used anywhere else, the maintainer may want to delete it in the Mapbox
  account it belongs to.
- **Signage's extra tileset**, `mapbox://gsepulveda96.covid`. A 2021 `TODO` added it as a source and **no layer ever drew it**, and MapLibre
  cannot load `mapbox://`. It is removed, with a comment where it was.
- **`test/setupJestMock.ts` deleted** (it mocked `mapbox-gl` and nothing loaded it).

**Two problems found on the way, each fixed:**

1. **The stylesheet broke GIS Day's component style budget.** The component had `@import url(...)` of mapbox-gl 1.10's CSS from
   `api.mapbox.com`, fetched at run time and never measured. Importing maplibre-gl's own 72 kB CSS into the component failed the production
   build (*"exceeded maximum budget. Budget 10.00 kB"*). **The stylesheet is now global, in `apps/gisday-angular/src/styles.scss`**, which
   CLAUDE.md allows for globally-applied widget styles. That is also where it has to be: the map builds its controls outside Angular's style
   scoping, so component-scoped rules would not reach them. A comment in the component points there.
2. **The map never finished loading.** The style, tile manifest and sprites arrived, but no tile was requested and `isStyleLoaded()` stayed
   false, with no error. **maplibre-gl 6 looks for its web worker, `maplibre-gl-worker.mjs`, beside its own module file**, which is not where
   it ends up once Angular bundles it. The fix:
   - GIS Day copies the worker into its build as an asset (`project.json`: `node_modules/maplibre-gl/dist/maplibre-gl-worker.mjs` → `maplibre/`).
   - The library fetches it once and gives maplibre-gl **a blob URL typed as JavaScript** (`setWorkerUrl`).
   - **Why a blob and not the file's own address:** `nginx-base` maps only `.js` to JavaScript. I checked: it serves the worker as
     **`application/octet-stream`**, which a module worker refuses, and a server-level `types {}` in our `nginx.conf` would replace every other
     MIME type. The blob works on any server.

**The lock**, key by key against `development`: **`mapbox-gl` and its own dependencies out, `maplibre-gl` and its own in, nothing else.** That
is 16 removed (`mapbox-gl`, `@types/mapbox-gl`, `supercluster`, `vt-pbf`, `geojson-vt`, `grid-index`, `csscolorparser`, the old `@mapbox/*`), 16
added (`maplibre-gl`, `@maplibre/*`, nested `pbf`/`kdbush`/`point-geometry`) and 6 shared helpers at new versions (`earcut`, `potpack`,
`quickselect`, `@mapbox/tiny-sdf`, `@mapbox/unitbezier`, `@mapbox/jsonlint-lines-primitives`). Two lose their production flag
(`bidi-js` and `require-from-string`, now dev-only).
