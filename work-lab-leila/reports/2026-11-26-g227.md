## 2. SSH from Git Bash: why it fails

- **It's not the WSL trap from #3273.** Git Bash runs its own `/usr/bin/ssh` (OpenSSH_10.5p1) under its own
  `/usr/bin/bash`.
- **A key exists:** `~/.ssh/id_ed25519`, ED25519, fingerprint `SHA256:e/8qOB9RCqmgn0O/Zl8JR2ueLAz34evY4sVnfc1IVmk`.
- **GitHub refuses it:** `ssh -T git@github.com` answers `git@github.com: Permission denied (publickey).` So the key
  isn't registered to any GitHub account, or not to one that may use it. No agent is running (`ssh-add -l`: "Could not
  open a connection to your authentication agent"), but the key file is read directly, so that isn't the cause.
- **Why nothing noticed:** the global git config has `url.https://github.com/.insteadof git@github.com:`, which rewrites
  every SSH remote to HTTPS. So every fetch and push here goes over HTTPS with `gh`'s credential, and works.
- **I can't check the account's keys:** `gh ssh-key list` needs the `admin:public_key` scope, which this token doesn't
  have.

**The fix is the maintainer's**, because it adds a key to his GitHub account:

```
gh auth refresh -h github.com -s admin:public_key
gh ssh-key add ~/.ssh/id_ed25519.pub --title "work-lab-leila"
```

Run from Git Bash on this machine, then check with `ssh -T git@github.com`. If SSH isn't meant to be used here at all,
see Q-g226-1: measuring the push route this machine actually uses would make this green, not red.

**Also worth knowing:** the private key file is `-rw-r--r--`, readable by every local account. OpenSSH on Windows
doesn't refuse it, but it should be owner-only.
