Pressing Escape on an admin details page now goes back to the list it came from, keeping the season and the search.
If the form has unsaved changes, it first asks "Leave without saving?" in the page. An Escape that a dropdown, search
list, date picker or modal used is left to that.

## The design

- **One shared piece:** a new base class, `BaseAdminDetailsPageComponent`, in
  `libs/gisday/platform/ngx/core/.../admin/pages/base-admin-details-page/`.
  - A details page extends it, as the lists extend `BaseAdminListComponent`.
  - A page with a form names that form in `detailsForm()`. For a page that wraps a form component, that is a
    `viewChild` and a 3-line override.
- **The 23 pages that use it:**
  - the add and edit pages of Broadcasts, Classes, Events, Venues, Affiliations, Organizations, Speakers, Sponsors,
    Tags and Universities;
  - the Season edit page;
  - the research competition review;
  - the speakers' "Edits to review" page.
- **Back to the right list, with its season:** the page remembers what it was opened from.
  - Opened from its own list: Escape goes back in browser history (`Location.back()`), so the list keeps its
    `?season=`.
  - Opened from anywhere else: Escape goes to the list's path.
- **The search is kept too:** a list's search (and Research Competitions' two filters) is stored in that list's
  browser history entry and restored when you come back to it.
  - Opening a list from the menu still starts empty.
  - Nothing is added to the address, because the menu links carry query parameters from section to section.
- **Unsaved changes:** Escape opens the existing `AlertModalComponent`, with **"Leave without saving?"**.
  - "Leave without saving" goes back.
  - "Keep editing", a second Escape or a click outside stays on the page.
- **Two fixes that unsaved-changes handling needed:**
  - **Edit pages looked changed as soon as they opened.** Every form in the shared form kit treated its loaded value
    as a user's change. Each GIS Day form is now marked unchanged after it loads (question 1).
  - **Changes made by a click didn't count.** An event's day, time or speakers, a season's days, and an
    organization's links now do.
- **Escapes that something else uses are left alone:**
  - The page decides on key release, after every other handler has seen the key press.
  - It ignores an Escape something else claimed (`preventDefault`), and any Escape while a modal is open.
  - Deciding on release also stops the modal's own Escape listener from closing the question as soon as it opens.
- **Shared pieces changed so they claim the Escape they use:**
  - **The keyboard-navigation directive behind searchable selects.** It also had an existing bug: closing a list
    recursed until the stack overflowed. That is fixed (question 3).
  - **The speaker search list (`SelectListComponent`):** Escape now closes it.
  - **`TooltipComponent`, which the date picker opens in:** Escape now closes it.
  - **Angular Material's time list** already claimed its Escape.

**Where I looked for something to reuse:**
- `libs/ui-kits/ngx/layout/modal`: `ModalService` and `AlertModalComponent`, both used.
- `libs/ui-kits/ngx/forms`, `.../interactions/keyboard` and the layout tooltip: extended.
- `libs/gisday/platform/ngx/common` (its `utils/`, forms and modals), `libs/gisday/common`, `libs/common/**` and
  `styles.scss`: nothing fitted.
- **The four admin base classes:** only the list's fitted, and the new class follows its pattern.
- **Unsaved-changes handling:** none existed, beyond the season form marking itself unchanged after it loads.
