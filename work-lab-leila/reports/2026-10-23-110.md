## 2. The mechanism: npm 11.19's own allow-list

npm 11.19.1 has **`allowScripts` in `package.json`**, maintained with `npm install-scripts approve|deny|ls|prune`, plus a
**`strict-allow-scripts`** setting. Its documentation disagrees with itself on the default, so each case was measured on our real lock, using
`better-sqlite3`'s binary as the probe:

| Setup | A package whose script is not listed | Exit |
| --- | --- | --- |
| no `allowScripts` (today) | **runs**, then a warning lists all 10 | 0 |
| `allowScripts` without `better-sqlite3` | **still runs**, with a one-line warning | 0 |
| the same plus **`strict-allow-scripts=true`** | **install fails**: `ESTRICTALLOWSCRIPTS … better-sqlite3@12.11.1 … not covered by allowScripts` | **1** |
| every package listed, strict | runs as listed | 0 |
| an entry `false` (denied), strict | **skipped silently** (no banner with `--foreground-scripts`) | 0 |

- **So without `strict-allow-scripts`, the list is advisory**: a new script runs and only warns. With it, CI notices.
- **`ignore-scripts=true` plus `npm rebuild <pkg>`** would also skip the root's own `postinstall`, and would need a hand-kept list of rebuilds.
  Not chosen.
- **Entries are name-only** (`--no-allow-scripts-pin`). A pinned `esbuild@0.28.2` would make every Dependabot bump of esbuild, swc or Nx fail
  until someone re-approves it. A new package, or a known package's script under a name not listed, still fails. See question 1.

## Questions for the director (security)

1. **Name-only or pinned entries?** Name-only (as pushed) lets a reviewed package's upgrades through without a re-review; pinned would put
   every Dependabot bump of esbuild, swc, Nx and the rest in front of a person. **Recommendation: name-only**, with the daily signature and
   advisory scans as the check on new versions.
2. **Deny more?** Seven of the nine allowed scripts are fallbacks that Linux x64 does not need: each package's platform binary is already
   there. They stay allowed for Windows and macOS installs and for odd architectures. **Recommendation: keep them allowed;** deny only what does
   nothing for us, as pushed.
3. **`better-sqlite3`** is allowed only for `ues-operations-nest`, which nothing builds or tests. **Recommendation: keep it** while that app
   exists; deny it if the app goes.
