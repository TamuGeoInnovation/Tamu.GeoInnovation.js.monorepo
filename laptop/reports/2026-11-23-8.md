## Step 1: what was built

- **API route:** `GET /user-submissions/:guid/files/:file/preview`. It sends a submission's PDF `inline` as `application/pdf`, under its own name.
  - **Who may use it:** those who hold `read:competitions` only. Unlike the download, the submission's own student may not.
  - **Which files:** a file is found only among that submission's own.
  - **PowerPoint:** answers 415, "… has no preview: download it instead."
  - **Reused:** `submissionFor`, `fileOf` and `fileDownload`. `fileDownload` gained an optional disposition, and `contentDisposition` generalises `attachment()`, keeping it for its callers.
- **Admin review page:** a `previewable` input on the shared `SubmissionFilesComponent`, which only the review page sets.
  - **Preview** beside each PDF shows it under the list, in the browser's own viewer, with Previous, Next (wrapping round) and Close.
  - **How the PDF reaches the frame:** it is fetched with the sign-in and drawn from an object URL, which is released when it is no longer shown.
- **Images:** uploads accept only `.pdf`, `.ppt` and `.pptx`, so the issue's "images preview directly" cannot arise today. Nothing was added for them.

## Findings

- **The browser's PDF toolbar shows the object URL's random id**, not the file's name. The name is shown above the viewer, so it is cosmetic. It could be fixed by giving the PDF a title, for example when it is converted, or by serving the frame from the API with a short-lived signed address.
- **My own mistake this batch:** a safety check stopped one measurement command because its shell script ran `rm` on a file inside a throwaway container's `/tmp`. I did not work around it. I rewrote the measurement so nothing was deleted: each run converted into a new folder.
- **Uploaded files on the local stack:** `APP_DATA` is empty in `gisday-api.local.env`, so a local upload lands inside the mounted checkout. For these images I gave the scratch API its own `APP_DATA` inside the container.
