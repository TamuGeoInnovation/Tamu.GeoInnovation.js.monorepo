## The fixes, and the interface

Each fix says what is true, with no `!`. **The public interface is kept for every caller:** none of them is strict, so `| undefined` changes nothing for them.
- the optional inputs are typed as passed;
- the input query is `viewChild.required` (it is always rendered);
- `SearchResult.results` is always an array;
- `search()` says it can answer `undefined`, as its guards already did;
- a breadcrumb's `source` can be `undefined`;
- `makeWhere` takes the `null` entries it already handles.

Behaviour changed only on paths that threw:

| Path | Before | After |
| --- | --- | --- |
| `search()` with no `values` | threw a TypeError | logs and refuses, checked after the existing source checks so their messages stay as they were (an existing spec caught my first ordering) |
| `features()`, an item with no features | threw | skipped |
| a `where` present but `undefined` | threw a TypeError | the existing "No where property provided" |
| the alt lookup: a missing source | threw | still throws, now naming it |
| the alt lookup: no result item | threw a TypeError | gives no selection; **spec red first** (`ff4ad87f1`: "promise rejected TypeError… reading 'features'"), green after |

**A suspected bug that was not one:** I thought `focused` read the input query in `ngOnInit` before it resolved. A spec on the unfixed code passed, so I dropped it and said so.
