## Still open (overnight rule 4)

No commit on `development` names #1756, and the tooltip's placement had not changed: `calculateOffset` in
`libs/ui-kits/ngx/layout/src/lib/components/tooltip/` tries four spots around the trigger, and when none fits it keeps the
last one tried, left of the trigger. At 390 px a 20rem popup fits none of them near either edge, so it went off screen.

## The fix

Only the tooltip changed, behind its interface: no caller, and not the picker itself. When no spot around the trigger fits
whole, the popup now goes **below the trigger, or above it if there is no room below, slid sideways as little as it takes**
to stay inside the window (10 px from its edge). If even that does not fit, it goes below, kept inside as far as it can be.
**Wherever a spot did fit, the placement is exactly as before**, so desktops are unchanged. That is the conservative choice:
the alternative, sliding the existing first choice (above, centred) onto the screen, would have moved popups that open
fine today.

## What this changes

<!-- What a reader needs to know. Why, not only what. -->

At phone width the shared date and time picker's popup opened off the left edge of the screen, where only a sliver showed and it could not be used. The picker asks its tooltip for a 20rem popup, and the tooltip's placement tries four spots around the trigger. When none fits, as near either edge of a 390 px screen, it kept the last one it tried, left of the trigger.

Now, when no spot fits whole, the tooltip places the popup below the trigger, or above it if there is no room below, slid sideways as little as it takes to stay inside the window. Wherever a spot did fit, the placement is unchanged, so desktop users see no difference.

The change is in the tooltip only, behind its interface: no caller changes. It reaches every GIS Day form with the picker (an event's start and end times, a season's days, the research competition's scoring dates, the competitions designer) and AggieMap's trip-planner time picker.
