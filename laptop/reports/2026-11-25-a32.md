## 2. #3483, the QR code's Download uses `downloadFile`

**Step 0, still true:** `qr-code.component.ts` built its own anchor and clicked it, never adding it to the page or releasing it.

**The batch had one fact wrong:** `qrPng` answers a **data URL** (`canvas.toDataURL`), not a Blob.
- `downloadFile` wraps its contents in a new Blob, so given the URL it would have saved **the URL's text as the PNG**: a file that does not open,
  exactly the failure you warned about.
- The PNG's bytes are read out of the data URL first (`fetch(dataUrl).blob()`), and saved as `image/png`.

**Proved in a browser, as asked**, on the local GIS Day stack, signed in as the txgisday-dev test admin:
- **Where:** a session's details page (the only page with a QR code that downloads), **Show check-in QR code**, then **Download PNG**.
