## Seen and not filed, with why
- **Every uploaded image reopens as a 404, locally.** The API saved each file under its own `APP_DATA` (`/tmp/gisday-app-data/images/...`), and the local dev server does not serve that folder. On production the volume is served at `/assets/uploads`. This is a gap in the local stack; `docs/gisday-local.md` could say so.
- **The Accounts dashboard said "The accounts could not be read. Try again in a moment."** once, after about twenty dashboard loads. The cause was Auth0's Management API on the dev tenant answering 429 "Global limit has been reached", which the API passes on as a 500. My test load caused it, and the page already says so plainly.
- **A 404 for `GET /api/rsvps/user/event/<guid>`** on a session the account has not registered for. By design: the page catches it as "not registered". It still shows in the console.
- **`/sessions`** lists its days collapsed, so the walk opened a session by its id.
