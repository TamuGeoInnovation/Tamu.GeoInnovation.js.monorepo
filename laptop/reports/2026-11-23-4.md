**Why `floating-table` does not help here:** in `admin.component.scss`, `table.floating-table` sets `width: 100%` and lets
cells wrap **between words**. Every cell in this table is one word ("Submissions", "Verified", "Discarded", "Total", or a
number), except "Needs a look" (which does wrap) and the category names. So the table cannot get narrower than its
widest words plus cell padding, **377 px**. The page's column is about 330 px wide on a 390 px phone. The other admin
tables fit with the same class because their cells hold sentences, which do wrap.

## What I would do instead (not done; for the branch's author)

1. **Recommended: scroll the table in its own box**, as the list below it already does (the list is an `ngx-datatable` with
   its own scrolling). The repository already has the box, `DashboardScrollComponent` (`tamu-gisc-dashboard-scroll`), which
   #2894 used to make the people tables scroll, with no page-level sideways scroll. It lives in
   `libs/gisday/platform/ngx/core/.../admin/pages/dashboards/shared/` and is not exported, so the competitions library
   cannot use it as it stands. Per CLAUDE.md's reuse rule, **move it to a shared library** (for example
   `libs/ui-kits/ngx/layout`, exported from its index) and use it in both places, rather than writing a second
   `overflow-x: auto` wrapper.
2. Or let it fit: shorter headings on a phone ("Subm.", "Disc."), or smaller cell padding below 400 px. That is cheaper, but
   purpose-built CSS, which the repository discourages, and it would break again with one more column.
