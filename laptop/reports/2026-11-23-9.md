## A. #3150: tapping a bus route on a phone does nothing

- **The fault, first** (local dev server on `development`, Playwright's iPhone 13): tapping NW0104 left `/map/m/bus` as it was,
  with no timetable. On the desktop, the control, the same tap opened it, because the desktop list uses in-place selection.
- **Cause:** the outlet trap. The phone's list is in `outlet-2` under `bus`, and `toggleRoute()` navigated `[ShortName]`
  relative to its own route inside the outlet.
- **Red first:** `bus-route.component.spec.ts` failed on the phone case (`relativeTo` was the `outlet-2` route); the desktop case passed.
- **Fix:** navigate from `primaryOutletRoute(this.rt)`. **The helper moved, as the batch asked**, from `base-directions.component.ts` to
  `@tamu-gisc/common/utils/routing`, with three tests of its own. `base-directions` imports it from there and still exports it.
  - The routing library names the primary outlet (`'primary'`) instead of importing `PRIMARY_OUTLET`. Importing the value made
    the library's own specs fail to load: Angular asks for its JIT compiler, which they run without.
- **After:** the phone tap went from `/map/m/bus` to `/map/m/bus/NW0104` with the timetable, and the route drawn on the map;
  the desktop was unchanged. The release entry has a dev-test row that says to use a phone.

## B. #3149: routing unreachable from the phone menu, and #3319 filed

- **The menu:** Directions, a link to `/map/m/trip`, right after Bus Routes. Red first (2 tests).
- **The omnisearch.** Before changing line 135 to "the relative form of line 187", I asked Angular's real router, in a test harness with the map's
  route shape, where each form leads from the stop search (`/map/m/search/:id`, whose page is an empty-path child):
  - `['./trip']` and `['trip']` lead to `/map/m/search/abc/trip`, which is no page.
  - `['../trip']` leads to `/map/m/search/trip`.
  - `['../../trip']` leads to `/map/m/trip`.

  **So line 187, which the issue and the batch both took as the model, is broken.** In the browser, its back arrow went
  from `/map/m/search/0` to `/map/m`, the main map, losing the trip. That is filed as
  **[#3319](https://github.com/TamuGeoInnovation/Tamu.GeoInnovation.js.monorepo/issues/3319)** (Bug, `bug`, no
  priority, no project). It is fixed on the same branch, because one named link fixes both: `TRIP_FROM_STOP_SEARCH =
  ['../../trip']`, used by line 135 (choosing a stop) and line 187 (the back arrow). Both run only under `search/:id`. The PR
  closes both issues. **Suggested priority for #3319: Medium.**
- **After** (the branch, iPhone 13):
  - the menu reads "... Bus Routes | Directions | All Maps ...";
  - Directions opens `/map/m/trip`;
  - back from a stop's search goes to `/map/m/trip`;
  - no console errors.
- **`report-bad-route.component.ts`'s `map/d/trip` is left as it is**; see Question 1. `bus-stop.component.ts`'s `map/d/bus` is untouched, as
  the batch said.
