## Step 0: still true, with one caller the scan missed

On `development` at `77a7b8051`:
- `trackFocus` had **no** caller outside its spec;
- the autocomplete still used `KeyboardNavigationDirective`;
- `arrowKeyControl` had one importer, `search.component.ts`. **But it had two users.** `SearchMobileComponent` (the phone's map search) *extends*
  `SearchComponent`, and its template called `keyControl`. An import search does not see that; the compiler did, when the first branch build failed
  on `Property 'keyControl' does not exist on type 'SearchMobileComponent'`.

So the phone was in scope too, and is changed the same way.

## What changed

- **Both searches' lists take the directive.**
- **Each box names its list by `aria-controls`**, with an id per search (`search-results-0`, `-1`…), because the trip planner has two searches on one
  page. It replaces `aria-owns="search-results-container"`, an id nothing had. That is the one difference a visitor can meet, through a screen
  reader, and it is the release entry's subject.
- **The directive gains one input, `keyboardNavigationWrap`** (default `true`, so the autocomplete is unchanged). The searches set it `false`:
  - the last option stays the last;
  - up from the first focuses the element naming the list in `aria-controls`;
  - up from that box does nothing.

  That is CLAUDE.md's "extend what exists" (add the option it lacks) rather than a second copy.
- **`arrowKeyControl` and `trackFocus` are deleted**, so `common-utils-ui.ts` and its spec go. The library keeps `download` and `image`.
