## Questions for the home session

**1. #541: how should in-person and online attendance be counted?**
- **A. Record how each check-in was made** (a column on the check-in: in the room's zone, or by the session's QR code), and
  split the Check-ins dashboard by it. Nobody types a number, and it covers every hybrid session. One migration.
- **B. Two typed headcounts in place of one** (in-person and online, at the start and the end): the issue as written. One
  migration, and the old combined numbers stay as they are.
- **C. Close it.** Check-ins (#3006, #2893) now count who came, and #2560 lets online attendees check in.

**Recommendation: A**, then close #541 when it ships. It answers the issue's question (do we need bigger rooms?) from data
the site already collects. B asks an organizer to count Zoom by hand, which is how the 2022 numbers were made.

**2. #545: the VGI export needs a queue that production does not have. Which way?**
- **A. Add a Redis to the cluster** (kubernetes-config, the API's `REDIS_HOST`), then add the button to Admin > VGI
  Competition > Submissions. Keeps #650 as built, and is infrastructure work for the work machine.
- **B. Drop the queue:** build the zip in the request and stream it, as #3185 already does for a session's slides and the
  chosen competition submissions, then add the button. No new infrastructure, and one less moving part. Bull and its
  packages could go too.
- **C. Leave it** until the partners ask for the data again.

**Recommendation: B.** A season's VGI submissions number in the hundreds, and #3185 shows a streamed zip of that size is fine
here. A Redis kept only for one export a year is more to run than the feature is worth.
